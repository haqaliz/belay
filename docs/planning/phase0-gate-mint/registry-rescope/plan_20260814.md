## Design (decided)

- **`observed.json`** (new committed artifact, `eval/instances/observed.json`): the
  previously-minted id set, derived deterministically by a new script
  `eval/scripts/derive_observed_ids.py` from: the real (non-control) instance ids in the
  committed `stage2.json` / `stage4.json` / `stage4a.json` + `EXCLUDED_INSTANCE_IDS` from
  `build_stage4_registry.py` + `pytest-dev__pytest-7432` (smoke) + the s3-partial observed
  ids (from the committed s3 ledger; if the ledger's real-observed set cannot be derived
  mechanically, the script records the ids it CAN derive and the run aspect's evidence
  note carries the rest — the set must be evidenced, never guessed).
- **Stage 1** → `stage1.json` (2 records: CTL-1, CTL-4) — regenerated from
  `CONTROL_RECORDS` + `POSITIVE_CONTROL_RECORD`.
- **Stage 2** → `stage4.json` (9: CTL-2, CTL-3, then 7 fresh real) — the `_select_fresh_real`
  shape generalized to `limit=7` with the observed-exclusion applied.
- **Stage 3** → `stage3.json` (83: 80 fresh real + 3 controls) — `draw_mint_set.py
  --target 80` with a NEW committed seed, exclusion = observed.json; the draw asserts no
  overlap by test.
- Naming: keep the committed filenames the runbook uses (`stage1.json`, `stage4.json`) and
  ADD `stage3.json`; the stale `stage2.json` header inconsistency is fixed by regenerating
  stage2 with a corrected header or replacing it — decided by the implementing agent with
  the run aspect's registry table, recorded in the commit message.
- Header of every stage file states: composition (controls vs real, order), seed, exclusion
  set path, and regeneration command.

## Testing strategy

- Deterministic, no network; seed and exclusion are inputs, never `random` without a seed.
- Existing reproducibility tests for the draw must stay green (the 20260723 draw is
  byte-identical).

## Environment & determinism

- No env vars. The new seed is committed in the script call and in the file headers.

## Edge cases & error handling

- A real id present in BOTH observed.json and a fresh draw → assertion failure (AC-2/4/5
  property tests); the generator fails closed, never silently drops a control.
- An exclusion that would make the pool insufficient (`InsufficientPoolError` from
  `selection.py`) → fail with the count, never a short draw.
- s3-partial ids not mechanically derivable → the script derives what it can; the run
  aspect's evidence note carries the remainder (documented, never guessed).
