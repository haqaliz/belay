## Design (decided; the agents implement it)

- `verify_turn` gains keyword `shell_server_command: Sequence[str] | None = None`.
  Resolution, exactly: `tool_name == "run_process"` (the `_EVIDENCE_TOOL` constant from
  `belay.verify.trajectory`) AND `shell_server_command is not None` → resolved command =
  shell; otherwise `server_command`. The resolved command feeds `replay_turn` AND
  `classify_determinism` inside `verify_turn` (`src/belay/verify/turn.py:225-267`).
- `run_batch` / `_verify_one_trace` gain the same optional param, threaded to `verifier(...)`
  and — per flagged turn, resolved by `verdicts[n].tool_name` — to each `ingester(...)` call
  (`runner.py:354-450`), so a corpus case stores the command its turn actually replayed
  against. The trajectory case resolves by the final turn's `tool_name`.
- CLI: `belay phase0 run --shell-server CMD` = ONE string, `shlex.split()` at use (argparse
  cannot host a second REMAINDER). Absent → `None` → today's behavior.
- `eval/minting_driver/entrypoint.py` `verify_command()`: for `filesystem+shell`, emit
  `--server node <fs-entrypoint> '{workspace}' --shell-server "node <shell-entrypoint>"`
  (the shell entrypoint from `resolve_server_entrypoint("shell", ...)`); filesystem-only
  byte-identical.
- No ledger/report/trace-format/vocabulary change. UNVERIFIED-never-PASS preserved.

## Testing strategy

- Deterministic, no network: fixture servers only; the darwin-gated e2e stays gated; the live
  smoke stays `-m manual`.

- The honesty contract is pinned per surface: ledger bucket + `TurnVerdict.cause` + CLI help.

## Environment & determinism

- No new env vars. No clock/network/randomness in tests. `shlex.split` is deterministic for
  the documented quoting shape.

## Edge cases & error handling

- Shell turn, `shell_server_command` given, replay unreadable → UNVERIFIED (named cause),
  never PASS — the `_replayed_is_error` None path.
- Shell turn, replay fails to spawn → UNVERIFIED with the engine's cause.
- `run_process` turn but `shell_server_command=None` → today's behavior (replays against
  `server_command`; the README's "finding for the successor" caveat now has a flag to
  remove it — no behavior change when absent).
- Shell command contains spaces → must arrive as one quoted string; shlex-split pinned by
  test; a malformed (un-lexable) string is a fail-closed CLI error, not a silent guess.
- Embedded in-root paths inside `command_line` → existing `replay-relocation-shell` machinery
  (untouched).
