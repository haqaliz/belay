## 1. Design decisions (resolve before coding)

### D1 — The gate belongs in `engine._relocation_decision`, not `client.py`

The spec says "client.py consumes the `changed` flag". **Implement it in the engine instead**,
and here is why: `_relocation_decision(source_root, arguments, argv)` already receives the argv
and already returns `(relocation_root, fallback_cause)`, and `engine.replay_turn` returns
UNVERIFIED from it **before any restore or spawn** (`engine.py:391-393`). That satisfies
acceptance criterion 2 ("does not spawn") by construction rather than by a second guard.
`client.py` keeps its mechanism unchanged.

Add a defensive no-op in `client.py` only if it costs nothing — the engine is the single gate.

### D2 — The conservative rule, and its honest cost

**Rule:** with a recorded `source_root`, when the turn's arguments need relocation but **no
argv token is under `source_root`**, return UNVERIFIED with a named cause.

**The cost, stated plainly:** a server that takes *no* root argument yet accepts absolute paths
would be relocatable via arguments alone, and this rule marks it UNVERIFIED anyway. That is a
**false UNVERIFIED, not a false verdict** — an honest abstention, consistent with
UNVERIFIED-never-PASS. We cannot distinguish "rootless by design" from "mis-rooted" from argv
alone, and the failure we are fixing (silent false FAIL) is far worse than an abstention.
Phase 4 removes the case in practice for the mint.

Flag if the RED phase shows an existing test hits this — that would mean a real rootless
absolute-path server is already exercised, and D2 needs revisiting rather than forcing.

### D3 — Phase 4's CLI surface: a `{workspace}` placeholder in `--server`

The spec asked the plan to decide, preferring no new flag. **Recommendation:**

```
belay phase0 run <batch-dir> --server node <entry> {workspace}
```

The engine substitutes each turn's **own recorded `source_root`** for `{workspace}`, then
relocation rewrites it to the scratch exactly as today — one code path, no second mechanism.

Why this over a `Callable` seam: the engine *already knows* each trace's root. Requiring the
operator to restate it per trace is the redundancy that caused this defect. A `Callable`
threaded through `run_batch` is still needed as the library-level seam (it is what `eval/`
will call), but the CLI should not ask for information the trace already carries.

**Backwards compatible:** no placeholder → today's constant command, byte-identical.

### Phase 2 — GREEN (b): the honesty floor

**Goal:** a replay that cannot be correctly rooted abstains instead of fabricating a FAIL.

**Files:** `src/belay/replay/engine.py`.

1. Add a cause constant beside `ROOTLESS_RELOCATION` (`engine.py:97-103`), following its
   comment style. Wording must let an operator tell the two apart — the root *was* recorded;
   the **server command** cannot reach it. Suggested:
   `"server command is not rooted at the recorded workspace; cannot relocate"`.
2. In `_relocation_decision`, in the `source_root is not None` + `turn_needs_relocation` branch,
   test whether any argv token is under `source_root` (reuse `remap_argv(...)[1]`, or `is_under`
   directly — prefer `is_under`, it states the intent without a throwaway remap). If none →
   return `(None, <new cause>)`.
3. Update the function's docstring — it currently says argv is consulted only for the recorded-
   root case; that stays true, but the new failure mode must be documented there.

### Phase 4 — GREEN (a): per-trace server rooting

**Goal:** one invocation verifies a heterogeneous batch.

**Files:** `src/belay/replay/engine.py`, `src/belay/phase0/runner.py`, `src/belay/cli.py`.

4. Document the placeholder in the `--server` help text and in the phase0 CLI docstring.

## 5. Edge cases → verdicts

| Case | Verdict |
|---|---|
| Recorded root, argv rooted correctly | today's behavior, unchanged |
| Recorded root, argv rooted elsewhere | **UNVERIFIED**, new named cause (was: false FAIL) |
| No recorded root, absolute-path args | **UNVERIFIED**, `ROOTLESS_RELOCATION` (unchanged) |
| cwd-relative capture | no relocation; byte-for-byte unchanged |
| Out-of-root absolute arg (`/etc/hosts`) | untouched — `relocate.py` rule is deliberate |
| `{workspace}` placeholder, no recorded root | **UNVERIFIED**, `ROOTLESS_RELOCATION` |
| Rootless-by-design absolute-path server | **UNVERIFIED** (D2's accepted false abstention) |

**A silent pass is never an acceptable fallback**, and no case above may produce FAIL from a
rooting problem — a rooting problem is an evaluation failure, not a violation.

## 7. Assumptions

1. `is_under` (`relocate.py:57`) is the right in-root test for argv tokens — it is what
   `remap_argv` already uses, so the gate and the mechanism agree by construction.
2. The `abs_path_editor_server.py` fixture can be launched at a root that differs from the
   capture root without modification (it rejects out-of-root paths, which is the behavior under
   test).
3. `run_batch`'s existing callers can absorb an added keyword-only parameter with a default.
4. No consumer outside `src/` depends on a mis-rooted replay returning FAIL. (Nothing could
   sanely depend on that, but it is an assumption, so it is written down.)
