## 2. Implementation phases

### Phase 1 — RED demonstration on the pre-fix tree (then revert)

- **Goal:** prove the new tests exercise the FIXED behavior — they must fail against the
  old namespace. Sequence: write the tests (Phase 2 below), run them against the current
  (fixed) tree to see them pass, then `git stash` the `add.py` change from aspect 1, run
  again, observe the banking assertions fail (old `-turn<final>` id), and `git stash pop`.
- **Validation:** the stash run shows exactly the namespace-shaped failures; the pop
  restores green.
- **Commit:** none — the demonstration is evidence, not a commit.

### Phase 2 — Proof + negative tests (test-only)

- **Goal:** pin the measurement pipeline end-to-end and the fail-closed honesty contract.
- **Files to modify:** `tests/test_corpus_trajectory_ingest.py` (reuse its rig; the banking
  fixtures already exist).
  1. **End-to-end score proof.** From a synthetic mint with a trajectory FAIL: case banks
     (`-trajectory` id) → `belay corpus label`-equivalent (set `human_label="true-positive"`
     on the stored case via `write_case`/the label API the tests use — check
     `tests/test_corpus_metrics.py` and `curate.py` for the exact call) → `score(cases)`
     from `src/belay/corpus/metrics.py` → assert `precision == 1.00` and `recall == 1.00`
     with a REAL denominator (1 TP / 0 FP), in a corpus that also holds a per-turn case
     (both shapes counted). Assert `coverage` is real, not `None`.
  2. **The `n/a` honesty pin.** The same corpus with the trajectory case's label left
     `pending` → `precision is None` (rendered `n/a`), never a fabricated 1.00 — the
     `_ratio` zero-denominator contract (`metrics.py:149-155`).
  3. **Unrestorable-pre-state negative.** A trace whose FINAL turn's `state_handle` has
     `status != "present"` (e.g. `"absent"`) + a trajectory FAIL → `_ingest_run` yields no
     trajectory case, `trajectory_unaddable` carries the named pre-state cause, the
     instance disposition stays `VERIFIED_FLAGGED`, and the instance remains in the
     violation denominator. Model on `add.py:303-308` (the pre-state check runs BEFORE the
     collision check — the cause reported is the pre-state one, never "already exists").
     The rig's `_write_gated_trace` always writes `{"status": "present", ...}` — write the
     trace with a modified handle for the final turn (a small local helper or a
     post-edit of the written trace bytes; prefer a helper parameter if trivial, otherwise
     rewrite the handle line in the trace file before ingest).
- **Validation:** targeted + full suite green.
- **Commit:** `test(corpus): labeled trajectory cases score with real denominators; unrestorable pre-state stays unbankable`

## 5. Environment & determinism

- No env, no network, no clock; `score()` is a pure function (`metrics.py:197-263`, no IO —
  pinned by `test_score_performs_no_io`). The proof test's hand-computed values must match
  the assertion exactly (1 TP / 0 FP / real denominators).

## 6. Edge cases & error handling

- **Pending labels → n/a, never 1.00** (test 2) — the honesty contract the repo pins
  everywhere.
- **Unrestorable pre-state cause ordering** (test 3) — the pre-state cause, never the
  collision cause; fail-closed, never a guessed restore.
- **Both shapes in one score** (test 1) — the trajectory case counts through its
  `expected.reduced_status == "FAIL"` (built at `runner.py:464-478`); no metrics change
  should be needed. **If the test forces one, STOP and report** — the PRD decision was
  "score() unchanged"; a forced change means the understanding was wrong.
