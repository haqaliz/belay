## Decisions fixed at plan time

- **Producer shape:** `_materialize_final_state` returns `tuple[Optional[Path], Optional[Abstention]]`
  (exactly one is non-None). Private, one call site (`claims.py:372`), no test stubs it.
- **Vocabulary:** shared `SUB_CAUSES` grows 8 -> 12. A pinned `SUB_CAUSES_BY_CAUSE` map
  (`NO_CHECK_AUTHOR` -> the eight `AUTHOR_*`, `FINAL_STATE_UNOBSERVABLE` -> the four
  `FINAL_STATE_*`) is the single source; `SUB_CAUSES` is derived from it so the two cannot drift.
- **Mismatch guard lives in `_unverified`** (it alone sees cause and abstention), raising
  `ValueError`. `Abstention.__post_init__` keeps its membership check (now against the 12).
- **`_unverified` without an abstention stays legal** (it stays total). `evaluate_claim`
  always supplies one for `FINAL_STATE_UNOBSERVABLE`, pinned across all four reasons.
- **`_one_line` slices `str`, not bytes** (`claims.py:~140`), so a multi-byte character cannot
  be split. Pin it with a test; no code change expected.
- Reason (b) detail = `type(exc).__name__` only. (a) and (d): empty detail. (c): `reply.status`
  plus `: reply.cause` when present, through `_one_line`.

## Testing strategy
Acceptance list is `./spec.md`; each bullet maps to a Phase 1-3 test. Deterministic, no network, no

No model call runs.

## Environment & determinism
No env vars, no new dependency. `uv sync` already done in the worktree. Nothing here depends on
time, network or ordering; `SUB_CAUSES` stays a frozenset and the map is pinned as a literal.

## Edge cases & error handling
- Every path stays UNVERIFIED with a named cause; the sub-cause refines, never decides.
- A mismatched sub-cause is a programmer error and raises `ValueError` at build time, mirroring
  `Abstention`; it cannot occur at runtime because `evaluate_claim` supplies the pair.
- Old stored verdicts carry no sub-cause and are never back-filled (surface aspect pins that).
- `replay_turn` raising is caught as before (`except Exception`), now recording the type name.
