# A3 — Linux snapshot/restore backend: implementation plan (2026-08-15)

Aspect spec: `docs/planning/linux-sandbox/linux-snapshot/spec.md`
PRD: `docs/planning/linux-sandbox/prd.md` (M4, OQ-5)

## Goal

A Linux `SnapshotBackend` on the existing pattern (`ClonefileBackend`,
`src/belay/snapshot/substrate.py:317-343`): byte-identical snapshot/restore on
the Linux substrate, honest about fidelity (reflink where available, copy
fallback on ext4 CI runners), capability-mismatch refusal preserved, Linux
`gc()` path, and the three reserved taxonomy causes reachable.

## Project setup

- New module `src/belay/snapshot/linux.py`.
- Stdlib-only (ctypes for `FICLONE`; `os.listxattr` already exists on Linux —
  `bth1.py:272-276` handles it).
- The backend registers into the same seam `ClonefileBackend` uses
  (`substrate.py`); manifest round-trip (`persist.py`) unchanged.

## Implementation phases

### Phase 1: the backend skeleton + capability probing (RED first)

**Goal:** `LinuxSnapshotBackend` exists with a probed `capabilities()`; the
registration point is tested.

**Prerequisites:** none (independent of A2 — lives in `snapshot/`).

**Files:**
- `src/belay/snapshot/linux.py`:
  - `class LinuxSnapshotBackend` mirroring `ClonefileBackend`:
    `name = "copy-fidelity"` (or `"reflink"` when probed — decide: one name,
    capabilities declare the substrate truth). `capabilities()` **probed, never
    declared**: detect `FICLONE` support (try a real `ioctl` reflink on a
    scratch pair in the snapshot dir; report `reflink` cap only if it works),
    `hardlinks`, `special-modes` (setuid/setgid/sticky via chmod), `dir-mtimes`
    (os.utime deepest-first), `xattrs-os-native` (`os.listxattr` — already the
    ClonefileBackend branch, reuse), `symlinks`, `devices?` (decide vs the
    `Guard` refusal in `substrate.py:252-315` — FIFO/socket/device refusal is
    substrate-neutral, keep it).
  - `snapshot()` / `restore()` functions equivalent to `clone.py:266-292`
    behind the same `take_snapshot`/`guarded_restore` seam.
- `src/belay/snapshot/substrate.py` — register the Linux backend in the
  selection/dispatch the way `ClonefileBackend` is selected today; `gc()`
  gains a Linux branch (plain rmtree — no `chflags`/`chmod -N`, which do not
  exist on Linux).
- `tests/test_linux_snapshot.py` (RED): fixtures asserting backend
  registration, capability probing is honest (a backend cannot claim `reflink`
  on ext4), and `capabilities()` differencing refuses cross-substrate restore
  (`UNRESTORABLE_CAPABILITY_MISMATCH`).

**Validation:** `uv run pytest tests/test_linux_snapshot.py` green (on Linux;
skipif elsewhere), macOS suite green.

**Commit:** `feat(snapshot): Linux backend skeleton + probed capabilities — RED first`

### Phase 2: byte-identical snapshot/restore on the Linux substrate

**Goal:** hash-of-tree equality for restored trees covering the BTH-1 field
set, via the reflink path where available and the copy fallback (the CI path on
ext4).

**Prerequisites:** Phase 1.

**Files:**
- `src/belay/snapshot/linux.py` — the real implementation:
  - Reflink path: recursive `FICLONE` via ctypes ioctl (`_clonefile`
    analogue); falls back per-file to copy on `EXDEV`/`EOPNOTSUPP` — the
    **honest fallback** records the substrate's truth in `capabilities()`
    (no `reflink` cap ⇒ every consumer knows).
  - Copy path: `os.link` for hardlink groups (sidecar, same pattern as
    `clone.py`), `os.symlink`, `shutil.copystat` + deepest-first `os.utime`
    restamps for dir mtimes, `os.chmod` for setuid/setgid/sticky, xattr copy
    via `os.listxattr`/`os.setxattr`, `st_rdev` for the (refused) device
    taxonomy.
  - Sidecar: reuse the `Sidecar` manifest format from `clone.py:117` /
    `persist.py` — manifest round-trip unchanged (PRD M4).
- `tests/test_linux_snapshot.py` (extend, RED→GREEN): the fixture tree —
  nested dirs, symlinks, hardlinks, setuid/setgid/sticky modes, non-ASCII and
  normalization-edge names, xattrs — snapshot → restore → hash-of-tree
  equality (spec criterion 1). Run the copy path unconditionally; run the
  reflink path only when the substrate claims the cap (spec criterion 2).

**Validation:** the extended test green on Linux; macOS suite green
(fixtures skipif linux-only).

**Commit:** `feat(snapshot): byte-identical Linux restore — reflink where available, honest copy fallback`

### Phase 3: taxonomy causes reachable on Linux + `gc()` Linux path

**Goal:** the three reserved causes become real on Linux; `gc()` works without
macOS-only calls.

**Prerequisites:** Phase 2.

**Files:**
- `src/belay/snapshot/linux.py` (or `substrate.py` — where the causes are
  raised): `UNRESTORABLE_CASE_COLLISION`, `UNRESTORABLE_INVALID_UTF8_NAME`,
  `UNRESTORABLE_NORMALIZATION_COLLISION` raised from real Linux fixtures —
  ext4 (case-sensitive) can produce case-collision and
  normalization-collision trees that APFS cannot, and invalid-UTF8 names that
  APFS rejects (`substrate.py:154-160` already reserves these for this slice).
  The exhaustive-classification tests (`substrate.py:59-61`,
  `test_each_locally_raised_cause_is_actually_produced`) must pass.
- `src/belay/snapshot/substrate.py` — `gc()` Linux branch: plain recursive
  removal (no `chflags`/`chmod -N`); document the Linux immutable-bit
  difference (an agent that sets `chattr +i` strands disk — stated, not
  silently ignored).
- Tests: `tests/test_linux_snapshot.py` adds the three fixtures; `gc()` test
  removes a tree incl. non-ASCII names (spec criteria 4-5).

**Validation:** the three cause fixtures green on Linux; classification tests
green; macOS suite green.

**Commit:** `feat(snapshot): Linux taxonomy causes reachable + Linux gc() path`

### Phase 4: un-gate the darwin-dependent snapshot tests on Linux

**Goal:** the ungated-but-clonefile-dependent tests run green on Linux via the
new backend (spec: "gain Linux coverage via the new backend").

**Prerequisites:** Phases 1–3.

**Files:**
- `tests/test_snapshot.py`, `tests/test_turn_gate.py`,
  `tests/test_snapshot_persist.py`, `tests/test_persist_relative_tree.py`,
  `tests/test_persist_source_root.py`, `tests/test_substrate.py` — remove or
  relax the darwin-dependence so they exercise the Linux backend on Linux
  (backend selection by platform in the test setup; the tests themselves stay
  substrate-neutral where possible). `test_substrate.py:273/287` backend-name
  assertions become parameterized (`clonefile-apfs` on darwin,
  Linux name on linux).
- Do NOT touch the macOS e2e gates that assert darwin-specific behavior
  (those stay; A4 handles the gating split).

**Validation:** the full suite green on Linux CI (the A4 ubuntu job — run
locally on a Linux box or wait for A4's CI).

**Commit:** `test(snapshot): darwin-dependent snapshot tests run green on the Linux backend`

## File-by-file build order

1. `src/belay/snapshot/linux.py` (backend skeleton + capabilities)
2. `tests/test_linux_snapshot.py` (RED)
3. `src/belay/snapshot/substrate.py` (registration + `gc()` Linux branch)
4. `src/belay/snapshot/linux.py` (reflink + copy implementation) — GREEN
5. Taxonomy fixtures + gc test
6. Un-gating edits in the six darwin-dependent test files

## Testing strategy

- Unit: capability probing honesty (no fake `reflink` on ext4), registration,
  sidecar round-trip.
- Integration: the byte-identical fixture tree (spec criterion 1); reflink
  path where the substrate supports it.
- Error paths: capability-mismatch refusal (spec criterion 3); the three
  reserved causes (spec criterion 5).
- Commands: `uv run pytest tests/test_linux_snapshot.py`; full suite green on
  both platforms.

## Environment & determinism

- No new deps (ctypes/stdlib only) — zero-dep contract (`pyproject.toml:42-43`).
- Deterministic: hash-of-tree equality is the assertion; no clocks, no network.
- CI substrate (ext4) exercises the copy path — the honest fallback IS the
  tested path (OQ-5).

## Edge cases & error handling

- Cross-substrate restore: refused via capability mismatch (unchanged
  `substrate.py:393-410`) — a macOS-banked corpus case on Linux is
  `UNVERIFIED`-by-capability-mismatch (PRD eval-data line); assert, never
  loosen.
- Reflink fails mid-tree (`EXDEV`/`EOPNOTSUPP`): per-file fallback to copy,
  capability stays honest.
- Hardlink groups across filesystems: sidecar rebuilt, same contract as
  clone.py.
- Invalid-UTF8 / normalization collisions: named causes, never silent.

## Agent execution notes

- Checkpoint: Phase 1 (backend skeleton + registration) — the naming and
  capability vocabulary decision is worth a look before implementation.
- The copy path is the CI path: do not optimize it away; its fidelity is the
  product on ext4.
- The taxonomy fixtures (Phase 3) are the trickiest — case-collision and
  normalization-collision trees must be constructed on a case-sensitive
  filesystem; use `tmp_path` on the runner and verify the fixture actually
  creates the collision (a fixture that silently doesn't collide would make
  the cause unreachable — the classification test catches that).
