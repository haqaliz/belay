# A1 — Containment spike: implementation plan (2026-08-15)

Aspect spec: `docs/planning/linux-sandbox/containment-spike/spec.md`
PRD: `docs/planning/linux-sandbox/prd.md` (M1, OQ-1, OQ-2/allow-ports, OQ-4/denial-semantics)

## Goal

Measure, on a **pinned** GitHub Actions runner image, which Linux containment
mechanism can enforce Belay's boundary — and record the evidence as a machine-
readable artifact the later aspects cite. This aspect produces a **decision
document + probe code + CI job**. It ships no `src/belay/` product code.

## Project setup

- New eval/planning tooling lives under `eval/linux_probe/` (eval-only tree,
  consistent with `eval/minting_driver/`; NOT part of the wheel).
- Probe runs on `ubuntu-24.04` (pinned image — `ubuntu-latest` is a moving
  target). Python 3.12 via `uv`.
- Zero new dependencies: the probe is stdlib-only (ctypes for prctl/landlock and
  for clone/unshare probes; `subprocess` for bwrap).

## Implementation phases

### Phase 1: the probe script + its unit tests

**Goal:** `eval/linux_probe/probe.py` measures all five probes and emits a single
JSON artifact; the probe's own logic is unit-tested so CI failure means a real
measurement change, not a bug in the probe.

**Prerequisites:** none.

**Files:**
- `eval/linux_probe/__init__.py` — package marker (empty or one-line docstring).
- `eval/linux_probe/probe.py` — the probe. Functions:
  - `probe_unshare_userns() -> dict` — try `unshare(CLONE_NEWUSER|CLONE_NEWNS)`
    via ctypes + `unshare -Urm` subprocess; report `ok` / `restricted` / error.
  - `probe_bwrap() -> dict` — `shutil.which("bwrap")`; if absent report
    `absent`, else run a minimal `bwrap --ro-bind / / --dev /dev --proc /proc
    --unshare-all -- /bin/true` and report rc; then a refused-write probe:
    `bwrap --bind <scratch> <scratch> --bind / / <scratch> <scratch>
    -- /bin/sh -c "echo x > /etc/blocked-file"` (or similar) capturing the
    stderr text and whether it contains "Operation not permitted" (EPERM) vs
    "Permission denied" (EACCES).
  - `probe_landlock() -> dict` — kernel ≥5.13 check via
    `os.uname().release` (accept `unavailable` if parse fails); attempt
    `prctl(PR_SET_NO_NEW_PRIVS)` + `prctl(PR_LANDLOCK_CREATE_RULESET, 0)` via
    ctypes; report whether the syscall exists (`ENOSYS` vs `EINVAL` vs success).
    Report `unavailable` with the reason on any failure — never a silent skip.
  - `probe_allow_ports_mapping() -> dict` — for the leading mechanism (bwrap if
    present else landlock): does the closed vocabulary `allow-ports` (loopback
    only, given ports) map? For bwrap: `--unshare-net` gives full isolation
    (deny-all) but no per-port; report `not-expressible-without-netns-tools` as
    the measured finding unless a viable stdlib-only route exists (nftables/
    iptables need root — report that). For landlock: filesystem-only by design —
    report `not-expressible` (landlock v1/v2 does not do network ports).
  - `probe_denial_marker() -> dict` — for each viable mechanism, capture the
    exact stderr text of a refused write and classify EPERM vs EACCES.
  - `probe_env() -> dict` — `platform.platform()`, `os.uname()`, image tag via
    `GITHUB_RUNNER_IMAGE` / `RUNNER_OS` env (present on GH runners), python
    version.
  - `main() -> int` — run all probes, write `probe_result.json` (image tag + all
    probe dicts + timestamp is NOT included — the artifact must be deterministic
    for re-runs; keep `git_sha` only if available) and print a human summary.
- `tests/test_linux_probe.py` — unit tests over the probe's pure helpers
  (classification of stderr text into EPERM/EACCES, env-dict shaping, JSON
  schema shape: every probe key present, values are `ok|unavailable|absent`
  with a `reason` when not ok). The syscall-touching functions are exercised on
  the CI job only (marked `manual` or guarded so the macOS suite stays green).

**Validation:** `uv run pytest tests/test_linux_probe.py` green on macOS
(probe logic is platform-neutral; live syscall probes skip off Linux via
`@pytest.mark.skipif(sys.platform != "linux")`).

**Commit:** `test(linux): containment probe unit tests + probe script — RED first`

### Phase 2: the CI spike job

**Goal:** `.github/workflows/ci.yml` gains a `spike-linux` job on
`ubuntu-24.04` that runs the probe and **uploads the artifact**, plus a second
run to assert determinism (same result on the same image — spec criterion 3).

**Prerequisites:** Phase 1.

**Files:**
- `.github/workflows/ci.yml` — new job:
  `spike-linux: runs-on: ubuntu-24.04`; checkout; `setup-uv`; `uv sync`;
  `uv run python eval/linux_probe/probe.py`; upload `probe_result.json` via
  `actions/upload-artifact`; then re-run and `diff` the two JSONs (assert
  byte-identical) as the determinism check.
  - The job is allowed to be informational in the sense that the probe never
    fails CI on an `unavailable` result — `unavailable` IS a valid measurement.
    CI fails only if the probe itself errors (non-zero, no artifact).

**Validation:** the job is green on this branch's PR and the artifact is
downloadable; the written decision below cites it.

**Commit:** `ci(linux): spike job on pinned ubuntu-24.04 — probe artifact + determinism`

### Phase 3: the written decision

**Goal:** `docs/planning/linux-sandbox/containment-spike/decision.md` — the
measured answer to OQ-1/OQ-2/OQ-4, cited to the probe artifact, and the A2/A3
mechanism choice. No claims from memory or literature (spec criterion 4).

**Prerequisites:** Phase 2 green (artifact exists).

**Files:**
- `docs/planning/linux-sandbox/containment-spike/decision.md` — sections:
  1. Probe provenance: runner image, artifact path, date, determinism result.
  2. Per-probe findings (userns, bwrap, landlock, allow-ports, denial marker)
     each citing the artifact's JSON path.
  3. **The decision:** which mechanism A2 builds on; what `allow-ports` degrades
     to (UNVERIFIED-with-cause per M7/OQ-2) if not expressible; what the denial
     marker on Linux is (EPERM/EACCES) and whether `_DENIAL_MARKER` survives or
     a Linux-specific marker is required — record shape identical either way.
  4. Consequences for A3 (does the mechanism constrain the snapshot backend?
     it should not, but record the finding).
  5. If **no mechanism is viable** on the pinned image: state that plainly —
     the plan is revised (A2 acceptance is unreachable), per spec's
     out-of-scope note.

**Validation:** decision.md exists, every claim carries an artifact citation,
A2/A3 plans update their mechanism lines to point at this file.

**Commit:** `docs(linux): containment spike decision — mechanism measured on ubuntu-24.04`

## Testing strategy

- Unit tests on probe helpers (platform-neutral, run on macOS suite too).
- Live probes: `manual`-marked or Linux-skipif'd — never in the macOS CI job.
- Determinism: double-run diff inside the spike job.
- No network in unit tests; the spike job's probe may make no network calls
  (bwrap probes are local subprocesses).

## Environment & determinism

- `ubuntu-24.04` pinned in the workflow `runs-on`.
- No timestamps/randomness in the artifact (determinism criterion).
- Env read: `RUNNER_OS`, `GITHUB_RUNNER_IMAGE` (may be absent — record absent).

## Edge cases & error handling

- `bwrap` absent → `absent` (valid result; decision then leans landlock or
  netns-composition).
- userns restricted → `restricted` with the AppArmor message.
- landlock `ENOSYS` → kernel too old or disabled → `unavailable` + reason.
- Every probe returns `unavailable` with a reason on failure — the job NEVER
  fails because a mechanism is unavailable (that is the measurement), only if
  the probe crashes.

## Agent execution notes

- Checkpoint for human review: Phase 3 decision.md — the mechanism choice gates
  A2/A3; do not proceed past it without surfacing.
- The probe must run on the ACTUAL runner image, not a local Linux box — a
  locally-green probe that differs on GH runners is the failure mode this aspect
  exists to prevent.
- Iteration likely: the refused-write probe's exact bwrap argv will need
  adjustment; keep the JSON schema stable while tuning argv.
