## Goal

The ubuntu CI job runs the full suite green under the user-confirmed gating
split; the reverse gate is rewritten; docs stop claiming macOS-only, with a
measured `THREAT_MODEL.md` Linux section and a README coverage line that
includes the cross-substrate `UNVERIFIED` consequence.

## Implementation phases

### Phase 1: the ubuntu CI job

**Goal:** `.github/workflows/ci.yml` runs the full suite on `ubuntu-24.04`
(pinned — same rationale as A1) with the gating split.

**Prerequisites:** A2 + A3 green on Linux (containment and snapshot must exist
or the job cannot pass); A1's spike job already landed.

**Files:**
- `.github/workflows/ci.yml` — new job `test (Linux)`:
  `runs-on: ubuntu-24.04`; checkout; `setup-uv`; `uv python install 3.12`;
  `uv sync`; `uv run ruff check .`; `uv run pytest -q`.
- **Gating split (user-confirmed reading of "no platform skips"):**
  - Substrate-independent sandbox/replay tests: already unmarked — run on both
    platforms (their darwin-gated `pytestmark` modules are the ones listed
    below; the ungated ones already run everywhere).
  - Substrate-specific tests with Linux analogues (written in A2/A3):
    the escape matrix, restore fidelity, denial capture — linux-skipif'd on
    macOS and darwin-skipif'd on Linux, both run in their respective jobs.
  - Genuinely seatbelt-only tests (e.g. `test_sbpl_limits.py`, which pins
    against `sandbox-exec` itself): stay darwin-gated with a **named cause** —
    the reason lives in README (Phase 2) and the skip reason string.
- First run will surface darwin-gated modules that are actually
  substrate-independent and can be unmarked; and A4 also fixes the ungated
  darwin-dependent tests that ERROR (these are the ones A3 Phase 4 handles;
  if any remain, they get an explicit named-cause gate in this phase).

**Validation:** the ubuntu job is green on this branch's PR; macOS job stays
green.

**Commit:** `ci(linux): full-suite ubuntu-24.04 job with the gating split`

### Phase 2: reverse gate + skip-report test

**Goal:** the corpus round-trip reverse gate asserts the new reality; a test
guards the "every remaining sandbox skip has a named cause" rule.

**Prerequisites:** Phase 1 green enough to enumerate the real remaining skips.

**Files:**
- `tests/test_corpus_roundtrip.py:103-105` — the
  `skipif(sys.platform == "darwin")` reverse gate rewritten: on Linux the
  off-substrate SKIP is no longer the expectation (the Linux backend replays);
  assert the new behavior (a corpus case captured on clonefile/APFS on a Linux
  box → capability-mismatch UNVERIFIED/skip with the named cause, per PRD
  M4/eval-data line).
- `tests/test_platform_gate_named_causes.py` (new) — scans the sandbox/replay
  test files' skip markers: every remaining darwin/linux gate in the
  sandbox/replay area maps to a named cause listed in README's platform
  coverage section. This is the L2/L5 "no skips without a named cause" rule
  made a test (spec criterion 2).

**Validation:** both green on both platforms.

**Commit:** `test(corpus): reverse gate rewritten for Linux replay; named-cause gate scan`

### Phase 3: `THREAT_MODEL.md` Linux section + README + classifier

**Goal:** honest docs — the Linux boundary's exact claims, measured; README
stops claiming macOS-only.

**Prerequisites:** A1 decision + A2/A3 acceptance runs exist (the doc cites
measured artifacts).

**Files:**
- `docs/technical/THREAT_MODEL.md` — new Linux section (same structure as the
  macOS sections): what is enforced (write scope, network vocabulary per the
  closed enum, denial recording), what is NOT enforced — **stated per the A1
  measurement**: are reads scoped on the Linux substrate? (landlock CAN scope
  reads; bwrap bind-mounts scope them too — a DIFFERENT answer than macOS's
  `file-read*` wholesale must be stated, not copied); denial provenance
  (shape-identical to macOS: `inferred: true, source: "child-stderr"`); the
  new R8 surface (the Linux launcher path — binary discovery, argv
  composition); TMPDIR/world-writable `/tmp` difference (`scope.py:243-246`);
  the cross-substrate corpus consequence (banked macOS cases → UNVERIFIED on
  Linux by capability mismatch). Every behavior claim cross-references the
  probe/acceptance artifact (spec criterion 4).
- `README.md` — badge (line 13), "The sandbox is macOS only" section
  (lines 220-221) → "macOS + Linux (measured)" with the coverage line; the
  cross-substrate UNVERIFIED line (PRD eval-data); the named-caused gates.
- `pyproject.toml:33` — add `"Operating System :: POSIX :: Linux"`.
- `docs/technical/PHASE0_RESULTS.md:482` — update the macOS-only caveat.

**Validation:** docs render; every Linux claim in THREAT_MODEL traces to an
artifact; classifier present.

**Commit:** `docs(threat-model): Linux boundary stated and measured; README coverage line updated`

## Testing strategy

- CI config is its own validation (job green on PR).
- The named-cause scan test is the guardrail (spec criterion 2).
- Deterministic, no network.

## Environment & determinism

- `ubuntu-24.04` pinned; macOS `macos-latest` unchanged.
- No new env vars; `BELAY_SANDBOX_*` semantics unchanged.

## Edge cases & error handling

- A darwin-gated test that is actually substrate-independent: unmark it (run
  on both). A linux test that cannot pass on the runner (mechanism absent):
  named-cause gate in README — never a silent skip.
- The ubuntu job's first run will have failures from ungated darwin-dependent
  tests — expected; fix via A3 Phase 4 or named-cause gate, in that order.

## Agent execution notes

- Checkpoint: Phase 1 (the ubuntu job's first green run) — before docs work,
  the CI must be a fact.
- The THREAT_MODEL Linux section is the honesty contract in prose: do not copy
  the macOS claims; each Linux claim must answer "measured where?".
- Iteration likely in Phase 1 as the gating split settles; keep the split
  mechanical (skip-reason strings carry the named cause).
