# A2 — Linux containment: implementation plan (2026-08-15)

Aspect spec: `docs/planning/linux-sandbox/linux-containment/spec.md`
PRD: `docs/planning/linux-sandbox/prd.md` (M2, M3, M7, S1, S2)
Mechanism: **decided by A1** (`containment-spike/decision.md`) — read it first.

## Goal

The seam becomes real (platform dispatch replacing the darwin-only raise
points), the A1-decided mechanism enforces the same escape matrix as macOS on
Linux, denials reach the trace with identical provenance shape, the network
vocabulary stays closed, and `belay sandbox check` tells the truth on Linux.

## Hard guardrails (from the PRD)

- **The macOS suite is the canary.** Every commit keeps `uv run pytest` green on
  macOS. The seam refactor must not land as "Linux first, macOS later".
- **Raise, never no-op:** any platform with NO implementation still raises
  `UnsupportedPlatform` with the honest message. This is the re-scoped reading
  of the brief's "preserve the raise" (understanding.md contradictions).
- **Zero runtime deps.** If the A1-decided mechanism needs a system binary
  (bwrap), absence degrades to a named-cause raise when the sandbox is
  requested — never silently unsandboxed.
- **Denial record shape is platform-stable** (`inferred: true, source:
  "child-stderr"` floor).

## Project setup

- New module `src/belay/sandbox/linux.py` (containment for the Linux substrate).
- Mechanism binaries (if any): NOT vendored; discovered via `shutil.which` at
  use time. The Docker image (L3, later) installs them.
- Existing modules: `seatbelt.py` stays macOS-only by name; dispatch sits at the
  call sites (`launch.contained`, `seatbelt.run` is called from
  `launch`/`cli`/tests).

## Implementation phases

### Phase 1: the seam — platform dispatch without behavior change (macOS green)

**Goal:** introduce the dispatch so that today's behavior is byte-identical on
macOS, and the raise-on-unsupported is expressed once, not three times.

**Prerequisites:** A1 decision.md.

**Files:**
- `src/belay/sandbox/__init__.py` — grow from the 82-byte docstring into the
  seam's public surface: re-export the current names (backward compatible) and
  add `backend_for(platform=None)` (or equivalent) that resolves
  `darwin -> seatbelt`, `linux -> linux` (once Phase 2 lands; until then linux
  still raises via a `LinuxBackend` placeholder that raises
  `UnsupportedPlatform` with the honest "no implementation yet" message ONLY if
  A1 said no mechanism — otherwise Phase 2 lands in the same PR).
- `src/belay/sandbox/launch.py` — `contained()` dispatches: macOS path
  byte-unchanged; unsupported platforms raise the same message as today. Keep
  `Contained` shape (`argv`, `scope`, `profile`, `profile_path`) — see Phase 3
  for how Linux fills `profile`.
- `src/belay/sandbox/seatbelt.py` — `run()` keeps its darwin raise (called only
  on darwin paths); note in its docstring that dispatch is upstream.
- Tests: `tests/test_launch.py:29-55` — the two linux-raise tests are **not yet
  rewritten** (Phase 4); they must stay green: monkeypatching `launch.sys.platform
  = "linux"` still raises (via the placeholder). Add a new test file
  `tests/test_seam_dispatch.py`: the dispatch resolves `darwin -> seatbelt`,
  `linux -> linux-or-placeholder`, `other -> raise`; the existing macOS suite
  passes unchanged.

**Validation:** full macOS suite green (`uv run pytest -q`), plus the new
dispatch tests.

**Commit:** `feat(sandbox): platform dispatch seam — macOS byte-identical, unsupported still raises`

### Phase 2: the Linux containment implementation

**Goal:** the A1-decided mechanism enforces write-scope containment on Linux;
escape attempts are refused AND recorded.

**Prerequisites:** Phase 1; A1 decision.md.

**Files:**
- `src/belay/sandbox/linux.py` — the Linux backend. Shape mirrors
  `seatbelt.py`'s responsibilities but for the Linux mechanism:
  - `contained(argv…)` builder / `run()` run-to-completion probe, per the A1
    mechanism (bwrap argv composition replacing `sandbox-exec -f <profile>`, or
    landlock ruleset + seccomp as decided).
  - Denial capture: `_denials_from_stderr` equivalent with the A1-determined
    marker (EPERM `Operation not permitted` if the mechanism produces it, or
    the Linux-specific marker if A1 found EACCES-only; the RECORD stays
    `inferred: true, source: "child-stderr"`).
  - Network: `deny-all | allow-all | allow-ports` mapping to the mechanism;
    per PRD M7, `allow-ports` degrades to UNVERIFIED-with-named-cause if A1
    found it inexpressible — implemented as a raise of a new
    `NetworkPolicyUnsupported`-style error that `contained()` translates into
    the honest refusal (never a silent widening, never a lie).
  - No-op denial: if the mechanism binary is absent and the sandbox is
    requested → raise `UnsupportedPlatform` (named cause: binary absent), never
    spawn bare.
- `tests/test_linux_containment.py` — the escape matrix with Linux analogues:
  direct / `../` / symlink / `mv` / grandchild writes outside scope → refused +
  recorded; positive control (write inside scope succeeds); network deny-all
  with a live listener refused. Marker: `@pytest.mark.skipif(sys.platform !=
  "linux", ...)`. If the mechanism needs a binary, the tests skip with a named
  cause when absent (mirroring `test_containment.py:177-179`'s shim pattern).

**Validation:** `uv run pytest tests/test_linux_containment.py` green on a Linux
box/CI; macOS suite untouched (new file is linux-skipif'd).

**Commit:** `feat(sandbox): Linux containment via <mechanism> — escape matrix contained and recorded`

### Phase 3: `launch.contained` Linux path + `belay sandbox check`

**Goal:** the proxy's spawn path works on Linux; the CLI reports the truth.

**Prerequisites:** Phase 2.

**Files:**
- `src/belay/sandbox/launch.py` — `contained()` linux branch composes the
  Linux argv; `Contained.profile` carries the policy artifact (for bwrap: the
  argv+bind list; for landlock: the ruleset description — same field, honest
  content). `DenialCapture` wiring unchanged (stderr pump is platform-neutral).
- `src/belay/cli.py` — `_check_substrate` (`:91-98`) and `_probe_containment`
  (`:122-175`) dispatch: `belay sandbox check` on Linux probes the Linux
  mechanism (binary present? kernel capable? per A1) and reports
  present/unavailable-with-cause — never claims a boundary that is not there
  (spec criterion 5).
- Tests: `tests/test_sandbox_check.py` gains a linux case (probe outcome
  truthful); `tests/test_launch.py:130-141` argv-shape pin becomes
  backend-parameterized (macOS asserts `sandbox-exec -f <p> env …`; linux
  asserts the mechanism's argv).

**Validation:** macOS suite green; `belay sandbox check` on Linux reports the
truth (manual + unit).

**Commit:** `feat(cli): sandbox check probes the Linux mechanism; launch.contained composes Linux argv`

### Phase 4: honest re-scope of the linux-raise tests + docstring splits

**Goal:** the old "linux raises" assertions become "linux works" (or
"linux raises with named cause when mechanism absent"); platform-specific
reasoning in docstrings split (e.g. `scope.py:163-179` env-`--` claim).

**Prerequisites:** Phases 2–3.

**Files:**
- `tests/test_launch.py:29-55` — rewritten: `test_off_macos_a_requested_sandbox_refuses…`
  becomes (a) a test that an unsupported platform (e.g. `"win32"`) still raises
  `UnsupportedPlatform` "Refusing rather than", and (b) a linux test that
  `contained` yields the mechanism argv when present, raises with named cause
  when absent.
- `tests/test_proxy_containment.py` — keep darwin-gated (it is the macOS e2e);
  no change beyond marker text.
- `src/belay/sandbox/scope.py:163-179` — docstring split: macOS `env` has no
  `--`; Linux `env` accepts it (behavior unchanged — conservative refusal stays,
  docstring corrected).
- `src/belay/sandbox/seatbelt.py` — `SandboxResult.profile` field note:
  macOS-shaped; Linux equivalent documented (per OQ-11 in the dig).

**Validation:** full macOS suite green; the two old linux-raise tests replaced
by the new assertions.

**Commit:** `test(sandbox): unsupported-platform raise pinned to win32; linux path asserted directly`

## File-by-file build order

1. `src/belay/sandbox/__init__.py` (dispatch + placeholder)
2. `tests/test_seam_dispatch.py` (RED)
3. `src/belay/sandbox/launch.py` dispatch (GREEN)
4. `src/belay/sandbox/linux.py` + `tests/test_linux_containment.py` (RED→GREEN)
5. `src/belay/sandbox/launch.py` linux branch; `src/belay/cli.py` sandbox check
6. `tests/test_sandbox_check.py`, `tests/test_launch.py` updates
7. `tests/test_launch.py:29-55` rewrite; docstring splits

## Testing strategy

- Unit: dispatch resolution, network-policy translation, denial parsing,
  binary-absent refusal (all deterministic, no network).
- Integration: Linux escape matrix (real mechanism, live listeners on loopback);
  macOS e2e stays green (the canary).
- Commands: `uv run pytest -q` (macOS), `uv run pytest tests/test_linux_containment.py`
  (Linux); `uv run belay sandbox check`.

## Environment & determinism

- Mechanism binary (if any) discovered at runtime — no new pip deps (zero-dep
  contract, `pyproject.toml:42-43`).
- Env: `BELAY_SANDBOX_SCOPE`, `BELAY_SANDBOX_NETWORK` semantics unchanged and
  platform-stable.
- Deterministic, no network except the loopback listeners the tests bind.

## Edge cases & error handling

- Mechanism absent + sandbox requested → `UnsupportedPlatform` named cause —
  **never** bare spawn (PRD M2).
- `allow-ports` inexpressible → named-cause refusal per M7 (A1 decision
  applies).
- Denial marker: A1-determined; record shape `inferred: true, source:
  "child-stderr"` identical to macOS (M3) — asserted by a field-for-field test.
- macOS path: byte-identical behavior — the whole pre-existing suite is the
  regression test.

## Agent execution notes

- Checkpoint: Phase 1 commit before touching `linux.py` (the dispatch is the
  load-bearing refactor; human review there catches seam mistakes before the
  mechanism code exists).
- The macOS canary means: run the full macOS suite after EVERY phase; never
  rely on the Linux tests alone.
- If A1's decision was "no mechanism viable" — STOP at Phase 2 and surface; the
  acceptance criteria are unreachable and the plan must be revised (spec's
  explicit fallback).
