## Design decisions (pinned; deviate only with the integrator)

1. **Module layout.** New `src/belay/gate/` package: `baseline.py` (this aspect),
   `check.py` (aspect 3), `bank.py` (store/load/identity resolution shared by both).
   CLI: `belay gate baseline <trace> [options]` registered in `src/belay/cli.py`;
   `gate` gains `check` in aspect 3. Mirror the `corpus/` package structure and its
   CLI registration style (`cli.py:2688-2954`).
2. **Baseline dir layout** (default root `baselines/local/`, gitignored — add
   `/baselines/` to `.gitignore` beside `/corpus/`):
   ```
   baselines/local/<run-id>/
     baseline.json        # schema 1: run_id, provenance, expected verdicts, stored policy
     trace.jsonl          # copy of the capture
     manifests/           # copy of the trace's manifest dir, tree_path rewritten
     snapshots/           # the snapshot trees, referenced by the rewritten tree_path
   ```
   The copy+rewrite mechanics are exactly `add_case`'s (`src/belay/corpus/add.py:280-422`:
   `copytree` + rewritten `tree_path`): the manifest joins handle → `tree_path` (absolute,
   under `BELAY_SNAPSHOT_DIR`) + sidecar bytes (`src/belay/replay/persist.py:99-121`), and
   the rewrite is what makes the baseline self-contained. Reuse the same semantics; extract
   a shared helper from `corpus/add.py` only if the extraction is clean and stays
   byte-identical for corpus — otherwise mirror the mechanics in `gate/baseline.py` (the
   corpus path must not move in this aspect).
3. **Verification at bank time.** Compose the verdict set the same way `_cmd_verify` does
   (`src/belay/cli.py:625-907`): `read_trace` → `derive_correlation`/`tool_calls` →
   `verify_turn` per turn → `evaluate_trajectory_rules` → `evaluate_claim` (the CLI's own
   imports at `cli.py:658-683` are the seam). Serialize with the SAME builders `verify
   --json` uses (`belay.verify.json`: `turn_record`, `trajectory_record`, `claim_record`)
   so the stored expected set is the engine's own machine contract — one computation, one
   serializer. A banked baseline's expected set is therefore exactly what `belay verify
   --json` of the same trace renders, modulo the gate envelope.
4. **Stored policy (re-derivation fidelity).** baseline.json stores the resolved
   `invariants` (the `--invariants` file's parsed rules / library entries — stored, never
   re-resolved, exactly the corpus `stored-invariants` pin), the resolved `server_command`
   (+ `shell_server_command` when given), `replays`, `timeout`, and the manifest
   convention used. Gate-check (aspect 3) re-verifies against THIS stored policy, which is
   what makes the comparison drift-free.
5. **Identity.** Resolve via `derive_run_identity(read_trace(...).records)`; `--run-id ID`
   overrides for pre-record captures (S2). Absent ⇒ exit 2, named cause `NO_RUN_IDENTITY`,
   nothing written. `--force` replaces an existing baseline; without it a re-bank exits 2.
6. **Provenance.** `engine_version` from `belay.__version__` (importlib.metadata, honest
   fallback — `src/belay/__init__.py:3-16`), `platform` from `sys.platform`,
   `capabilities` from the copied manifests' `capabilities` field (mirror
   `add_case`'s `sorted(snap.manifest.capabilities)`, `src/belay/corpus/add.py:415`),
   omitted when unknown (absent-never-zero).
7. **Fail-closed copy.** A manifest whose `tree_path` does not exist ⇒ bank fails, exit 2,
   named message (never a baseline with dangling pre-state). A missing manifest dir
   (`--manifest-dir`, or the `<stem>.manifests` sibling default only when it exists —
   the console precedent) ⇒ exit 2.
8. **No verdict/axis changes, no banking into the corpus** (that is aspect 4), no gate
   check (aspect 3). `--json` prints the stored baseline document.

## Testing strategy

- Mechanics (everywhere): byte-stable re-bank, expected-set equality vs `verify --json`,
  identity fail-closed, `--force`, provenance, missing manifests.
- Fidelity (darwin-gated, named cause): self-contained snapshot roundtrip.
- Compatibility: parity guard, run-identity suite, corpus roundtrip unchanged.

## Environment & secrets

`BELAY_RUN_ID` (existing). Baseline dirs hold traces + snapshots — as sensitive as the
trace itself; never uploaded; owner-mode semantics inherited from the trace/corpus paths.

## Edge cases & error handling

- Missing identity, missing manifest dir, missing snapshot tree, malformed baseline.json,
  re-bank without `--force`, a trace with zero `tools/call` (banks an empty expected set
  — legal, and the gate will report the shape divergence).
- A baseline of a FAILing capture is allowed and documented (the mechanism does not
  require all-PASS; gate-check's exact-equality compares whatever the bank stored).
