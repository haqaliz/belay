## Design decisions (pinned; deviate only with the integrator)

1. **README quickstart step.** Add a new step to the Quickstart section (after step 3
   "Grow the corpus" / before step 4 "Measure at scale", numbered to fit — renumbering
   must not break `tests/test_quickstart_docs.py`'s existing assertions): *"Gate your
   agent upgrades"* — `BELAY_RUN_ID` at capture, `belay gate baseline`, `belay gate
   check` in a CI snippet (GitHub Actions example, one job: capture step + check step),
   the exit-code table (0 clean / 1 regression / 2 preflight), the baseline location +
   gitignore note (`baselines/local/`), the substrate recommendation (bank on the CI
   substrate; cross-substrate checks SKIP with a named cause, never a false regression),
   and the honest coverage line (the gate checks what crosses the MCP boundary;
   UNVERIFIED is never PASS; new UNVERIFIED turns never fail the gate alone).
2. **Machine-checked docs.** New `tests/test_gate_docs.py` modeled on
   `tests/test_quickstart_docs.py` (deterministic string/parse checks):
   - every `belay gate …` command in the README's new section exists (parse the fenced
     block, extract the commands, assert argparse recognizes them);
   - the README's exit-code table matches the implementation
     (`exit_reason` → 0/1/2 in `src/belay/gate/check.py` / `compare.py`);
   - `--help` texts of `gate baseline` / `gate check` state the stored-policy rule (no
     `--invariants` on check) and the coverage line;
   - a guard that the published numbers (`11/60 = 18.3%`, `precision 0.00`, `1/15`,
     `4/16`) are byte-unchanged in the README/STATUS lines this unit touches (grep-style
     guard).
3. **STATUS.md + checklist entries** (the repo convention, invariant-library precedent:
   "STATUS entry, checklist row, planning artifacts"):
   - `docs/STATUS.md` gains the unit's append-only entry at the top (newest first):
     the gate ships — `belay gate baseline` / `belay gate check` with the stored-policy
     rule, the decision table (regression = PASS/WARN→FAIL; UNVERIFIED/shape/drift never
     fail; SKIP named causes), run identity (`BELAY_RUN_ID`), banking (`--no-ingest`),
     honesty lines (no axis/number moves; suite 2188 → 2261+); reference
     `docs/planning/ci-regression-gate/`.
   - `docs/planning/launch-readiness/CHECKLIST.md` progress log gains a row
     (2026-09-13, `ci-regression-gate`, Block 0 — Phase 2's first goal, not a checklist
     item).
   - `CLAUDE.md`: add the unit's block at the top of the file per the current pattern
     (the newest shipped units carry a short block there; mirror the `invariant-library`
     block style). Note: if the CLAUDE.md convention for the latest units is
     STATUS-only, follow what the actual newest blocks show — check the file's top
     before deciding, and match it.
4. **No other docs.** TRACE_FORMAT (`run_identity`) and flag parity already shipped in
   aspects 1–3; `--help` already carries the surface. No THREAT_MODEL change (no new
   boundary — the gate runs the existing sandbox/replay). No marketing copy or launch
   assets.
