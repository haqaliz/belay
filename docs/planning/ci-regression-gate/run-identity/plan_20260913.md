## Design decisions (pinned; deviate only with the integrator)

1. **Pattern: extend `KINDS`, not the skips seam.** The `claim` record reads via
   `Skip.record` because it is appended after the writer closes. `run_identity` is written
   *during the session* by the live writer, so it becomes a first-class kind in `KINDS`
   (`src/belay/trace.py:55`). The reader then returns it in `records`, and the existing
   `test_reader_understands_every_current_kind` (`tests/test_trace_reader.py:189`) extends
   automatically — it writes one record per `KINDS` entry and asserts none are skipped.
   No schema version bump (`SCHEMA_VERSION = 1` unchanged); old readers skip the new kind
   per the unknown-kind rule (`src/belay/trace.py:50-54`).
2. **Write once, at proxy start.** `main()` reads `BELAY_RUN_ID`; when a trace writer
   exists and the env is set, `writer.record("run_identity", run_id=<value>)` runs right
   after `TraceWriter.in_directory(...)` (`src/belay/proxy.py:563-566`) and before
   `run()` — the record is early (low seq), before any frame. Unset env ⇒ no record
   (absent-never-zero). Env set without `BELAY_TRACE_DIR` ⇒ inert no-op (nothing to record
   into); no error.
3. **Validation is capture-path-only and fail-closed (exit 2).** Rules, pinned by test:
   non-empty; no control chars (`ord(c) < 32 or c == 127`); no whitespace; split on `/`,
   no empty segment (no leading/trailing/double slash), no segment equal to `..`. Rationale:
   the id becomes a baseline directory key in a later aspect (`baselines/local/<run-id>/`),
   so path-traversal/segment safety is decided now, where it is cheapest. Slashes ARE legal
   (documented shape `<task>/<agent-version>`). Valid ids are recorded **verbatim**.
   Rejection message names `BELAY_RUN_ID` and exits 2, mirroring the
   `BELAY_SANDBOX_SCOPE`-without-`BELAY_SNAPSHOT_DIR` refusal precedent
   (`src/belay/proxy.py:544-554`).
4. **Derive helper is a pure function.** `belay.identity.derive_run_identity(records)`
   returns the first non-empty string `run_id` from a `run_identity` record, else `None`.
   Malformed record (non-string `run_id`) ⇒ `None` (fail-closed at the gate level later).
   No I/O, no imports of the writer (mirrors the `belay.connection` derivation pattern).

## Environment & secrets

- New env var: `BELAY_RUN_ID` — optional; set at capture time. Never logged beyond the
  trace record itself; the trace is owner-only (mode 0600, `trace.py:295-299`).

## Edge cases & error handling

- Unset env, env without trace dir, whitespace-only, control chars, `..` segments,
  leading/trailing/double slash, non-string record value — all decided in Phase 1 tests;
  fail-closed at capture, `None` at derive.
- A trace whose `run_identity` record is absent: not an error at this aspect; the gate
  aspects name it `NO_RUN_IDENTITY`.
- Writer failure while recording (writer already broken): `record()` propagates; the
  proxy's existing `finally: writer.close()` handles it — do not add a new failure path.
