## Design decisions (pinned; deviate only with the integrator)

1. **The gate is a worsen-detector, not an equality checker.** `corpus run` compares one
   trace against its own stored expected (exact equality — detector regression). The gate
   compares TWO captures of the same run, which legitimately differ in shape. So the core
   is a pure **decision table** over per-dimension status transitions, TDD'd exhaustively:
   - **REGRESSION (exit 1):** a dimension that was PASS/WARN moves to **FAIL** — per turn
     ordinal (common ordinals only), the instance-level trajectory status (PASS → FAIL),
     and the claim dimension **when the baseline declared one** (A3 never PASSes; FAIL vs
     stored FAIL is not a regression, a stored FAIL → UNVERIFIED is reported not failing).
     A **new turn** beyond the baseline's count that FAILs is a regression (it is a new
     failure — acceptance 1's "new failing turn").
   - **Named, reported, NEVER fail (exit 0):** PASS/WARN → UNVERIFIED (coverage loss —
     R7 discipline), any transition INTO WARN, FAIL → FAIL (still failing, not newly
     failing), UNVERIFIED → anything, shape divergences (turn count, tool name at an
     ordinal), baseline-drift (stored expected vs baseline re-verification), and new-turn
     UNVERIFIED/PASS/WARN.
   - **SKIP (exit 2, rendered UNVERIFIED + named cause):** the baseline cannot be
     re-verified — missing dir, unrestorable pre-state (`BASELINE_UNRESTORABLE`), or
     capability mismatch (`BASELINE_CAPABILITY_MISMATCH`, the cross-substrate corpus
     precedent). Never a false clean, never a false regression.
2. **Comparison target is the STORED expected set** (what the operator banked and
   validated). The baseline is **re-verified in the same run** for three reasons: to prove
   replayability (SKIP gate above), to report **baseline-drift** (recomputed ≠ stored —
   engine-change evidence; named rows, never a failure), and to keep both sides on the
   current engine. `_verify_one_trace`'s ingest seam is NOT reused for the baseline —
   compose both sides through the same `verify` seam aspect 2 used (aspect 2's
   `gate/baseline.py` already contains that composition; reuse it via a shared helper in
   `gate/bank.py` or `gate/baseline.py` rather than duplicating).
3. **One stored policy for both sides.** The baseline's stored invariants, server
   command(s), `replays`, `timeout` apply to the baseline re-verification AND the new
   capture's verification. `gate check` therefore carries **no** `--invariants` /
   `--invariant-library` / `--replays` / `--timeout` flags — the policy is the banked one,
   and an operator who wants a different policy re-banks. `--server` / `--shell-server`
   are **overrides** of the stored boundary (default = stored). This is a deliberate
   divergence from `verify`'s surface; document it in `--help`.
4. **New capture's manifests:** `--manifest-dir`, defaulting to the `<stem>.manifests`
   sibling ONLY when it exists (the aspect-2 precedent), else required.
5. **The pure comparison engine** lives in `src/belay/gate/compare.py`:
   `compare(description, expected, recomputed) -> GateComparison` over plain dicts
   (expected set shape from aspect 2's `baseline.json`; recomputed from the same
   `belay.verify.json` builders). No I/O, no replay — the decision table is unit-tested
   exhaustively, mirroring `corpus/run.py`'s `_divergences` discipline
   (`src/belay/corpus/run.py:289-312`).
6. **Exit contract** (M6): `0` comparison ran, no regression (named abstentions/shape/drift
   may be present) · `1` regression · `2` preflight (missing baseline / no run identity /
   unusable baseline), outcome rendered `UNVERIFIED` + named cause.
7. **Report.** Text + `--json` (`gate.json` schema 1, one computation two renderers):
   run id, baseline drift rows, capture verdicts, divergence rows with expected→got,
   shape rows, coverage line, exit reason. UNVERIFIED never rendered as PASS; coverage
   line on every surface.
8. **No banking yet** (aspect 4), no `--no-ingest` flag yet, no UI/README.

## Implementation phases

### Phase 1 — RED: the comparison decision table

**Files:** create `tests/test_gate_compare.py`.

**Steps:** unit tests over `belay.gate.compare` (does not exist → RED):
1. Regression rows: PASS→FAIL, WARN→FAIL, new-turn FAIL, trajectory PASS→FAIL,
   claim FAIL-when-declared (baseline declared FAIL... define: baseline claim FAIL,
   recomputed FAIL = not a regression; baseline declared claim PASS is impossible — A3;
   the claim row only exists to assert "declared and FAIL on both sides is not a
   regression").
2. Non-failing rows: PASS→UNVERIFIED, WARN→UNVERIFIED, FAIL→FAIL, PASS→WARN, any→PASS,
   UNVERIFIED→FAIL (an abstention becoming a failure is a fix, not a regression — the
   gate cannot call a previously-unchecked turn's FAIL a regression of a passing one),
   new-turn PASS/WARN/UNVERIFIED, shape (turn count, tool rename), baseline-drift rows.
3. SKIP inputs: baseline unreplayable causes → skip_reason, no comparison.
4. `exit_reason`: clean vs regression vs preflight derived correctly from rows.
5. Every row carries the named dimension + expected→got; the empty comparison is clean.

## Testing strategy

- Unit: the full decision table (every transition class, shape, drift, SKIP inputs).
- Integration: real captures clean/regressed (snapshot-less everywhere; snapshot-bearing
  darwin-gated with named cause); preflight paths; JSON pinned contract.
- Compatibility: parity guard, aspect-1/2 suites, corpus roundtrip untouched.

## Environment & secrets

`BELAY_RUN_ID` (existing). `gate check` reads the baseline dir only under the user's
specified root (default `baselines/local/`); nothing leaves the box.

## Edge cases & error handling

- Empty expected set (baseline of a zero-turn trace): shape rows, no regression.
- Turn count shrink (new capture has fewer turns): shape rows; a missing previously-PASS
  turn is reported as a shape change, not a regression (the run did less — the operator
  sees the shape row; verdict-worsening decides, per S4).
- Tool not offered on the new boundary: UNVERIFIED named cause (`TOOL_NOT_OFFERED` etc.),
  never a fail — the `verify-tool-not-offered` discipline.
- Malformed baseline.json: exit 2, named cause; never a silent clean.
- A3 dark on both sides (no claim): claim dimension absent, compared only when declared.
