## 2. Implementation phases

### Phase 1: scaffold + the tail/server core (RED first)

- **Goal:** `console/` scaffolded; the server's trace-list/tail/verify endpoints tested
  (node-side tests, offline, fixture traces); tests fail before the server code exists.
- **Prerequisites:** A1 GREEN (the real `belay verify --json` exists in the worktree
  venv).
- **Files to create:**
  - `console/package.json`, `vite.config.ts`, `tsconfig*.json`, `index.html` — Vite
    vue-ts scaffold; `"test": "vitest run"`, `"build": "vue-tsc -b && vite build"`.
  - `console/src/server/` — the local server (express-free, node `http`):
    - `tail.ts` — append-only file tail (size/offset polling; tolerant of a partial
      final line; emits complete lines only).
    - `trace.ts` — trace → per-turn derivation: frames → `tools/call` correlation
      (mirror `belay.index.tool_calls`, `TRACE_FORMAT.md:425`), decode args/result
      from base64 `raw`, annotations from `annotation_snapshot`, timing.
    - `engine.ts` — subprocess wrapper: `belay verify --json` and
      `belay verify --turn N --json`; resolves the `belay` binary (PATH first,
      `BELAY_CONSOLE_ENGINE` env override for the repo venv case); captures stdout +
      exit code; parseable JSON required, else a named error.
    - `index.ts` — the http server: `GET /api/traces`, `GET /api/trace?path=`,
      `GET /api/feed?path=&cursor=` (tail deltas), `POST /api/verify`, `POST
      /api/replay`; serves the built SPA statically.
  - `console/src/server/*.test.ts` — node-side Vitest: tail append behavior (in-test
    file append, partial line = pending), trace derivation on a **synthetic fixture
    trace** (committed under `console/fixtures/`, built by hand — NOT lifted from real
    captures), engine wrapper against the real CLI (in the dev venv) with the A1 JSON
    shape, error paths (missing binary → named error; bad JSON → named error).
  - `console/fixtures/` — 2–3 small synthetic traces: a clean 2-turn run (one PASS with
    a NOT_COVERED sub-verdict), a FAILed turn (with diff message), an UNVERIFIED turn
    (with cause). Hand-written JSONL per `TRACE_FORMAT.md`.
- **Validation:** `npm run test` — server tests RED first, then GREEN; `uv run pytest
  -q` untouched (no engine change).
- **Commit message:** `feat(console): the server — tail, trace derivation, engine subprocess (tests first)`

### Phase 2: the SPA — feed, trace view, honesty rendering

- **Goal:** the Vue app renders fixture traces with verdicts; the honesty contract is
  asserted by component tests.
- **Prerequisites:** Phase 1 GREEN.
- **Files to create:** `console/src/` SPA components + tests:
  - `App.vue`, `FeedView.vue` (streaming list + live aggregate strip), `TraceView.vue`
    (per-turn list), `TurnRow.vue`, `VerdictBadge.vue` (the honesty surface: distinct
    treatment per status — UNVERIFIED gets its own class/color, never grouped with
    PASS), `CoverageLine.vue` (renders the coverage block; absent coverage → the
    component renders "coverage unavailable", never fabricates), `DiffView.vue` (FAILed
    turn's diff from sub-verdict messages), `ReplayDialog.vue` (server/manifest inputs
    or recorded context; named-cause UNVERIFIED when context is missing),
    `useFeed.ts` (polling the tail endpoint), `useClicks.ts` (click/expand log to
    `~/.belay/console-events.jsonl` via the server `POST /api/events`, injected clock).
  - Component tests (`*.spec.ts`, Vitest + Vue Test Utils + jsdom, offline):
    - **UNVERIFIED renders distinctly from PASS** — snapshot/DOM assertion that the two
      badges differ (the C7 correctness test).
    - every surface renders status + coverage line; a PASS rendered without its
      coverage line fails.
    - NOT_COVERED sub-verdict renders as a coverage boundary, never as PASS.
    - a FAILed turn shows its diff.
    - no-engine state renders "not verified / engine unavailable", distinct from PASS.
    - feed appends turns as the tail advances; a partial line is pending.
    - replay dialog: valid context → engine invoked; missing context → named-cause
      UNVERIFIED.
    - click log: one JSONL record per expand/diff-open.
- **Validation:** `npm run test` green offline; `npm run build` succeeds.
- **Commit message:** `feat(console): the SPA — feed, verdict honesty, diff, replay, click log`

## 4. Testing strategy

- Node-side server tests + component tests, all offline (synthetic fixtures, injected
  clock). The engine wrapper tests use the real CLI in the dev venv — the one place the
  console tests touch the engine, and only to prove the subprocess contract.
- The C7 acceptance tests (spec items 1–8) are the plan's test list, not invented
  parallels.

## 5. Environment & determinism

- No network in tests; injected clock (no `Date.now` in tested code paths); tail logic
  is offset-based, not inotify-dependent (portable).
- Engine binary: PATH first, `BELAY_CONSOLE_ENGINE` override; the server must work
  without the repo venv (a stranger's installed `belay`).

## 6. Edge cases & error handling

- **Partial final JSONL line** → pending, never a verdict (tested).
- **Engine binary absent** → turns render "engine unavailable", distinct from PASS and
  UNVERIFIED (tested).
- **Engine exits non-zero but emitted parseable JSON** (FAIL/UNVERIFIED traces) →
  render the verdicts; exit code is not the error signal (tested).
- **Engine emits unparseable output** → named error rendered, never a guess.
- **Replay without context** (no server/manifest) → named-cause UNVERIFIED (tested).
- **Click log unwritable** → degrade silently in the UI, record the failure once in the
  console's own log (never a crash).
