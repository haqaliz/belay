---

## 1. Two design decisions to make before coding

**D-A · `trace_id` is NOT unique across stages.** A capture's `trace_id` derives from the trace
file stem, so the `s2` and `s3` captures of `pallets__flask-4992` **share the id
`trace-pallets__flask-4992`** while being different captures with different turn counts (17 vs
20). Therefore:

- a **capture** is identified by `(ledger_label, trace_id)`;
- an **instance** is identified by `trace_id`;
- every input ledger must carry a **label** (its stage: `s1`, `s2`, `s3`…), supplied by the
  caller. Without labels the population silently collapses two real observations into one.

**D-B · Do NOT synthesize a merged `InstanceRecord`.** Collapsing two captures into one record
would have to merge `turn_status_counts`, and summing them makes `total_turns()` and the per-turn
FAIL rate meaningless (they would count the same instance's turns twice while the instance
counts once). Instead keep the capture-level records as the ground truth and compute an
**instance-level view** over them:

- per-**turn** statistics stay over **captures** (all 397 turns actually verified);
- per-**instance** statistics come from the view (violating iff **any** capture flagged;
  in-denominator iff **any** capture is CLEAN or FLAGGED — a capture that ERRORED is not evidence
  of a violation, spec open question).

## 2. Phases

### Phase 1 — Detector identity on the ledger (M-2)

**Goal:** a ledger states what produced it; one that doesn't says `unrecorded`.

**RED — `tests/test_phase0_ledger.py`, then `tests/test_phase0_cli.py`:**
- `test_detector_identity_round_trips` — rules+scopes survive `to_json`/`from_json` exactly.
- `test_ledger_without_detector_loads_as_unrecorded` — a dict shaped like `runs/s2.json` (nine
  fields, **no** detector key) loads, and the identity reads as unrecorded. **Fail-closed is
  wrong here** and the test must say so: an absent field means "predates the field", exactly like
  `not_covered_turns` (`ledger.py:57-63`), not "corrupt ledger".
- `test_unrecorded_detector_is_not_rendered_as_current` — the report for a detector-less ledger
  contains `unrecorded` and does **not** name any rule.
- `test_report_states_the_detector_when_recorded` — when present, the rules and scopes appear.

**GREEN:**
1. `ledger.py`: a frozen `DetectorIdentity` dataclass — `rules: tuple[tuple[str, str], ...]`
   (scope, rule) plus `version: str | None`. Add `detector: DetectorIdentity | None = None` to
   `RunLedger`. Serialize under key `"detector"`; **omit the key entirely when `None`** so
   existing ledgers round-trip unchanged. Deserialize absent ⇒ `None`. Follow the
   `_DEFAULT_NOT_COVERED` comment style, and say in the docstring why absent ≠ error.
   **The library must not read git, env, or a clock** — `version` is caller-injected.
2. `report.py`: render a detector line; `None` ⇒ the literal word `unrecorded` with a short
   clause that the run's detector was not recorded and the result must not be assumed current.
3. `cli.py` (`_cmd_phase0_run`): build the identity from the invariants already in force at
   `:1202` (`default_invariants()` / `--invariants`), pass it into the ledger.

**Validation:** `uv run pytest tests/test_phase0_ledger.py tests/test_phase0_cli.py -q`; full suite.
**Commit:** `ledger-reporting-honesty: a ledger says which detector produced it, or says unrecorded`

### Phase 2 — Population: merge, dedup, both denominators (M-3)

**Goal:** N labeled ledgers become one population with an auditable dedup rule.

**RED — new `tests/test_phase0_population.py`:**
- `test_same_instance_across_stages_counts_once` — two ledgers, same `trace_id`, different
  labels ⇒ instance denominator counts it **once** while the capture count is **two**. (A naive
  concat double-counts; that is the failure being pinned.)
- `test_worst_verdict_wins_across_captures` — CLEAN in one capture, FLAGGED in another ⇒ the
  instance is violating.
- `test_errored_capture_is_not_evidence_of_violation` — ERRORED + CLEAN ⇒ in the denominator,
  **not** violating. ERRORED alone ⇒ **out** of the denominator.
- `test_disagreeing_instances_are_named` — the report names the instance and both outcomes.
- `test_both_denominators_are_reported` — instances (headline) and captures (alongside), each
  labeled with what it counts.
- `test_merge_is_order_independent` — merging in either order yields equal aggregates.
- `test_capture_identity_uses_label_and_trace_id` — two captures sharing a `trace_id` under
  different labels remain **two** captures (D-A). Without this the population silently loses one.

**GREEN — new `src/belay/phase0/population.py`:**
- `LabeledLedger(label: str, ledger: RunLedger)`.
- `Population.from_labeled(ledgers)` holding capture-level records keyed `(label, trace_id)`.
- Methods: `capture_count()`, `instance_count()`, `instance_denominator()`,
  `violating_instances()`, `disagreements()` (instances whose captures differ on the violation
  question, with each capture's outcome), plus per-turn totals delegated to the captures.
- Pure functions over data; **no I/O, no clock, no network**.
- `report.py`: `render_population_report(population)` — headline over instances, capture line
  alongside, disagreements named. Reuse the existing `n/a`-on-zero-denominator discipline
  (`report.py:36-44`); never print a bare 0% or 100% for an empty denominator.
- `cli.py`: new subcommand `belay phase0 combine LABEL=PATH [LABEL=PATH ...]`. A repeated label
  or a malformed `LABEL=PATH` pair is a named error, never a silent skip. **Do not change
  `phase0 report`'s single-ledger contract.**

**Validation:** `uv run pytest tests/test_phase0_population.py -q`; full suite.
**Commit:** `ledger-reporting-honesty: one population from many stages, dedup rule stated`

### Phase 3 — Controls partitioned (M-4)

**Goal:** controls out of the headline, and a FAILing control means the right thing *here*.

**RED — `tests/test_phase0_population.py` + `tests/test_phase0_report.py`:**
- `test_controls_excluded_from_headline_rate` — a `control__*` instance changes neither the
  headline numerator nor its denominator.
- `test_controls_reported_in_their_own_block` — listed with their own counts, and the ids treated
  as controls are named.
- `test_failing_control_is_reported_as_detector_false_positive` — the output labels it a detector
  **false positive** and explicitly states this is **not** a mint-void condition in a
  re-verification. (Void belongs to a fresh mint; conflating them fabricates a void.)
- `test_population_without_controls_says_so` — an explicit "no controls in this population" line,
  never silence.

**GREEN:**
- `population.py`: `_CONTROL_PREFIX = "control__"` with a comment that this is a **convention**
  shared with `eval/instances/controls.py` and deliberately **duplicated, not imported** —
  `src/belay/` must not depend on `eval/`. Partition captures into controls and instances.
- `report.py`: the controls block, including the false-positive-not-void wording.

**Validation:** full suite; expect ~1225 passed.
**Commit:** `ledger-reporting-honesty: a control is not an instance, and a FAILing control is not a void`

## 4. Testing Strategy

Unit-level and deterministic throughout; no Seatbelt, no darwin gate, no network, no replay —
every test builds `InstanceRecord`/`RunLedger` values directly. Criterion 13 (nothing existing
changes) is carried by the pre-existing `phase0` suites staying green **unmodified**; if one
needs editing, that is a real finding to report, not a fix to make.

---

## 5. Edge Cases & Error Handling

| Case | Behaviour |
|---|---|
| Ledger with no `detector` key | loads; renders `unrecorded`; **never** assumed current |
| Two captures, same `trace_id`, same label | a named error — that is a duplicate input, not two observations |
| Instance ERRORED in every capture | out of the instance denominator, shown in the disposition breakdown |
| Instance CLEAN in one capture, FLAGGED in another | violating (worst-wins), **and named** in disagreements |
| Zero instances after partition (all controls) | `n/a`, never 0% or 100% |
| No controls present | explicit "no controls in this population" |
| Malformed `LABEL=PATH` | named error, never a silent skip |

No verdict changes on any axis. `UNVERIFIED` and `NOT_COVERED` handling is untouched.
