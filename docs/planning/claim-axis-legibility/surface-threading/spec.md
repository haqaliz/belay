# surface-threading — spec

PRD: `../prd.md` (M4, M6, M7, S2, N1). Depends on `author-abstention` (the `expected`
keys) and `silence-record` (the e2e asserts both).

## Problem slice

The sub-cause exists on the verdict but every serializer copies named keys only
(`claim_record` `json.py:273-303`, `_claim_summary` `runner.py:638-660`, `claim_case`
`claims.py:476-520`), and the text renderers print `[cause]` only. Outcome: the
sub-cause reaches every surface that shows the cause, additively, and nothing a verdict
reader relies on moves.

## In scope

- `claim_record`, `_claim_summary`, `claim_case`: add `"sub_cause"` and
  `"sub_cause_detail"` **only when** `expected` carries `sub_cause`.
- `cli.py:_emit_claim`: `UNVERIFIED [NO_CHECK_AUTHOR/AUTHOR_TIMED_OUT] — never PASS`, plus
  `      ({detail})` on the next line when the detail is non-empty.
- `phase0/report.py:_claim_line`: the same `cause/sub_cause` token; the aggregate's
  by-cause note is **unchanged** (it groups on `cause`).
- `corpus`: `_validate_claim` accepts optional `sub_cause: str|None` and
  `sub_cause_detail: str|None` (type-checked if present); `corpus run` recompute
  **ignores** them (status-only contract, `corpus/run.py:671-724`); `corpus show` prints
  the sub-cause when present. **No schema bump** (PRD §5).
- Committed-ledger pin (S2) and real-CLI e2e (M7).
- N1: annotate `claim-re-derivation-a3/prd.md:120` (`CHECK_TIMED_OUT` → folded into
  `CHECK_DID_NOT_EXECUTE`), quoting what it replaces.

## Acceptance criteria (tests written first)

1. `claim_record` / `_claim_summary` / `claim_case` on a `NO_CHECK_AUTHOR` verdict with
   sub-cause → the two keys present; on FAIL, on every other UNVERIFIED cause, and on a
   `NO_CHECK_AUTHOR` verdict **without** a sub-cause (an old corpus case / ledger) → dict
   equal to today's shape exactly (the existing `==` pin at
   `test_verify_claim_surfaces.py:360` passes unmodified).
   **[Corrected 2026-09-25, during implementation — "passes unmodified" held only for
   the FAIL pin.]** The FAIL-record `==` pin (`test_verify_json_carries_the_a3_record_after_trajectory`)
   is unmodified. Two exact-record pins on `NO_CHECK_AUTHOR` records went red, because
   `author-abstention` gives every such verdict a sub-cause, and were amended
   **additively** (the two keys added, still exact equality), with the team lead's
   approval, per PRD M4: `test_verify_claim_surfaces.py::test_verify_renders_a3_unverified_with_its_named_cause`
   and `test_phase0_claim.py::test_claim_unverified_never_flags_the_instance`.
2. `verify` text and `phase0 report` render `[NO_CHECK_AUTHOR/<SUB>]` and still end
   `— never PASS`; a record without a sub-cause renders byte-identically to today.
3. Corpus: a v5 case with `sub_cause` round-trips byte-identically; a case with
   `sub_cause: 3` is rejected with a named error; `corpus run` outcome for a stored
   `UNVERIFIED/NO_CHECK_AUTHOR/AUTHOR_TIMED_OUT` case recomputing to
   `NO_CHECK_AUTHOR/AUTHOR_EXITED_NONZERO` is `MATCH` (sub-cause never decides);
   `CASE_SCHEMA_VERSION` is still 5.
4. `gate check` on a baseline with a sub-caused claim vs one without → no divergence row
   (compare is status-only; pinned).
5. **Committed-ledger pin (S2):** `belay phase0 report` over each of the 4
   `docs/planning/phase0-corpus-mint/mint-run/ledgers/cm-*.json` produces output equal to
   a golden captured from `origin/master` (`1ada903`) **with exactly one permitted
   substitution** — the `_CLAIM_UNRECORDED_SENTENCE` old→new text (`silence-record` AC 6).
   Goldens are generated by a script committed alongside and are never hand-edited.
   **[Finding, 2026-09-25, Phase 0]** the four `cm-*.json` ledgers carry **0 claim-less
   instances** (all 16 instances carry a `claim`, every one UNVERIFIED), so this pin
   **cannot observe** the `_CLAIM_UNRECORDED_SENTENCE` change — the substitution never
   fires on them; that change is pinned by `tests/test_claim_silence.py` instead. S2's
   value is that the 2 `NO_CHECK_AUTHOR` lines in `cm-run3-stage2` re-render unchanged,
   because an old ledger carries no `sub_cause`.
6. **Real-CLI e2e (M7, darwin-gated like every capture test):** on the committed demo
   capture, `belay verify --json --claim-author <stub>` for five stub authors (python
   scripts under `tests/fixtures/claim_authors/`): exit 1 + named stderr →
   `AUTHOR_EXITED_NONZERO` with the stderr line in `sub_cause_detail`; sleep past a
   monkeypatched `AUTHOR_TIMEOUT` → `AUTHOR_TIMED_OUT`; malformed → `…MALFORMED`; `{"error"}`
   → `…REPORTED_ERROR`; valid exit-0 check → `claim_silence` present, `claim` absent.
   **In all five, `turns`, `aggregate`, `trajectory`, and the exit code equal the
   no-author run.** Cost control: one no-author baseline shared by a module fixture;
   the four abstaining stubs never reach the check runner.
7. **No published number moves:** a grep-free check — `git diff 1ada903 -- docs/` touches
   no line containing `18.3%`, `precision 0.00`, `1/15`, `4/16`, `recall 0.00`, `3/93`
   (verified at the end, recorded in the PR; the measurement-traps rule: an occurrence
   count is not proof).

## Risks

~6 min, share one replay via `--turn`-free runs with the stubs selected by a single
`BELAY_CLAIM_AUTHOR` swap per run — **ask before cutting a stub**, never drop one silently.
