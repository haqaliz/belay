## 2. Phases

### Phase 1 — Stage 1: the probe instance (1 control)

- **Goal:** prove the instrument on a control before any real spend; gate Rule A row 1.
- **Files:** `mint-run/acceptance-stage1.sh` (NEW, agent-drafted, **contains no result**),
  `mint-run/acceptance-stage1.out` (NEW, committed after the run), `mint-run/ledgers/s4a.json`
  (NEW, copied), `mint-run/STAGE4A_FINDINGS.md` (NEW).
- **Freeze commit (main thread, before the run):** `mint(stage1): the invocation, frozen before it has been run`
  ```
  # acceptance-stage1.sh
  set -euo pipefail
  export BELAY_EVAL_SERVER_ROOT="${BELAY_EVAL_SERVER_ROOT:-$PWD/eval/servers}"
  uv run python -m eval.minting_driver one control__flask-read-only \
    --root eval/mint/s4a --registry eval/instances/stage4a.json \
    --provider claude-cli --model claude-opus-5 --max-steps 20
  ```
- **Run once (main thread):** `bash mint-run/acceptance-stage1.sh | tee mint-run/acceptance-stage1.out`
- **Verify:** `mkdir -p runs && uv run belay phase0 run eval/mint/s4a/batch --ledger runs/s4a.json
  --corpus-dir corpus/local --server node eval/servers/node_modules/@modelcontextprotocol/
  server-filesystem/dist/index.js '{workspace}'`; copy ledger; `belay phase0 report` output
  appended to the findings note.
- **Gate (Rule A row 1):** capture exists AND ≥1 genuinely verifiable turn AND control
  `VERIFIED_CLEAN`. Fail → **STOP**; name the reason; fix before stage 2. `INSTRUMENT SUSPECT`
  → wiring failure, STOP.
- **Result commit (verbatim, whatever it says):** `mint(stage1): the measurement, verbatim, run once`
- **Validation:** the committed `.out` is raw stdout; the ledger re-renders the same headline.

### Phase 2 — Stage 2: 3 controls + 7 real (10)

- **Goal:** the attrition + exposure probe; gate Rule A row 2.
- **Files:** `mint-run/acceptance-stage2.sh` / `acceptance-stage2.out`, `mint-run/ledgers/s4b.json`,
  `mint-run/STAGE4B_FINDINGS.md` (same pattern; `--root eval/mint/s4b --registry eval/instances/stage4.json`).
- **Freeze commit (before the run; pins `stage4.json`):** `mint(stage2): the invocation, frozen before it has been run`

  STOP and re-scope the population per PRD Rule A).
- **Result commit:** `mint(stage2): the measurement, verbatim, run once`

### Phase 3 — Stage 3: the full 68 (`selected.json`)

- **Goal:** the gate denominator; Rule A row 3 (no abort except the quota breaker).
- **Files:** `mint-run/acceptance-stage3.sh` / `acceptance-stage3.out`, `mint-run/ledgers/s4c.json`,
  `mint-run/STAGE4C_FINDINGS.md` (`--root eval/mint/s4c --registry eval/instances/selected.json`).
- **Freeze commit (before the run):** `mint(stage3): the invocation, frozen before it has been run`
- **Run once, resumable:** if the quota breaker stops the batch, record the verbatim stop,
  wait out the cap, **resume with the identical command on the same root** (declared as a

- **Verify + gate:** `belay phase0 run` over `eval/mint/s4c/batch`; copy ledger; report.
  Every UNVERIFIED instance to a named cause; `INSTRUMENT SUSPECT` → STOP.
- **Result commit:** `mint(stage3): the measurement, verbatim, run once`

## 3. Edge cases (each pre-decided; see spec)

| Case | Handling |
|---|---|
| Quota stop | S-7 resume; the limit shape is a finding (R-4), recorded verbatim |
| Unrecognised error | `terminal` → `failed`, skipped, never re-driven |
| Stage-2 exposure gate fires | STOP; write the re-scope decision; stage 3 does not launch |
| Control FAIL | Mint **void**; record, hand-replay (next aspect), publish as a detector finding |
| `INSTRUMENT SUSPECT` | Wiring failure, never a result; STOP and fix |
| `MissingServerError` / clone failure | Setup failure; fix and re-run the stage (anti-re-roll applies to results, not to runs that never happened) |
| macOS TCC prompt | Record it; the sibling-dir layout is designed to avoid it |
| Node/server drift | Pins re-checked only if install fails; the code-pinned versions win over the README's stale "re-run npm view" note |

## 4. Agent execution notes

- **Agents draft** the three `acceptance-stageN.sh` files (they contain no results by
  construction) and the `SUMMARY.md` template. **The main thread commits each freeze, runs
  each stage once, and commits each `.out` verbatim.** A drafted `acceptance.sh` that embeds
  an expected result is a defect — the script must contain only the invocation, env, and
  protocol prose.
- Checkpoints: after each stage's result commit, the gate decides whether the next stage
  launches. The owner is present at every checkpoint.
- The `belay phase0 run` command line is identical in shape across stages — only the batch
  dir and ledger name differ; it must not gain a `--` separator (`nargs=REMAINDER`).
