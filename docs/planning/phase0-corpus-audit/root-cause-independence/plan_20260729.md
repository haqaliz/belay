### Phase 1 — `Case.root_cause` and `Case.target_tool`

**Goal.** Both fields exist, round-trip, validate fail-closed, and are **omitted from `case.json`
when absent**.

**Prerequisites.** None.

**Files.**
- `src/belay/corpus/case.py` — modify
- `tests/test_corpus_case.py` — modify (add the RED tests first)

**The design decisions, restated so the implementing agent does not re-litigate them:**

- `root_cause` shape is `{"key": str, "note": str}`. `key` must match `^[a-z0-9]+(-[a-z0-9]+)*$`.
- **Absent means the key is not written at all.** `_to_payload` must build the dict and then omit
  `root_cause`/`target_tool` when `None` — *not* write `null`. Rationale: *"a default is never a
  declaration"*; absent must stay distinguishable from declared-empty.
- Neither field goes in `_REQUIRED_FIELDS`. That tuple is closed and fail-closed, and adding to it
  would reject all 7 banked cases — the exact reasoning `case.py:64-69` already records for
  `schema_version`.
- Both are dataclass fields with `= None` defaults, placed **after** `schema_version` so every
  existing positional constructor call keeps working.

**RED tests to write first** (spec acceptance 1–6):

```python

    # assert "root_cause" not in json.loads(...) -- NOT `is None`
def test_case_without_either_new_field_still_loads(tmp_path):
    # the 7 banked cases' shape; both read back None
def test_root_cause_bare_string_is_rejected(tmp_path): ...
def test_root_cause_missing_key_is_rejected(tmp_path): ...
def test_root_cause_non_kebab_key_is_rejected(tmp_path): ...

```

**Validation.** `uv run pytest tests/test_corpus_case.py -q` green; full suite green.

**Commit.** `case: an optional root cause and target tool, absent-never-guessed`

### Phase 2 — `set_label` requires a root cause for a true-positive

**Goal.** A TP the gate could not evaluate cannot be written; an existing root cause survives
relabeling.

**Prerequisites.** Phase 1.

**Files.**
- `src/belay/corpus/curate.py` — modify (`set_label` gains `root_cause: dict | None = None`)
- `src/belay/cli.py` — modify (`corpus label` gains `--root-cause-key` / `--root-cause-note`)
- `tests/test_corpus_label.py` — modify

**The hazard this phase exists to close.** `set_label` is `load_case → dataclasses.replace →
write_case` (`curate.py:50-52`), and `write_case` serializes a fixed key set. Acceptance 10 is the
test that catches a root cause being silently erased by a later relabel. **Write it first and
watch it fail.**

**Ordering requirement.** Validation happens **before** any disk write — mirroring the existing
`ADJUDICATIONS` check at `curate.py:42-47`, whose docstring already promises "rejects ... before
touching disk". Acceptance 7 asserts `case.json` is byte-identical after a rejected call.

**CLI surface.** Two flags rather than one parsed string, so the key stays machine-clean and the
note stays free:

```
belay corpus label CASE --label true-positive \
  --root-cause-key required-test-update \
  --root-cause-note "upstream 7c526140 deletes the same test"
```

`--root-cause-note` without `--root-cause-key` is an error; a key alone is allowed (empty note).

**RED tests first** (acceptance 7–12).

**Validation.** `uv run pytest tests/test_corpus_label.py -q`; full suite green.

**Commit.** `curate: a true-positive without a root cause is not a recordable finding`

### Phase 3 — independence counts in `score()`

**Goal.** `Metrics` carries both independent counts, computed purely.

**Prerequisites.** Phase 1.

**Files.**
- `src/belay/corpus/metrics.py` — modify
- `tests/test_corpus_metrics.py` — modify

**New `Metrics` fields.**
```python
independent_tp: int            # distinct root_cause["key"] among TPs
independent_tp_strict: Optional[int]  # None == n/a (a TP lacks target_tool)
```

**The strict rule, precisely** — implement the pre-registered *gloss*, not the permissive reading:

> A set of TPs is one finding unless they differ in **both** instance and tool. Concretely: group
> TPs by `(instance, tool)`; the strict count is the number of groups **only if** both dimensions
> actually vary across the corpus — if every TP shares one tool, the strict count is **1**
> (or 0 when there are no TPs).

Instance derives from `provenance["source_trace_id"]`; tool from `target_tool`. A TP with no
`target_tool` makes the strict count `None` → rendered `n/a`, **never 0 and never a guess**.

**Do not** derive a root cause from any engine-computed field. That would make independence a
function of the engine's own output — the label-trap (`metrics.py:11-23`) one level up.

**Guard the modal outcome.** Acceptance 16: zero TPs with FP>0 must yield `precision == 0.0`, a
real number. `_ratio` already returns `0/7 = 0.0` correctly; the test pins it so a later
refactor cannot turn the headline finding into `n/a`.

**RED tests first** (acceptance 13–18), each asserting a hand-computed value with the rule named
in its docstring.

**Validation.** `uv run pytest tests/test_corpus_metrics.py -q`; full suite green.

**Commit.** `metrics: count independent findings, and name which rule counted them`

### Phase 4 — rendering: `score`, `show`, `list`

**Goal.** The counts and fields are visible, with the grouping rule named beside them.

**Prerequisites.** Phases 2 and 3.

**Files.**
- `src/belay/cli.py` — modify (`_cmd_corpus_score`, `_cmd_corpus_show`, `_cmd_corpus_list`)
- the CLI test module(s) — modify

**Output shape.**
```
  TP                        3
  TP (independent)          2   [distinct root-cause keys]
  TP (independent, strict)  1   [distinct instance+tool; one tool across corpus]
```

The bracketed rule is **not decoration** — it is the same discipline as the coverage line
travelling with a `PASS`. A count whose grouping rule is invisible invites quoting the flattering
number. When strict is `None`, print `n/a` with its reason.

`corpus show` renders `root_cause.key`, `root_cause.note` and `target_tool`; absent fields render
as absent, never as empty strings (acceptance 20). `corpus list` gains a root-cause-key column.

**Validation.** Full suite green; eyeball `uv run belay corpus score` against the real corpus.

**Commit.** `cli: the independent count travels with the rule that produced it`

## Edge cases & error handling

| Case | Behaviour |
|---|---|
| `root_cause` absent | Field is `None`; key **omitted** from `case.json`. Not an error. |
| `root_cause` malformed | Named `ValueError` (bare string / missing `key` / non-kebab key / non-dict). |
| `true-positive` with no root cause | `ValueError` before any disk write; `case.json` byte-identical. |
| Relabel a case that has a root cause | Root cause **preserved** — the erasure hazard. |
| TP lacks `target_tool` | Strict count is `None` → `n/a` **with its reason**, never 0, never a guess. |
| No TPs at all | Both counts `0`; `precision` is `0.0` when FP>0, `None` only when TP+FP==0. |
| Empty corpus | Unchanged: all-`n/a`, never a vacuous 1.0. |

No new `UNVERIFIED` path arises — this aspect introduces no check. The honesty burden is carried
by absent-never-guessed and by the strict count's explicit `n/a`.
