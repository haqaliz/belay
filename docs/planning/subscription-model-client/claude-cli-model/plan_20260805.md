## 1. Design, fixed before any code

### The class

`eval/minting_driver/clients/claude_cli_client.py`

```python
PROVIDER_NAME = "claude-cli"
DEFAULT_CLAUDE_CLI_MODEL = "claude-opus-5"   # full id, never an alias (criterion 20)
DEFAULT_TIMEOUT_SECONDS  = 600.0             # the client owns the bound; --max-turns does not

class ClaudeCliModel:
    def __init__(self, *, model: str, tools: list[dict],
                 runner: Optional[Callable[..., Any]] = None,
                 binary: str = "claude",
                 timeout: float = DEFAULT_TIMEOUT_SECONDS) -> None: ...
    @property
    def provider(self) -> str: ...      # PROVIDER_NAME
    @property
    def model(self) -> str: ...         # read off the object that made the calls
    @property
    def request_count(self) -> int: ... # incremented BEFORE the call
    @property
    def usage(self) -> Optional[dict[str, int]]: ...  # None until reported
    def propose_next(self, messages: list[Message]) -> ToolCall | Done: ...
```

**The seam is `runner`, not `client`.** The boundary is a subprocess, so the injected object is a
callable with `subprocess.run`'s shape, returning something exposing `.returncode`, `.stdout`,
`.stderr`. Default is `subprocess.run`. **Every offline test drives this seam** — no `claude`
binary, no network, no subscription.

> `make_model_factory` passes its test seam as `client=`. Map it: when `client is not None`, pass
> it through as `runner=`. Do **not** rename the factory's parameter — that is a shared surface and
> `test_minting_driver_entrypoints.py` pins it.

### The argv (criteria 8, 9, 14, 15, 16)

```
<binary> -p <prompt>
  --output-format json
  --model <model>              # explicit, always; never an alias, never omitted
  --tools ""                   # allowlist emptied — no built-in tool is granted
  --strict-mcp-config          # do not inherit the operator's MCP servers (R6 hole)
  --no-session-persistence     # ~800 session files across a full mint otherwise
```

**Never** `--bare` (breaks OAuth), **never** `--max-turns` (no-op), **never**
`--dangerously-skip-permissions`, **never** `--add-dir`.

### The env (criterion 13 — the load-bearing one)

Start from `os.environ`, then **remove**:

| Var | Why |
|---|---|
| `ANTHROPIC_API_KEY` | **It is set on this operator's box.** A leak bills a metered key on a run that looks identical and succeeds — the exact failure this aspect exists to prevent |
| `ANTHROPIC_AUTH_TOKEN` | Same precedence slot: it **also** shadows the OAuth profile, so scrubbing only the API key is insufficient |
| `ANTHROPIC_BASE_URL` | Could silently redirect the oracle at a proxy, making the published run non-reproducible |

Scrub by **absence**, never by setting `""` — an empty string still occupies its precedence slot
and authenticates as an empty credential. Assert on the **constructed env dict**, not the argv.

### The prompt, and the open `--system-prompt` question

`claude -p` takes **one prompt string**, so unlike the SDK clients there is no native message
array: the whole conversation is re-serialized every turn. Layout:

1. the task/system message (`role == "system"`, sent once by `loop.py`, first);
2. the MCP tool schemas as JSON — **data in the prompt**, the entire basis of Option B;
3. the conversation so far (`user` / `assistant` / `tool` turns, with tool results labelled);
4. the response contract: *reply with ONLY* `{"kind":"tool_call","name":…,"arguments":{…}}`
   *or* `{"kind":"done","reason":…}`.

**Open — decide in Phase 1 and record the decision in the module docstring.** P0 measured
**24,099 cache-creation tokens** for a trivial prompt: that is Claude Code's own system prompt
riding along on every call. Passing our own `--system-prompt` would replace it, cutting per-call
cost substantially across a 68 × ≤12 mint, and would make the oracle independent of Claude Code's
prompt version — a reproducibility win. **Risk:** it is unprobed, and it changes the oracle's
behaviour, which is the thing under test. **Recommendation: probe it once in Phase 1** (one live
call, compare `cache_creation_input_tokens` and that a tool call still parses). If it regresses
parsing, drop it and say so.

### The envelope contract (criteria 1–4, 17–19)

Parse `stdout` as JSON, then **in this order**:

1. `is_error is True` **or** `subtype != "success"` → raise `ClaudeCliInvocationError`.
2. `permission_denials` non-empty → raise `ClaudeCliToolAttemptError`. Under `--tools ""` this
   should be impossible; treat it as an **instrument fault**, never discard it (criterion 19).
3. Fold `usage` into the running total — **absent-never-zero** (criterion 18).
4. **Never read `total_cost_usd`** (criterion 17).
5. Extract the JSON object from `result`, tolerating prose around it. `kind == "tool_call"` →
   validate `name` against the supplied schemas (criterion 4) → `ToolCall`;
   `kind == "done"` → `Done`. Anything else → `ClaudeCliParseError` (criterion 3).

**Never fabricate a `Done`.** A `Done` is returned only when the model explicitly says so.

  - `--model` present with the **exact** id passed; constructing without a model is an error.

  - The constructed env has **no** `ANTHROPIC_API_KEY`, `ANTHROPIC_AUTH_TOKEN`, `ANTHROPIC_BASE_URL`

### Phase 2 — Envelope parsing

- **Goal:** one envelope → one `ToolCall | Done`, or a named error.
- **Prereqs:** Phase 1.
- **Criteria:** 1, 2, 3, 4, 17, 18, 19.
- **Tests (write first):** well-formed tool call → `ToolCall`; completion → `Done`; unparseable →
  named error (**never** a fabricated `Done`); unknown tool name → error; `is_error: true` → error;

### Phase 3 — Prompt construction and cross-turn threading

### Phase 4 — Error classification

## 4. Testing strategy

- **All offline.** No `claude` binary, no network, no subscription, no API key. The `runner` seam
  is the only boundary and it is always faked.
- **Deterministic.** No clock, no randomness, no network, no ordering dependence. `request_count`
  is asserted by sequence, not by timing.
- **Lift the criteria, don't invent parallel ones.** Spec criteria 1–20 map to phases 1–6 above;
  each test names the criterion it covers in its docstring.
- **Commands:** per-phase `uv run pytest tests/test_minting_driver_claude_cli.py -q`; full
  `uv run pytest` at Phase 6.
- **Manual verification is out of scope here** — the live run is `live-smoke-confirmation`.

## 5. Environment & determinism

- No new env vars, no new dependencies, **no `uv add`**. The client is stdlib-only, which is why
  the zero-runtime-dependency contract holds trivially.
- `BELAY_EVAL_LIVE` and the `manual` marker gate the live path only; nothing in this aspect runs it.
- **Determinism note:** the child env is derived from `os.environ` **minus** the scrubbed keys, so
  a test must monkeypatch the environment rather than depend on the developer's. A test that
  passes only because the developer has no `ANTHROPIC_API_KEY` set is a bug in the test.

## 6. Edge cases & error handling

| Case | Behaviour |
|---|---|
| `claude` binary missing | `FileNotFoundError` → `classify_error` → **`terminal`** |
| Non-zero exit | named error → `terminal` (unless the message is recognisably a quota shape) |
| Timeout | `subprocess.TimeoutExpired` → **`transient`** (it is a `TimeoutError` subclass — `resilience.py` rule 5) |
| `stdout` not JSON | `ClaudeCliParseError` → `terminal`. **Never** a `Done` |
| `result` has prose around the JSON | tolerated — extract the object |
| `result` has no JSON object | `ClaudeCliParseError`. **Never** a `Done` |
| Tool name not in schemas | `ClaudeCliUnknownToolError`. Never passed through to `loop.py` |
| >1 tool call in one reply | take the first + `warnings.warn`, mirroring `anthropic_client.py:270-277`. **Never** a queue |
| `permission_denials` non-empty | `ClaudeCliToolAttemptError` — an instrument fault, not a model verdict |
| Subscription usage limit | `quota` where recognisable, **`terminal`** where not. **Never `transient`** |
| `usage` absent | `usage is None`. **Never** `{}` and never `0` |

**Verdict impact: none.** This aspect is `eval/`-only and computes no verdict on any axis, so there
is no `UNVERIFIED` path to define here. The verdicts come later, from the stock
`belay phase0 run` over whatever the mint captures.

## 7. Agent execution notes

- **Checkpoint after Phase 1.** The argv/env surface is the whole R6/R7 and no-metered-key
  guarantee. Have a human read those tests before anything is built on top of them — a weakened
  assertion here weakens the mint's verifiability claim silently.
- **Checkpoint after Phase 5**, before Phase 6: `entrypoint.py` is shared with two working
  providers and is covered by a 59 KB test file. A regression there breaks the existing mint path.
- **Likely to need iteration:** prompt construction (Phase 3). There is no native message array, so
  the serialization is a judgement call. Keep it boring and readable; the live smoke is what
  actually tests it.
- **Ask before proceeding if:** any phase appears to need a change to `loop.py`, `batch.py`, or
  anything under `src/belay/`. That is the signal the design has drifted — Option A is the failure
  mode, and it is forbidden (PRD §3).
- **Do not** add retry logic to the client. `RetryingModel` owns retries at the factory boundary,
  and it structurally cannot retry a `tools/call` — a property that must not be given up.
