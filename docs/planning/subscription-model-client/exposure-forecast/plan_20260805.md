## 1. Design

**Deliverable:** `eval/scripts/forecast_exposure.py` — a standalone, offline, stdlib-only script
(matching `eval/scripts/rearm_checkpoint.py`'s register), plus tests.

**Frozen token set** (committed in the script as a module constant, and printed in the output):

```
test, tests, testing, pytest, assert, assertion, failing, traceback, reproduc
```

matched **case-insensitively on word-prefix** against each instance's `problem_statement` **and**,
reported separately, its `task_string`.

**Output sections, each with denominators:**

1. **Pool (166)** — headline: *N of 166 problem statements mention …*, per repo.
2. **Launched (68)** — the same, reported **separately and never averaged with the pool.** The draw
   deliberately rebalanced composition (pool: django 82 / sympy 56; launched: django 19 / sympy 18),
   so a combined figure is a category error.
3. **Controls (3)** — partitioned out of both headlines, following the `phase0 combine` precedent.
4. **`problem_statement` vs `task_string`** — separately, so a reader can see which field carries
   the signal.
5. **Surface floor** — one line per repo confirming an in-scope path segment exists at all.
   **Expected 7/7. Recorded as a floor, never presented as a finding** — this is the residue of the
   design that was discarded, kept only so the output cannot be read as claiming no surface exists.
6. **Calibration against v0.12.0's measured exposure**, per repo, labelled **calibration, never
   validation** (n=15 across 5 repos).
7. **The honesty paragraph** (criterion 8), in the output's own text: it measures a property of the
   **task description**, not agent behaviour; it **under-counts by construction** — `flask` scores
   **0/1** yet `flask-4992` wrote to a test file **four times**, because *adding* a test is normal
   correct behaviour a statement never has to mention; and it is **not comparable** to the 17
   judgments, which counted observed writes by a specific model on a different population.
8. **`unknown` count** — instances with a missing or empty `problem_statement`. **Absent is not
   zero** (criterion 7).

## 2. Phases

### Phase 1 — The script and its tests (contains no result)

- **Files:** `eval/scripts/forecast_exposure.py` (NEW), `tests/test_forecast_exposure.py` (NEW).
- **TDD.** Tests first, against **small synthetic fixtures**, not against the real 166 — a test
  that asserts `59` would have to change whenever the pool does, and would be asserting the answer
  rather than the arithmetic.
- **Tests required:**
  - deterministic: same input → byte-identical output (run twice, compare);
  - every reported figure carries a denominator (assert the rendered text, not just the numbers);
  - pool and launched are reported **separately** — a fixture where they differ, asserting both
    appear and neither is an average of the other;
  - controls partitioned out of the headline;
  - a missing/empty `problem_statement` renders **`unknown`**, never `0` (criterion 7);
  - the token set is read from the module constant, so a test can prove the output states it
    (criterion 6);
  - the honesty paragraph is present and names `flask-4992` (criterion 8);
  - **no network, no clock, no randomness** — assert by construction (no `import requests`, no
    `datetime.now()` in the module) in the spirit of `tests/test_verify_zero_llm.py`'s import guard.
- **Commit:** `forecast: the tooling, before it has an answer`

### Phase 2 — Run it once, commit verbatim

- `uv run python eval/scripts/forecast_exposure.py > docs/planning/subscription-model-client/exposure-forecast/acceptance.out`
  with the invocation in `acceptance.sh`.
- **Compare against §0.** Reproducing those figures is the check that the instrument is sound.
- **Commit:** `forecast: the measurement, verbatim, run once`

### Phase 3 — Read it against Rule B

- Apply **PRD §2.1 Rule B**, honouring the **asymmetry**: a high score is reasonable evidence the
  population can produce exposure; a low score is **weaker** evidence it cannot, because the signal
  under-counts.
- Write the reading into the aspect spec and add a dated note to the PRD. **No published number is
  re-derived or edited** (criterion 11) — this only *adds* a figure.
- **Commit:** `docs(forecast): what the task descriptions say, and what they cannot`

## 3. Edge cases

| Case | Handling |
|---|---|
| Missing/empty `problem_statement` | **`unknown`**, counted and named. Never `0` |
| An instance in `selected.json` absent from `pool.json` | Report it as a named discrepancy; do not silently drop |
| A repo present in the pool but not in v0.12.0's measured set | Calibration row reads **`not measured`**, never `0` |
| Script output disagrees with §0 | **Do not publish.** Investigate the instrument first |
| Temptation to tune tokens until calibration looks good | Forbidden by criteria 6 and 10. The set is frozen **before** calibration is computed |

## 4. Agent execution notes

- The whole aspect is offline; an agent may run every phase, **but must still honour the freeze
  protocol** — the Phase 1 commit contains no `acceptance.out`.
- The single likeliest failure is **reimplementing the A1 scope rule by eye** for the surface floor.
  Keep the floor blunt and say it is blunt; the sharp version is the design that was already
  rejected.
- If the script's figures do not reproduce §0, **stop and report** rather than adjusting either.
