# Plan — console approval UI (issue #55)

Strict TDD (vitest). Branch `feat/55/aliz`.

## Task 1 — server: list pending holds (RED → GREEN)

- `ServerConfig.approvalDir?: string`, read from `BELAY_APPROVAL_DIR` in `createServer`.
- `GET /api/approvals` → `{configured: boolean, holds: [{hold_id, tool, triggers,
  request_id, created_at, timeout, expires_at}]}`.
  Pending = request parses, no `decisions/<hold_id>.json`, `now < created_at + timeout`.
  Missing dir / unreadable entries / malformed JSON are skipped, never throw.
- Tests in `console/src/server/index.test.ts` with a tmp approval dir:
  pending listed; decided absent; expired absent; malformed skipped; unconfigured empty;
  `expires_at == created_at + timeout`.

## Task 2 — server: write a decision (RED → GREEN)

- `POST /api/approvals/decision` `{hold_id, decision, reason?}`.
  Validate id (`^[A-Za-z0-9._-]+$`), existence, expiry, absence of a decision.
  Write `{"decision": ..., "reason"?: ...}` atomically (tmp + rename).
  Errors: 400 `bad-hold-id`/`bad-decision`; 409 `approval-not-configured`/`hold-not-found`/
  `hold-expired`/`already-decided`.
- Tests: approve, deny+reason, exact file bytes, second write 409, traversal 400, unknown 409,
  expired 409, unconfigured 409.

## Task 3 — UI panel (RED → GREEN)

`console/src/components/ApprovalPanel.vue` + spec:
- injectable `fetchFn`/`now` like `useFeed`; poll 1 s;
- renders nothing when `configured === false`;
- lists tool, triggers, countdown, Approve/Deny, deny reason;
- at the deadline buttons disable and `timed out — the engine fails closed` appears;
- a 409 triggers a refetch and no optimistic change;
- `data-testid` on every testable surface; muted slate styling consistent with the console.

Wire it into `FeedView.vue` above the feed (it needs no trace selection).

shared workspace mount already present. README console section; STATUS v-next; CHANGELOG
Unreleased. State: a held call is an observation, never a turn or verdict.

## Task 5 — verification

`npm test` in `console/` (all suites), plus the repo's console CI job semantics
