## Implementation phases

### Phase 1 — Case schema v4: the optional `trajectory` field

- **Goal:** a corpus case can express an INSTANCE-LEVEL expected verdict without corrupting
  the turn-level contract.
- **Prerequisites:** none.
- **Files:**
  - Modify `src/belay/corpus/case.py`: `CASE_SCHEMA_VERSION` → `4`; an optional
    `trajectory` field on the case (absent = not a trajectory case — old cases read
    unchanged; present = `{"status": <PASS|FAIL|UNVERIFIED>, "cause": <named cause or
    null>}`). Fail-closed validation: the field, when present, must carry a known status
    and a cause that is null-or-string; a malformed `trajectory` is a load error, never a
    silent drop. Update the schema-version rationale docstring (what v3 added, what v4
    adds). Check the version-mismatch handling: what does `corpus run`/`show` do with a
    case whose version is newer than the reader understands? Follow the existing rule.
  - Create `tests/test_corpus_trajectory_schema.py` (RED first): round-trip (write a v4
    case with and without `trajectory`; read back byte-identical); old v3 cases (without
    the key) load with `trajectory` absent; malformed trajectory values fail closed; the
    fail-closed status vocabulary is respected.
- **Validation:** `uv run pytest tests/test_corpus_trajectory_schema.py tests/test_corpus_case.py`
- **Commit:** `feat(corpus): case schema v4 — the optional instance-level trajectory verdict`

### Phase 2 — Ingestion: trajectory FAILs become corrupt-success cases

- **Goal:** `phase0 run` ingests an instance-level trajectory FAIL as a case, alongside the
  existing per-turn ingest.
- **Prerequisites:** Phase 1.
- **Files:**
  - Modify `src/belay/phase0/runner.py` (the ingest block ~320-339): when the instance's
    trajectory verdict is FAIL, add a case with target turn = the instance's final turn,
    `trajectory={"status": "FAIL", "cause": null}` in the expected, and the full trace
    (which already carries the claim record) + prestate/manifest via the existing
    `add_case` path. An instance with BOTH turn FAILs and a trajectory FAIL ingests both a
    per-turn case and the trajectory case (every caught failure becomes a case).
  - `corrupt_success_case`-style shaping: the trajectory case's `kind` is `corrupt-success`
    with rule `suite-before-success-claim` (extend the shaping helper if needed so it can
    be called for the instance-level verdict).
  - Create `tests/test_corpus_trajectory_ingest.py` (RED first): a trajectory-FAIL trace
    through the real `run_batch` with `ingest=True` produces a case whose expected carries
    the trajectory FAIL; the case's trace contains the claim record; a trajectory-UNVERIFIED
    instance ingests nothing; a mixed instance (turn FAIL + trajectory FAIL) ingests both.
- **Validation:** `uv run pytest tests/test_corpus_trajectory_ingest.py tests/test_phase0_ingest*.py`
- **Commit:** `feat(phase0): trajectory FAILs ingest as corrupt-success corpus cases`

### Phase 3 — `corpus run` recomputes instance-level verdicts

- **Goal:** the regression-suite property holds for trajectory cases: re-verification
  recomputes the SAME instance-level verdict from the case's own stored artifacts.
- **Prerequisites:** Phases 1–2.
- **Files:**
  - Modify `src/belay/corpus/run.py` `run_case`: when the case carries the `trajectory`
    expected field, recompute via the INSTANCE-level path — reuse the runner's
    `_verify_one_trace` with `ingest=False` and the case's stored `invariants`,
    `server_command`, `manifest_dir=case_dir` — and compare `instance["trajectory"]["status"]`
    to the expected status: equal → MATCH, else REGRESSION. Per-turn cases take the
    existing `verify_turn` path unchanged.
  - Recorded-miss interplay: a declared trajectory miss closes (`MISS_CLOSED`) when the
    recomputed trajectory status transitions PASS→FAIL; otherwise `STILL_MISSED`. Follow
    the existing `_closes_the_miss` shape.
  - The `_divergences` naming path must handle the trajectory dimension (per-turn
    `(axis, kind)` keying must not hide an instance-level regression — name it).
  - Create `tests/test_corpus_trajectory_run.py` (RED first): a synthetic trajectory-FAIL
    case (built via the Phase-2 ingest or `add_case`) re-runs to MATCH; a tampered expected
    (status flipped) reads REGRESSION; a declared-miss trajectory case reads STILL_MISSED /
    MISS_CLOSED correctly; per-turn cases (without the field) classify exactly as before —
    a regression suite that includes both shapes discriminates each.
- **Validation:** `uv run pytest tests/test_corpus_trajectory_run.py tests/test_corpus_run.py`
- **Commit:** `feat(corpus): corpus run recomputes instance-level trajectory verdicts`

## Testing strategy

- RED-first per phase; deterministic, no network; cases built in tmp dirs (the worktree has
  no `corpus/local/` — real banked cases are absent by design; synthetic cases carry the
  contract).
- The regression suite's core property is pinned twice: existing per-turn cases classify
  exactly as before, and trajectory cases MATCH on recompute.

## Environment & determinism

- No env vars, services, or deps. Recompute is deterministic: the case stores everything
  (trace incl. claim, prestate, invariants, server_command).

## Edge cases & error handling

| Case | Behavior |
|---|---|
| v4 case, `trajectory` absent | Not a trajectory case; per-turn path byte-identical |
| `trajectory` present but malformed | Fail-closed load error, never silent drop |
| Recompute status ≠ expected | REGRESSION, named on the trajectory dimension |
| Declared miss, recompute PASS→FAIL | MISS_CLOSED (per existing transition shape) |
| Declared miss, otherwise | STILL_MISSED |
| Trajectory FAIL + turn FAILs on one instance | Both cases ingest (every caught failure becomes a case) |

## Agent execution notes

- **Checkpoint after Phase 3** (recompute is the aspect's core; Phase 4 rides on it).
- Reuse `_verify_one_trace` rather than re-deriving the instance path — it already computes
  `instance["trajectory"]` and respects `ingest=False`.
- Do not change the turn-level MATCH semantics; the two shapes must coexist in one corpus.
