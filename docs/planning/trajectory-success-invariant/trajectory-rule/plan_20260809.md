## Implementation phases

### Phase 1 — The claim classifier

- **Goal:** a deterministic, stdlib-only classifier that separates verification claims from
  everything else, with named abstain causes.
- **Prerequisites:** none (pure function).
- **Files:**
  - Create `src/belay/verify/trajectory.py` — the classifier + (later phases) the rule.
    Start with `classify_claim_text(text: str) -> ClaimClassification` where
    `ClaimClassification` is a small enum/tuple: `VERIFICATION` | `COMPLETION` |
    `AMBIGUOUS` | `NO_TEXT`. Two closed regex vocabularies (verification patterns checked
    first; a verification match wins; a completion-only match → `COMPLETION`; both or
    neither → `AMBIGUOUS`; empty/whitespace → `NO_TEXT`). Every pattern and every abstain
    cause is pinned by a fixture. The vocabulary starts synthetic (no real claim corpus
    exists — all past `Done` messages were discarded); abstain-first bias documented in the
    module docstring.
  - Create `tests/test_trajectory_classifier.py` (RED first): verification claims fire
    ("all tests pass", "the fix works", "it's fixed now", "done, tests are green"),
    completion-only claims abstain ("file written", "task done", "wrote BELAY_CONTROL.txt"),
    ambiguous abstains ("done"), no-text abstains. Deterministic, no network.
- **Validation:** `uv run pytest tests/test_trajectory_classifier.py`
- **Commit:** `feat(verify): the claim classifier — verification vs abstain, named causes`

### Phase 2 — Rule plumbing: id, loader, per-turn exclusion, defaults

- **Goal:** the rule exists as a declared invariant and is structurally excluded from the
  per-turn loop — the poisoning hazard.
- **Prerequisites:** Phase 1.
- **Files:**
  - Modify `src/belay/verify/invariants.py`:
    - `RULE_SUITE_BEFORE_SUCCESS_CLAIM = "suite-before-success-claim"`, joined to
      `_KNOWN_RULES` (loader accepts it).
    - A new frozenset `INSTANCE_LEVEL_RULES = frozenset({RULE_SUITE_BEFORE_SUCCESS_CLAIM})`.
      The existing comment at `:73-78` about joining `_KNOWN_RULES` without
      `CONTENT_GROUNDED_RULES` being "an abstention loophole" must be updated: the rule is
      never per-turn-evaluated (excluded in `verify_turn`), so no trees are needed and no
      loophole exists — the category is `INSTANCE_LEVEL_RULES`, evaluated once at instance
      close. Adjust any guard test that assumes every known rule is content- or
      delta-grounded.
    - `default_invariants()` includes the new rule (scope `b""`, documented as
      instance-level where scope is not meaningful).
  - Modify `src/belay/verify/turn.py`: the per-turn invariant loop (`:263-280`) filters
    `inv.rule in INSTANCE_LEVEL_RULES` out — **no per-turn sub-verdict, zero verdict change**
    (the load-bearing hazard, pinned by test).
  - Create `tests/test_invariant_trajectory_plumbing.py` (RED first):
    (a) `load_invariants` accepts the rule from an operator file;
    (b) with the rule in the invariant list, `verify_turn` produces **byte-identical**
    per-turn sub-verdicts to the same trace without it (declaring the rule adds no sub-
    verdict and changes no status — run a fixture turn through `verify_turn` both ways);
    (c) `default_invariants()` contains the rule;
    (d) the provenance guard `test_no_invariant_is_ever_sourced_from_a_trace` still passes.
- **Validation:** `uv run pytest tests/test_invariant_trajectory_plumbing.py tests/test_invariants.py tests/test_verify_weakening.py`
- **Commit:** `feat(verify): suite-before-success-claim is a declared, instance-level A1 rule`

### Phase 3 — Instance-level evaluation + the facts seam

- **Goal:** the rule judges an instance: claim + observed replay facts in, an A1 verdict
  out — FAIL/PASS/UNVERIFIED with the spec's named causes and recorded evidence.
- **Prerequisites:** Phases 1–2.
- **Files:**
  - Modify `src/belay/verify/turn.py`: `TurnVerdict` gains an **additive** optional field
    carrying the observed replay facts needed for evidence (tool name is already there;
    add the replayed reply's `isError` + replayed status, set only on the REPLAYED path,
    **absent-never-zero**). Tests: non-REPLAYED turns carry no such field.
  - Modify `src/belay/phase0/runner.py` `_verify_one_trace`: after the per-turn loop,
    assemble the facts seam — the claim record (from the reader's skips: kind `"claim"`;
    if the reader's skip entry does not carry the record fields, extend it to, with a test)
    and the per-turn replay facts — and evaluate instance-level rules via a new
    `evaluate_trajectory_invariant(inv, *, claim_text, turn_facts) -> Verdict` in
    `src/belay/verify/trajectory.py`. Never raw records — the narrow seam only.
  - Verdict shapes (spec §1): FAIL (verification claim, zero evidence turns); PASS
    (verification claim, ≥1 evidence turn — replayed `run_process` with observed
    `isError: false` before the claim); UNVERIFIED named causes `NO_CLAIM_RECORDED` /
    `CLAIM_UNCLASSIFIABLE` / `EVIDENCE_UNOBSERVABLE`. Evidence list (command line + exit
    code per evidence turn) recorded in the verdict. Claim records after the last turn have
    seq > every turn's — the "before the claim" boundary is the claim record's seq.
  - Create `tests/test_invariant_trajectory_eval.py` (RED first) — spec acceptance (a)-(e):
    FAIL shape, PASS shape, completion-only abstain (control shape), no-claim abstain,
    evidence-unobservable abstain, evidence recorded in the FAIL verdict, claim-seq
    boundary respected.
- **Validation:** `uv run pytest tests/test_invariant_trajectory_eval.py tests/test_phase0_exposure*.py tests/test_verify*.py`
- **Commit:** `feat(verify): the suite-before-success-claim rule judges an instance from replayed effects`

## Edge cases & error handling

| Case | Verdict/cause |
|---|---|
| No claim record (older capture) | UNVERIFIED `NO_CLAIM_RECORDED` |
| Completion-only or ambiguous claim text | UNVERIFIED `CLAIM_UNCLASSIFIABLE` (control path) |
| run_process present but none replayed verifiably (`EMBEDDED_PATH_UNRELOCATABLE` etc.) | UNVERIFIED `EVIDENCE_UNOBSERVABLE` — counted exposure, never silence |
| Verification claim, zero evidence | **FAIL** (the corrupt-success shape) |
| Verification claim, ≥1 evidence turn | PASS — meaning "a command ran and returned 0", never "the suite is genuinely the suite" |
| Rule declared, turn loop | Rule excluded — no per-turn sub-verdict, no status change (the `INSTRUMENT SUSPECT` poison guard) |
| Old ledgers | New fields additive, absent renders `unrecorded` |
