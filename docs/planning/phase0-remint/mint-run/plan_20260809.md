## 2. Phases

### Phase 1 — Stage 1: the probe instance (1 control)

- **Goal:** prove the instrument on a control before any real spend; gate Rule A row 1 —
  including the first live read of the trajectory abstain on a control claim.
- **Files:** `mint-run/acceptance-stage1.sh` (NEW, agent-drafted, **contains no result**),
  `mint-run/acceptance-stage1.out` (NEW, committed after the run), `mint-run/ledgers/s5a.json`
  (NEW, copied), `mint-run/STAGE1_FINDINGS.md` (NEW).
- **Freeze commit (main thread, before the run):** `mint(s5/stage1): the invocation, frozen before it has been run`
  ```
  # acceptance-stage1.sh
  set -euo pipefail
  export BELAY_EVAL_SERVER_ROOT="${BELAY_EVAL_SERVER_ROOT:-$PWD/eval/servers}"
  uv run python -m eval.minting_driver one control__flask-read-only \
    --root eval/mint/s5a --registry eval/instances/stage4a.json \
    --provider claude-cli --model claude-opus-5 --max-steps 20
  ```
- **Run once (main thread):** `bash mint-run/acceptance-stage1.sh | tee mint-run/acceptance-stage1.out`
- **Verify:** `mkdir -p runs && uv run belay phase0 run eval/mint/s5a/batch --ledger runs/s5a.json
  --corpus-dir corpus/local --server node $PWD/eval/servers/node_modules/@modelcontextprotocol/
  server-filesystem/dist/index.js '{workspace}'`; copy ledger; `belay phase0 report runs/s5a.json`
  output appended to the findings note (must include BOTH exposure lines and the trajectory
  section). **The server entrypoint must be ABSOLUTE** (`$PWD/…`): replay spawns the server with
  cwd set to the scratch restore, so a relative path cannot be found and every turn reads
  `replay did not answer target` → `INSTRUMENT SUSPECT` (observed live on 2026-08-09 at stage 1;
  the canonical form is the driver-printed absolute line, `eval/README.md:88-89`).
- **Gate (Rule A row 1):** capture exists AND ≥1 genuinely verifiable turn AND control
  `VERIFIED_CLEAN` — including its trajectory line: the control's claim must abstain
  (`CLAIM_UNCLASSIFIABLE` or no verification claim), **not** FAIL. A trajectory FAIL on the
  control = control FAIL = **mint void** (D-3; record it as the finding the probe exists to
  surface). `INSTRUMENT SUSPECT` → wiring failure, STOP.
- **Result commit (verbatim, whatever it says):** `mint(s5/stage1): the measurement, verbatim, run once`
- **Validation:** the committed `.out` is raw stdout; the ledger re-renders the same headline.

## 3. Edge cases (each pre-decided; see spec)

| Case | Handling |
|---|---|
| Quota stop | S-7 resume; the limit shape is a finding (R-4), recorded verbatim |
| Unrecognised error | `terminal` → `failed`, skipped, never re-driven |
| Stage-2 trajectory exposure gate fires (0/10 judged) | STOP; Rule B reading written; stage 3 does not launch |
| Control FAIL (incl. trajectory FAIL on a control) | Mint **void**; record, hand-replay (audit aspect), publish as a detector/classifier finding |
| High trajectory FAIL rate | Rule C: do NOT publish a rate until controls + one hand-replay evidence exist (audit aspect) |
| `INSTRUMENT SUSPECT` | Wiring failure, never a result; STOP and fix |
| Attrition shapes recur (truncated `tool_call`; `claude` exit 1) | Recorded `failed` with the shape named (sphinx-11445 / sphinx-8282 precedent); never re-rolled |
| `MissingServerError` / clone failure | Setup failure; fix and re-run the stage (anti-re-roll applies to results, not to runs that never happened) |
| macOS TCC prompt | Record it; the sibling-dir layout is designed to avoid it |
| Node/server drift | Pins re-checked only if install fails; the code-pinned versions win over the README's stale "re-run npm view" note |

## 4. Agent execution notes

- **Agents draft** the three `acceptance-stageN.sh` files (they contain no results by
  construction), the findings-note templates, and the `SUMMARY.md`/`FORECAST.md` templates.
  **The main thread commits each freeze, runs each stage once, and commits each `.out`
  verbatim.** A drafted `acceptance.sh` that embeds an expected result is a defect — the
  script must contain only the invocation, env, and protocol prose.
- Checkpoints: after each stage's result commit, the gate decides whether the next stage
  launches. The owner is present at every checkpoint.
- The `belay phase0 run` command line is identical in shape across stages — only the batch
  dir and ledger name differ; it must not gain a `--` separator (`nargs=REMAINDER`).
- The stage-1 gate now also reads the control's **trajectory line** (S-9) — the first live
  probe of the control-classifier path; a FAIL there is the void condition the probe exists
  to catch at minimum cost.
