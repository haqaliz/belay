### Phase 2.1 — LIBRARY table + resolver + deliberate guard amendment

- **Goal:** the named-entry table exists; the resolver is a deliberate third
  producer of `Invariant` policy, fail-closed on unknown names, unreachable from
  any trace; the egress entry resolves to an invariant that evaluates
  UNVERIFIED-with-cause, never PASS.
- **Prerequisites:** aspect 1 (rules exist).
- **RED (write first):**
  - New `tests/test_invariant_library.py`:
    - `LIBRARY` has exactly the five v1 entries with their declarations:
      `no-create` → `[{"scope": "", "rule": "no-create"}]`,
      `no-delete` → `[{"scope": "", "rule": "no-delete"}]`,
      `tests-read-only` → `[{"scope": "tests/", "rule": "read-only"}]`,
      `source-read-only` → `[{"scope": "src/", "rule": "read-only"}]`,
      `network-egress` → `[{"scope": "", "rule": "network-egress"}]`; each entry
      carries a description and a grounding marker (`delta` / `delta` /
      `delta(read-only)` / `delta(read-only)` / `ungrounded`);
    - resolver: each of the five names resolves to `Invariant` objects with the
      expected rule + byte scope; unknown name → `ValueError` naming it
      (fail-closed); the resolver takes exactly `["name"]`;
    - egress evaluation: `evaluate_invariant` on the egress invariant → UNVERIFIED
      with the named cause and a message that says Belay cannot observe egress and
      the sandbox denies it by construction — never PASS, never FAIL;
    - operator-file safety: `load_invariants` on a JSON file declaring
      `{"scope":"","rule":"network-egress"}` still raises (unknown rule, exit 2
      path) — the curated entry is the only path.
  - Amend `tests/test_invariants.py::test_no_invariant_is_ever_sourced_from_a_trace`
    **deliberately** (the review-approved amendment): the expected producer set
    grows to `{"load_invariants", "default_invariants", "resolve_library_entry"}`,
    and add the new structural pin: `resolve_library_entry` takes only `["name"]`,
    no callable in `invariants.py` with "trace"/"record" in its name may call it,
    and resolution performs no file I/O (it consults only the module table). The
    RED run shows the producers mismatch before the amendment.
- **GREEN:** edit `src/belay/verify/invariants.py`:
  - the `LibraryEntry` dataclass (name, description, declarations tuple of dicts,
    grounding marker) and `LIBRARY: dict[str, LibraryEntry]` — plain data;
  - `resolve_library_entry(name: str) -> list[Invariant]` — looks up `LIBRARY`,
    constructs `Invariant(scope=os.fsencode(d["scope"]), rule=d["rule"])` for each
    declaration **directly** (NOT via `_parse_invariant`, which rejects
    `network-egress` — that rejection is the operator-file safety the tests pin);
    unknown name → `ValueError`; no file I/O;
  - `evaluate_invariant` catch-all: for `rule == "network-egress"`, the UNVERIFIED
    message names the cause and points at the sandbox's deny-by-construction
    egress boundary (keep the derived grounded-set text for other rules);
  - module docstring: one paragraph on the library (named presets, the guard
    amendment, egress honesty).
- **Validation:** `uv run pytest tests/test_invariant_library.py
  tests/test_invariants.py tests/test_invariant_delta_rules.py -q`
- **Commit:** `feat(invariants): named invariant library + guarded resolver`

## Edge cases & error handling

- Unknown library name → `ValueError` → exit 2, same shape as malformed file;
  never a silent no-policy run.
- `network-egress` in an operator FILE stays rejected (exit 2) — curated entry
  only; its evaluation is UNVERIFIED-with-cause, never PASS/FAIL.
- `--no-default-invariants` + library: library on top of no defaults (both
  compose; defaults only when not disabled).
- Repeated flag = append; a repeated name is idempotent in effect (same
  invariants twice is harmless — but assert duplicates do not double-FAIL
  anything; no dedup needed, matching `--invariants` behavior).
- Ledger: if the ledger/detector record turns out NOT to carry the invariants
  list (read the code first), stop and flag — do not invent a new recording path.
