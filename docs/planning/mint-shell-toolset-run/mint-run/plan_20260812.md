# Implementation Plan — mint-run (2026-08-12)

Aspect spec: `docs/planning/mint-shell-toolset-run/mint-run/spec.md`. PRD:
`docs/planning/mint-shell-toolset-run/prd.md`. Precedent for every phase:
`docs/planning/phase0-remint/mint-run/plan_20260809.md` — where this plan differs,
it says so.

## Standing rules (bind every phase)

- **Freeze:** every invocation script and stage file commits BEFORE its run,
  containing no result. Verbatim stdout commits next, whatever it says. A second
  run only if declared.
- **Live runs run in the main thread (owner/agent acting as the operator), never
  delegated** (remint precedent S-3: irreversible, spend-incurring steps are not
  fanned out). Agents draft the freeze scripts and findings templates.
- **No re-rolls:** `captured` never re-drives; quota stop resumes with the IDENTICAL
  command on the SAME root; `no_observation` re-arms.
- **`belay phase0 run` shape:** identical across stages, only the batch dir and
  ledger name differ; **no `--` separator** (`nargs=REMAINDER`); server entrypoint
  ABSOLUTE (`$PWD/…`); `mkdir -p runs` first.
- **Operating point (D-6):** `--provider claude-cli --model claude-opus-5
  --max-steps 20 --request-timeout 120 --toolset filesystem+shell`.

  (or the freeze-able CLI form: `uv run python -m eval.minting_driver one

  eval/instances/pool.json --provider claude-cli --model claude-opus-5
  --toolset filesystem+shell`).
- **Verify:** stock `belay phase0 run` over the smoke capture — `run_process` turn
  replays verifiably (PASS or UNVERIFIED-by-cause, never `NOT_VERIFIABLE`, never

  instance workspace root (cwd evidence).
- **Gate (smoke taxonomy, `mint-dual-server/smoke.md:85-96`):** probe absent →
  model finding (inspect trace, record); probe outside workspace → wiring finding
  (STOP: cwd wrong); FAIL/causeless-UNVERIFIED → instrument finding (STOP and fix
  before stage 1); `INSTRUMENT SUSPECT` → wiring report, never a result.
- **Commit:** `mint(s6/smoke): the dual-server smoke, verbatim, run once` + the
  updated `smoke.md` record (echoed facts, findings included).

## Phase 2 — Stage 1: the probe instance (1 control)

- **Run once (main thread):**
  `bash mint-run/acceptance-stage1.sh | tee mint-run/acceptance-stage1.out`
- **Verify:** `mkdir -p runs && uv run belay phase0 run eval/mint/s6a/batch
  --ledger runs/s6a.json --corpus-dir corpus/local --server node
  $PWD/eval/servers/node_modules/@modelcontextprotocol/server-filesystem/dist/index.js
  '{workspace}'`; copy ledger to `mint-run/ledgers/s6a.json`;
  `belay phase0 report runs/s6a.json` → findings note (both exposure lines +
  trajectory section).
- **Gate (Rule A row 1):** capture exists AND ≥1 genuinely verifiable turn AND the
  control `VERIFIED_CLEAN` — including its trajectory line: the claim must
  **abstain** (`CLAIM_UNCLASSIFIABLE` or no verification claim), never FAIL. A
  trajectory FAIL on the control is the void condition the probe exists to catch at
  minimum cost. Else **STOP** (wiring defect; fix before spending).
- **Commit:** `mint(s6/stage1): the measurement, verbatim, run once`
- **Checkpoint — owner present:** stage-1 gate decides whether stage 2 launches.

## Phase 3 — Stage 2: 4 controls + 7 fresh real (11 records)

- **Run once (main thread):**
  `bash mint-run/acceptance-stage2.sh | tee mint-run/acceptance-stage2.out`
  (expect ~10–15 min; ~11 instances).
- **Verify:** `belay phase0 run eval/mint/s6b/batch --ledger runs/s6b.json

- **Gates:**
  - Capture rate ≥5/11 (stop-loss → publish the smaller denominator if it fails).
  - ≥1 genuinely verifiable turn.
  - **All 4 controls `VERIFIED_CLEAN`** — a control FAIL (including trajectory FAIL)
    **VOIDS the mint**: STOP, hand-replay is the next aspect's job.
  - **Trajectory exposure gate (D-1): ≥1 of 11 instances judged** from the report's
    trajectory aggregate (judged = FAIL or PASS); 0 judged → STOP and re-scope the
    population per Rule B. The file-comparison line is reported but does not gate.
- **Commit:** `mint(s6/stage2): the measurement, verbatim, run once`
- **Checkpoint — owner present:** if VOID, the whole mint stops and the decision is
  the void record; else stage 3 launches.

## Testing strategy

- The **pre-registered gates are the tests**; the suite must stay green
  (`uv run pytest`) before and after every phase.
- Smoke test (`tests/test_minting_driver_dual_server_smoke.py`) is `manual`-marked,
  never in CI, run once live here.
- Deterministic, offline, no network for everything except the live runs
  themselves.

## Environment & determinism

- Env: `BELAY_EVAL_LIVE=1` (live runs), `BELAY_EVAL_SERVER_ROOT` (if servers live
  elsewhere), `BELAY_EVAL_MINT_ROOT` (overrides only if used, declared).
- Servers pinned (`server-filesystem@2026.7.10`, `mcp-server-commands@0.8.2`);
  launched by absolute `node` path; `npx` is prohibited behind the gated proxy.
- Ledgers committed; `belay phase0 report` is a pure re-render (byte-identical from
  the committed ledger is the audit aspect's gate).

## Edge cases

| Case | Disposition |
|---|---|
| Quota stop mid-stage | Pause; record verbatim; resume identical command on same root (`no_observation` re-arms) |
| `terminal` instance errors | Record `failed`, continue; attrition rate is a finding, never a re-roll |
| Truncated JSON reply / `claude` exit 1 | `failed`, named shape, recorded |
| Control trajectory FAIL | **VOID** (D-3), regardless of later adjudication |
| 0/11 trajectory judged at stage 2 | STOP; re-scope per Rule B |
| `INSTRUMENT SUSPECT` | STOP — wiring failure, never a result |
| `run_process` turn not replayable | U9: echoed, UNVERIFIED-by-cause (`EMBEDDED_PATH_UNRELOCATABLE` / `EVIDENCE_UNOBSERVABLE`), counted as exposure, never silent |
| Positive control's command fails in the contained run | Recorded finding; expectation never silently changed |

## Agent execution notes

- Agents prepare: stage files, freeze scripts, findings templates, ledger copies,
  report renders, runbook corrections. **Live runs execute in the main thread** —
  do not delegate a stage run to a subagent.
- Owner checkpoints: end of Phase 0 (freeze commit), end of Phase 1 (smoke gate),
  after every stage's result commit. The stage gates are not the agent's call.
- If the stage-2 gate reads differently than the plan's wording (e.g. the report's
  trajectory aggregate shape), record the reading and ask — never reinterpret the
  gate in the agent's favor.
