## Design (settled)

The SKIP decision is a pure function decided BEFORE any replay, inside
`_recompute_trajectory_case`:

```python
def _trajectory_boundary_skip(tool_names, target_tool, shell_server_command):
    names = {t for t in tool_names if t is not None}
    needs_two = "run_process" in names and any(t != "run_process" for t in names)
    if not needs_two:
        return None
    if target_tool == "run_process":          # stored command IS the shell boundary
        return TRAJECTORY_FILESYSTEM_BOUNDARY_UNEXPRESSIBLE
    if shell_server_command is None:
        return TRAJECTORY_SHELL_BOUNDARY_NOT_SUPPLIED
    return None
```

- `tool_names`: the same `calls` computation the recompute uses —
  `tool_calls(derive_correlation(records))` then `_tool_name(records, n)` per turn.
  `_tool_name` from `belay.verify.turn`; `tool_calls`/`derive_correlation` from
  `belay.index`.
- `target_tool`: `case.target_tool` (recorded at ingest, `case.py:174`; for a trajectory
  case the target turn IS the final turn).
- A `None` tool name (unreadable turn) is treated as non-`run_process` — conservative in
  the honest direction.
- On a SKIP, return `CaseResult(case_id=case.id, outcome=SKIP, skip_reason=<cause>)`
  WITHOUT calling `_verify_one_trace`. SKIP never consults `expected`/`recorded_miss`.
