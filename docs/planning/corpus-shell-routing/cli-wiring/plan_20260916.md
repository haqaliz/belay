## Design (settled)

The flag shape mirrors `verify` / `phase0 run` (`cli.py:3180-3193, 3598-3610, 2586-2588`):
a single string, `default=None`, shlex-split at use, fail-closed (exit 2, named message) on
an un-lexable string. `corpus add`'s `--server` is `nargs=argparse.REMAINDER`, so the new
flag MUST be registered BEFORE it in the parser and the help text must warn "WRITE
`--shell-server` BEFORE `--server`". `corpus run` / `corpus show` have no `--server` — no
ordering hazard.

The stored command for a `corpus add` target turn is resolved for ITS tool, exactly as
`phase0 run` does (`_resolve_server_command(tool_name, server_command, shell_server_command)`
in `runner.py:104-122`): a `run_process` target with `--shell-server` stores the shell
command. Import `_resolve_server_command` from `belay.phase0.runner` (the codebase already
imports private runner helpers, e.g. `run.py` imports `_verify_one_trace`).

## Edge cases & notes for the agent

- `corpus add` REMAINDER ordering is load-bearing: `--shell-server` registered BEFORE
  `--server`, or `belay corpus add trace --server X --shell-server Y` swallows the flag.
- `verify_turn` needs `shell_server_command` on the `corpus add` recompute path AND
  `add_case` needs the resolved stored command — both are separate edits in the same
  handler; a missing one surfaces as a wrong stored command, which the Phase-1 test 2 pins.
- `corpus show`'s SKIP render is new behavior (its recompute could not SKIP before this
  unit) — assert it, don't assume the existing render handles it.
- The claim recompute in `corpus show` does NOT take the shell boundary by design
  (self-consistent; see PRD) — thread the flag to the call for uniformity but it is a no-op
  there; do NOT add a `shell_server_command` param to `_recompute_claim_case`.
