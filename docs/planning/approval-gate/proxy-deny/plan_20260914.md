## The design, precisely

- **`BeforeFrame` (proxy.py:68) returns `bool`.** `True` = forward the original frame
  verbatim; `False` = suppress (deliver nothing to the peer). The docstring gains the
  suppress case. `_FrameHold._run` (proxy.py:257) returns the hook's value; `__call__`
  (proxy.py:237-255) forwards only on `True` and collects suppressed frames (the
  frame **without** its newline — the hook's view) into a list returned to the pump.
  `_write_all` (proxy.py:180) returns `None` — never suppresses.
- **`BoundedPeek.feed(chunk, suppressed=())` (proxy.py:137).** For each suppressed
  frame: its bytes = suffix of `self._buf` (the cross-chunk prefix) + head of the
  incoming chunk + `\n`. `feed` verifies both matches exactly (a mismatch raises a
  named `ObservationDesync`-style error — never a silent corruption), drops the
  buffer suffix, and continues processing the chunk after the frame's bytes. All
  other frames are emitted exactly as today. `_observe` (proxy.py:311) gains the
  `suppressed` parameter and passes it through; its exception path already names and
  kills observation while forwarding continues (proxy.py:319-327).
- **`_pump` (proxy.py:331):** `suppressed = forward(dst_fd, chunk)`; then
  `peek = _observe(peek, chunk, on_capture_error, suppressed)`. The failure path
  (proxy.py:359-369) observes with no suppression (the frame never got a hook
  decision... actually it did — keep it simple: pass what `forward` returned; if
  `forward` raised mid-chunk the suppression list is unreliable, so the failure path
  passes `()` — the same "name the loss" honesty as today).
- **The peer lock:** `run()` gains `peer_lock: Optional[threading.Lock] = None`. When
  set, the **s2c** forwarder is wrapped in a new tiny `_LockedChunkWriter(inner,
  lock)` whose `__call__(fd, chunk)` holds the lock for the whole chunk write and
  whose `flush(fd)` holds it while delegating to `inner.flush` only if it exists
  (`_write_all` has none — the current `forward is not _write_all` flush check
  (proxy.py:375-379) then hits the wrapper, which delegates correctly). The c2s
  forwarder is never wrapped (it writes to the server, which the refusal never
  touches). The refusal's `deliver` (aspect 2) uses the same lock around
  `_write_all(sys.stdout.fileno(), refusal)`.
- **Composition (`proxy.main`, proxy.py:530-596; `_contained_run`, 599-651):**
  - Read `BELAY_APPROVAL_DIR`, `BELAY_APPROVAL_TIMEOUT` alongside the existing env
    (proxy.py:535-538).
  - `BELAY_APPROVAL_DIR` set without `BELAY_TRACE_DIR` → print `belay: ... refusing
    to start` and return 2 (M16). Unusable dir / invalid timeout → same (M1).
  - Construct `ApprovalGate(dir, timeout, poll_interval=0.1, clock=time.monotonic,
    record=<writer.record wrapper>, deliver=<locked client writer>)` — imported
    locally like `belay.sandbox.gate` (proxy.py:617-618), never at module scope
    (M11).
  - Build the peer lock here; pass it to `run(..., peer_lock=...)`.
  - Hook chain: `before_frame = approval.compose(gate.before_frame)` where
    `compose` (in `belay.approval`) returns a callable that on c2s runs
    `decide_c2s` first (False → return False, never reaching the turn gate) and on
    s2c runs `observe_s2c` then the turn gate (both return True). Without a sandbox,
    compose handles a `None` turn-gate argument.
  - `gate.close_all(APPROVAL_SHUTDOWN)` runs in the `finally` of the run path
    (alongside `writer.close()`).

## Phases

### Phase 1 — the suppress contract, pure (RED → GREEN)

- **Goal:** `BeforeFrame` bool return; `_FrameHold` suppresses and reports; no hook
  behavior changes for True-returning hooks.
- **Files:** `src/belay/proxy.py` (contract + `_FrameHold`); `tests/test_approval_proxy.py` (new).
- **RED first:** unit tests driving `_FrameHold` directly (no subprocess):
  1. a hook returning False suppresses: the peer fd receives nothing for that frame
     and the suppressed frame (without newline) is returned in the suppression list;
  2. a hook returning True forwards the original bytes verbatim (byte-identity
     assert) and returns no suppression;
  3. suppression of a frame spanning two `__call__` inputs works (partial held
     across calls) and the returned suppression is the whole frame;
  4. multiple frames in one chunk with a suppression in the middle: the peer
     receives the others verbatim.
- **GREEN:** implement; keep `_run`'s exception contract (proxy.py:260-273) exactly
  as today: a raising hook is named via `_name` and the frame is **forwarded** — a
  hook failure can never stall the data path (the byte-transparency invariant).
  Fail-closed for the approval path is achieved inside `decide_c2s` (aspect 2: the
  hook is total — internal faults suppress and refuse with `APPROVAL_FAULT`), never
  by `_FrameHold`. Pin this in the tests: a raising hook is named, the frame is
  forwarded, the direction survives.
- **Validation:** `uv run pytest tests/test_approval_proxy.py tests/test_turn_gate.py
  tests/test_differential.py -q`; full suite green.
- **Commit:** `feat(proxy): BeforeFrame suppress contract`

### Phase 2 — the observer stays delivered-consistent (RED → GREEN)

- **Goal:** `BoundedPeek.feed(chunk, suppressed)`; `_pump`/`_observe` wiring.
- **RED first:** unit tests on `BoundedPeek` directly:
  1. suppressed frame wholly in one chunk → not emitted; surrounding frames emitted
     byte-identically;
  2. suppressed frame spanning two feeds (buffer suffix + chunk head) → not emitted,
     buffer cleared, following frames correct;
  3. a mismatch (suppressed bytes that don't match buffer/chunk) raises the named
     error (observation dies, no partial frame emitted);
  4. multiple suppressions in one feed applied in order;
  5. `_pump`-level: with a `_FrameHold` forwarder whose hook suppresses, the peek's
     emitted frames equal the delivered stream for mixed chunks.
- **GREEN:** implement `feed`/`_observe`/`_pump` changes; keep the `finally` flush
  logic (proxy.py:374-390) untouched in behavior.
- **Validation:** targeted + `test_bounded_peek.py`, `test_capture_shutdown.py`,
  `test_trace_ordering.py` green; full suite green.
- **Commit:** `feat(proxy): observer sees the delivered stream`

### Phase 3 — the peer lock (RED → GREEN)

- **Goal:** `_LockedChunkWriter`; `run(peer_lock=...)` wraps only the s2c forwarder.
- **RED first:** a stress-ish test with a slow large server frame being written while
  the refusal delivery writes concurrently — with the lock, the client's stream
  contains whole frames only (no interleaving); without it (control), interleaving
  is observable. Also: the flush path works when the inner forwarder is `_write_all`
  (no flush) and when it is `_FrameHold` (flush delegates under the lock).
- **GREEN:** the wrapper class; wire in `run()`.
- **Validation:** targeted green; `test_differential.py` + `test_turn_gate.py` green;
  full suite green.
- **Commit:** `feat(proxy): frame-atomic client writes under a shared lock`

### Phase 4 — composition root + env validation (RED → GREEN)

- **Goal:** `BELAY_APPROVAL_DIR` / `BELAY_APPROVAL_TIMEOUT` validation, subdir setup,
  hook chain, refusal wiring, `close_all` on exit.
- **Files:** `src/belay/approval/__init__.py` (compose), `src/belay/proxy.py` (main /
  `_contained_run`), `tests/test_approval_proxy.py` (subprocess-level).
- **RED first:** subprocess tests driving `python -m belay.proxy` with a scripted
  server (a tiny Python server that records stdin and answers tools/list with a
  destructive tool, then echoes stdin back):
  1. `BELAY_APPROVAL_DIR` without `BELAY_TRACE_DIR` → exit 2, `belay:` message;
  2. unusable approval dir → exit 2; invalid timeout → exit 2;
  3. gate unset + destructive server → byte-identical capture to a no-approval run
     (differential), nothing in the approval dir;
  4. deny pre-written → client receives the refusal with its request id; server
     stdin never sees the request; the run completes (client EOF) without a hang;
  5. approve pre-written → request reaches the server byte-identically, response
     reaches the client byte-identically;
  6. shutdown with a pending hold (client sends a destructive call and closes) →
     run exits within the shutdown bounds, decision resolved `APPROVAL_SHUTDOWN`.
- **GREEN:** implement; `compose` in `belay.approval/__init__.py`.
- **Validation:** targeted green; `test_import_guard.py`, `test_proxy_containment.py`,
  `test_demo_capture.py`, `test_real_client.py` green; full suite green.
- **Commit:** `feat(approval): gate wiring — env, hook chain, refusal, shutdown`

## Edge cases & error handling

- `_run`'s generic catch (proxy.py:260-273) is unchanged: a raising hook is named
  and the frame is forwarded — a hook failure never stalls the data path. The
  approval gate is **total** (aspect 2): it catches its own faults and suppresses
  with a named `APPROVAL_FAULT` refuse — fail-closed lives in the hook, not in
  `_FrameHold`.
- The failure path of `_pump` observes without suppression (the "name the loss"
  discipline of proxy.py:359-369).
- The `finally` flush identity check (proxy.py:375) must keep working for both the
  unlocked and locked forwarders — the wrapper owns a `flush`.
- While a hold is parked, the c2s direction is not read (bounded by the deadline) —
  the accepted residue, named in the PRD (M3).
- No `json` in `proxy.py` — the refusal bytes come from the approval module via
  `deliver`.
