## Phases

### Phase 1 — request/decision file contract (RED → GREEN)

- **Goal:** atomic request writes, atomic decision reads, retry-on-partial.
- **Files:** `src/belay/approval/channel.py`; `tests/test_approval_channel.py`.
- **RED first:**
  1. `write_request(hold)` → file at `<dir>/requests/<hold_id>.json` with exactly the
     contract fields (`hold_id`, `tool`, `request_id`, `triggers`, `created_at`,
     `timeout`); atomicity pinned: the write goes through a temp file in the same
     directory renamed into place (assert the temp name appears and the final name
     never exists half-written — e.g. monkeypatch `os.replace` to observe the pair).
  2. `read_decision(hold_id)` → `None` when absent; a decision when present;
     malformed JSON / unknown `decision` value / missing `decision` key → treated as
     absent for that poll (return None), never raise, never guess.
  3. Startup validation: an unusable requests dir raises a named `ValueError`-family
     error the composition root can refuse on.
- **GREEN:** implement with `tempfile`/`os.replace`; `json.loads` inside try/except.
- **Validation:** `uv run pytest tests/test_approval_channel.py -q`; full suite green.
- **Commit:** `feat(approval): request/decision file contract, atomic`

### Phase 2 — bounded poll loop, fail-closed deadline (RED → GREEN)

- **Goal:** `await_decision(hold, clock)` — one clock, one order, exact.
- **RED first:** with an injected fake clock and `poll_interval=0`:
  1. decision file present on first poll → resolved immediately with its decision.
  2. no decision → the loop checks the deadline each tick; at deadline → deny
     `APPROVAL_TIMEOUT` (fail-closed, never forward — M5).
  3. decision file arriving after the timeout deny → ignored, never re-decides (M14);
     the hold is already resolved (aspect 1's resolution-once).
  4. a decision with a reason string is carried into the resolution.
  5. deterministic: the same inputs produce the same outcome (one ordering: check
     decision, then deadline — or deadline first; pick one and pin it in the test).
- **GREEN:** `time.monotonic` default clock; `poll_interval` default 0.1; the loop
  never sleeps longer than `min(poll_interval, remaining)`.
- **Validation:** targeted green; full suite green.
- **Commit:** `feat(approval): bounded fail-closed deadline, one clock`

### Phase 3 — refusal bytes (RED → GREEN)

- **Goal:** `refusal_bytes(hold, cause)` — the JSON-RPC error for the client.
- **RED first:** acceptance 5 — parse the produced bytes; assert `jsonrpc == "2.0"`,
  `id` equals the request's own id (string, int, and null ids all round-trip), error
  code `-32000`, message names the gate and tool, `data.belay.approval` carries
  `hold_id`, `decision: "deny"`, `cause`; the bytes end with `\n`.
- **GREEN:** one `json.dumps` + `b"\n"`.
- **Validation:** targeted green; full suite green.
- **Commit:** `feat(approval): named JSON-RPC refusal`

### Phase 4 — live annotation cache (RED → GREEN)

- **Goal:** `ToolFacts` observer — facts current at hold time, no trace reads.
- **RED first:** acceptance 6 —
  1. `observe_c2s(frame)` records id → method for request frames only (bounded FIFO;
     assert the cap drops the oldest and the tracker never exceeds it).
  2. `observe_s2c(frame)` with an id naming a tracked `tools/list` request and a
     `result.tools` array → per-tool tri-state facts in the `annotations.py:60-81`
     shape (`{"readOnlyHint": {"state": ...}, ...}`).
  3. a response to a tracked non-`tools/list` request never updates facts; an
     untracked id never updates facts; a `notifications/tools/list_changed` frame
     clears the cache; the next snapshot repopulates.
  4. absent annotations → `not-declared`; literal `null` → a declaration
     (`declared.py` present/absent split) — never confused.
- **GREEN:** reuse `declared.declared_state`; mirror `annotations._tool_facts`.
- **Validation:** targeted green; full suite green.
- **Commit:** `feat(approval): live annotation cache from the wire`

### Phase 5 — hook surface (RED → GREEN)

- **Goal:** `decide_c2s(frame) -> bool` and `observe_s2c(frame)` wired through the
  registry + cache + channel; `close_all` on shutdown.
- **RED first:** acceptance 4 and 7 —
  1. a triggered `tools/call` with a decision file pre-written → True (forward); the
     same with a deny file → False, exactly one refusal delivered through the
     injected `deliver`, hold + decision records through the injected `record` with
     the decision before the refusal (order pinned by call-sequence assertions).
  2. an untriggered call, unparseable frame, batch, notification, and non-`tools/call`
     → True, nothing written, nothing recorded.
  3. `close_all(APPROVAL_SHUTDOWN)` resolves every pending hold, records each, and a
     subsequent `decide_c2s` on a new triggered call still works (the gate is
     sticky-but-alive — no half-closed state); a refusal is produced for each
     shutdown-denied hold.
  4. a hold with `list_changed` after its snapshot → the hold's own facts were fixed
     at hold time (the decision uses the facts observed when the call arrived).
  5. **Totality (the fail-closed rule):** `decide_c2s` never raises — an internal
     fault (channel I/O failure, registry error, any unexpected exception) results
     in `False` (suppress) with a best-effort refusal and a decision record whose
     cause is `APPROVAL_FAULT` (a vocabulary extension of the PRD's closed cause
     set — a gate that cannot evaluate its trigger must refuse loudly, never
     forward a destructive call silently and never let the client hang). Pin it with
     a deliberately faulting channel.
- **GREEN:** the channel becomes the composition object the proxy root will wire.
- **Validation:** targeted green; full suite green.
- **Commit:** `feat(approval): decide_c2s/observe_s2c hook surface`

## Edge cases & error handling

- Every poll outcome is deterministic; malformed decisions retry to the deadline.
- The refusal carries the request's id exactly as the client sent it — never
  normalized.
- The tracker cap mirrors `trace.py:_REQUEST_INDEX_MAX` (4096).
- No network, no real sleeps beyond `poll_interval`; the injected clock makes every
  timeout test deterministic.
