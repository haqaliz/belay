## 2. Implementation Phases

### Phase 1: RED — the acceptance tests (`tests/test_docker_image.py`)

- **Goal:** a failing test file asserting the image's behavior, so the Dockerfile's existence is demanded by tests, not by prose.
- **Prerequisites:** none (suite green at base: 1795 passed / 25 skipped).
- **Files to create:** `tests/test_docker_image.py` only.
- **Content (per `image/spec.md` acceptance):**
  - Module gate: skip whole module with cause `docker-unavailable:` when `docker` CLI is missing or the daemon doesn't answer (`docker info` probe). Add `docker-unavailable` to the README platform-coverage cause table (row: "no Docker CLI/daemon on the host — the docker tests skip with this cause") — **this README edit is part of Phase 1** (RED) because the named-cause discipline requires the row to exist before the skip reason names it.
  - Fixture (session-scoped): run `uv build --wheel` into the repo's `dist/` (gitignored), `docker build -f Dockerfile -t belay:test .`, return the tag; clean up image+dist after.
  - Tests (each a subprocess `docker run`):
    1. `test_image_builds` (implicit in fixture) + `test_build_is_reproducible_enough` — fixture failure IS the RED.
    2. `test_belay_help_exits_zero` — `docker run <tag> belay --help` exit 0; stdout contains `sandbox`, `replay`, `verify`, `corpus`, `phase0`, `interop`.
    3. `test_proxy_entrypoint_reachable` — `docker run <tag> python -m belay.proxy --help`… (if proxy has no `--help`, use `python -m belay.proxy` with a trivially-invalid server and assert a *belay-shaped* error, not a module-not-found; verify actual proxy argv contract at `src/belay/proxy.py:530-574` before writing) — assert exit code and stderr mentions `belay.proxy`, never `No module named`.
    4. `test_version_stamps_from_the_installed_wheel` — `docker run <tag> python -c "import belay; print(belay.__version__)"` matches `pyproject.toml` version (0.20.0).
    5. `test_default_user_is_non_root` — `docker run <tag> id -u` == 1000; `docker run <tag> whoami` == `belay`.
    6. `test_root_is_opt_in` — `docker run --user root <tag> id -u` == 0.
    7. `test_ownership_contract_both_ways` — (a) bind-mount a host tmp dir owned by the *host* uid (≠1000 on CI) → container user 1000 **cannot** write (assert EACCES/denied); (b) same mount as `--user root` → write succeeds. Deterministic, no sudo needed.
    8. `test_workdir_and_volume_mount_point` — `docker run <tag> pwd` == the WORKDIR chosen (to be `/workspace`); asserts the documented mount point exists.
    9. `test_no_documented_python_m_belay` — `docker run <tag> python -m belay` exits nonzero with `No module named belay` (asserts we never ship a false `__main__` path).
- **Validation:** `uv run pytest tests/test_docker_image.py -k docker` — module skips with `docker-unavailable` **or** tests fail at the fixture (no Dockerfile). The named-cause gate test `tests/test_platform_gate_named_causes.py` stays green (new cause row used).
- **Commit:** `test(docker): RED — image acceptance tests (build, entrypoints, user, ownership contract)`

### Phase 2: GREEN — `Dockerfile` + `.dockerignore`

- **Goal:** make Phase 1 pass.
- **Prerequisites:** Phase 1 committed.
- **Files to create:** `Dockerfile`, `.dockerignore`.
- **Dockerfile (single stage — the wheel is built by the host, pinned per PR):**
  ```dockerfile
  FROM python:3.12-slim
  COPY dist/belay_harness-*.whl /tmp/
  RUN pip install --no-cache-dir /tmp/belay_harness-*.whl \
      && rm /tmp/belay_harness-*.whl
  RUN adduser --disabled-password --uid 1000 --gecos "" belay
  WORKDIR /workspace
  USER belay
  ENTRYPOINT ["belay"]
  ```
  (Adjust only on measured failure: base must keep `/bin/sh` + coreutils for the `sandbox check` probes — python:slim does; the A2 escape matrix is the final arbiter of substrate divergence, per the PRD decision rule.)
- **.dockerignore** — exclude: `.git`, `.venv/`, `.claude/`, `traces/`, `runs/`, `_sandbox/`, `corpus/`, `eval/`, `node_modules/`, `__pycache__/`, `.pytest_cache/`, `.mypy_cache/`, `.ruff_cache/`, `uv.lock` optional, **allow** `!dist/*.whl` (the pinned wheel).
- **Validation:** `uv build --wheel && docker build -f Dockerfile -t belay:test . && uv run pytest tests/test_docker_image.py -k docker` — green. Full suite: `uv run pytest -q` green.
- **Commit:** `feat(docker): the image — python:3.12-slim, wheel-pinned, non-root user, belay entrypoint`

## 4. Testing Strategy

- Unit tests: none in `src/` — this aspect ships no engine code (asserted: the diff touches no `src/belay/` file).
- The acceptance tests ARE the unit tests here (subprocess-level, mirroring `tests/test_sandbox_check.py:373-382` and `tests/test_launch.py`).
- Determinism: all `docker run` invocations are fixed-arg, checked via exit code + stdout/stderr substring; the fixture builds the wheel from the current checkout (never network-installed); image tag `belay:test` fixed.
- No network in tests beyond the base-image pull by docker (documented; CI has it).
- Full-suite gate after each phase: `uv run pytest -q` (1795+ baseline, skips unchanged plus the new `docker-unavailable` skip outside CI).

## 5. Environment & Determinism

- Env: none new at runtime. `docker` must be present for the test module to run (CI job has it; local machines without docker get the named-cause skip).
- Determinism contract: the wheel is built from the PR's own source in the fixture — a stale `dist/` wheel would fail the version-stamp test (asserted, not assumed).
- The named-cause discipline: `docker-unavailable` added to the README table (Phase 1) so the gate test `tests/test_platform_gate_named_causes.py` remains green; if that test's SCAN_AREA doesn't cover `test_docker_image.py`, extend SCAN_AREA (it is a platform-gated file by the discipline's own definition).

## 6. Edge Cases & Error Handling

| Edge | Behavior |
|------|----------|
| No docker CLI/daemon | module skips with cause `docker-unavailable`, never fails, never fake-passes |
| `docker build` fails | the fixture raises → every test in the module fails (honest RED) |
| Host uid ≠ 1000 bind-mount | container user denied write (asserted as the documented contract), `--user root` writes |
| Host uid == 1000 bind-mount | container user writes fine — same assertions hold (writes succeed) |
| `python -m belay` | documented as nonexistent; test asserts nonzero exit — no fake entrypoint |
| Wheel missing in `dist/` | `uv build` in the fixture regenerates it before build — never a silent stale wheel (version test guards) |
