## 2. Implementation Phases

### Phase 1: RED — the compose acceptance

- **Goal:** failing tests for a `docker-compose.yml` that does not exist yet.
- **Files:** `tests/test_docker_compose.py`; `tests/test_platform_gate_named_causes.py` (scan area gains the module).
- **Tests:** (a) `docker compose config` validates and resolves the image the fixture built; (b) `docker compose run --rm belay --help` exits 0 and lists the CLI surface; (c) the file declares exactly one service and names the console as a comment, never a service — a broken console service must not ship.
- **Validation:** the module is RED for the right reason (no compose file); ruff + named-cause gate green.
- **Commit:** `test(docker): RED — compose acceptance`

### Phase 2: GREEN — `docker-compose.yml`

- **Goal:** the minimal engine service, and the tests pass.
- **Files:** `docker-compose.yml`.
- **Shape:** one service `belay`, `build: .` with `image: belay:test` so compose and the test fixture name the same artifact; `/workspace` mount; the three env vars a self-hoster actually sets (`BELAY_TRACE_DIR`, `BELAY_SNAPSHOT_DIR`, `BELAY_SANDBOX_SCOPE`) written as pass-throughs with the container-side defaults; no `ports`, no daemon socket.
- **Commit:** `feat(docker): minimal compose service — engine only, console named not built`

### Phase 3: the honesty surfaces

- **Goal:** THREAT_MODEL container section, README quickstart, CHECKLIST L3 ✅.
- **Rule:** every container claim cites the test that measured it, in-image, or is stated as unmeasured. The macOS-host path is named a manual re-probe and is never written as a CI-verified claim.
- **Commit:** `docs(docker): the container boundary, measured — THREAT_MODEL section, README quickstart, L3 done`

## 3. Testing Strategy

- Compose is exercised through the real `docker compose` CLI, subprocess-level, same style as A1/A2.
- The doc claims are not unit-testable prose; what IS checked is the pair that would rot silently: the README callout is gone (asserted by its absence being a visible edit, not a test) and every skip cause the docker modules emit is in README's table (already enforced by `test_platform_gate_named_causes.py`).

## 4. Edge Cases & Error Handling

| Edge | Behavior |
|------|----------|
| `docker compose` plugin absent (only `docker-compose` v1) | skip with the `docker-unavailable` cause — the probe checks `docker compose version`, never assumes |
| Compose builds a second image | avoided: `image:` pins the tag the session fixture built, `pull_policy` left default so the local tag wins |
| A reader runs the quickstart on a pre-5.13 host | documented: the launcher refuses with a named cause, exit 2 — loud, not silent |
