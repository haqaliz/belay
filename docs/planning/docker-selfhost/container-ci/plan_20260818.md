## 4. Testing Strategy

- The A2 "unit tests" are the subprocess-level docker tests (same style as A1). No engine code, so no unit tests in `src/`.
- The in-container full suite is pytest-in-docker-in-pytest: it reuses the repo's own suite unchanged — the L2/L3 discipline (named-cause skips) is what keeps "green" meaningful.
- Determinism: fixed-arg docker invocations; the fake MCP server is inline and deterministic (fixed responses, no clock/network); the trace is generated fresh each run; image tag fixed; `--rm` on every container.
- Manual verification: `docker run <img> sandbox check` on a machine without docker cannot run (named-cause skip).

## 5. Environment & Determinism

- No new env vars. Docker required for the module (skip `docker-unavailable` otherwise).
- Dev deps inside the dev container are measured, listed in the test comment, installed with `--no-cache-dir`.
- The proxy/verify roundtrip uses only AF_UNIX / local stdio — no network beyond the container's own loopback (allowed by design in tests).

## 6. Edge Cases & Error Handling

| Edge | Behavior |
|------|----------|
| In-container full suite has an unexpected skip | the test asserts the skip report names only known causes — an unknown cause FAILs (the honesty rule, machine-checked) |
| `landlock-unavailable` on the host kernel | the probe test must report the cause honestly — if the host lacks Landlock, `sandbox check` exits nonzero with the cause; the test asserts the *cause is named*, never a bare pass or a fabricated pass |
| Overlayfs / `reflink-unavailable` | fidelity test passes via the copy path + named cause (SKIP), never a silent fallback |
| Proxy smoke trace dir | created in-container temp dir, cleaned up |
| `pip install` inside the dev container needs network | CI has it; documented (not a test-network violation — the repo's own suite stays network-free) |
