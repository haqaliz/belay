## 1 · Design decisions (settled — do not re-litigate mid-build)

1. **The fix is in the recorder, not the reader and not the pump.** Teaching
   `derive_correlation` to re-pair an inverted pair would make a *merged* trace
   (`merge_session_traces` destroys session provenance by design) pair a response with a
   request it never answered. Removing the cause is the only safe direction.
2. **The wait is a `threading.Condition` over the writer's existing `_lock`.** One lock,
   not two: the index must be updated atomically with the append, and a waiter must
   release the lock while waiting or the c2s record it is waiting for could never be
   written. `notify_all` under the same lock, on every append that indexes a request and
   on `close()`.
3. **Classification mirrors `index.classify` exactly** (`result`/`error` first). It is
   re-implemented in `trace.py` rather than imported from `belay.index`: the recorder must
   not depend on a derivation that reads what it writes, and the two are pinned to each
   other by a test that runs both over the same frames.
4. **The key is `(type-name, id)`, matching `index._id_key`'s tail.** Only one id space is
   involved — the client's — because only c2s requests are indexed and only s2c responses
   wait, so the direction half of the reader's key is constant here.
5. **The index is monotone and FIFO-capped, NOT drained on answer.** The PRD's S2 said an
   id leaves the index once its response is recorded. That is wrong in one reachable case:
   a **duplicate response** (a non-conforming server replying twice; `index.py` names it
   `duplicate-response` and this repo has fixtures for it) would then find its key gone and
   stall for the whole deadline. So the index keeps a key once written and drops the
   **oldest** beyond `_REQUEST_INDEX_MAX = 4096` — bounded memory, and a spurious wait only
   for a duplicate response arriving more than 4096 requests late.
6. **Deadline: `REQUEST_WAIT_TIMEOUT = 2.0` s, injectable via the constructor.** The window
   it covers is a base64, two hashes and one `write` — microseconds, ~100 ms for a
   16 MB frame. 2 s is four orders of magnitude of headroom and caps the cost of an orphan
   response well below the proxy's own exit grace. (The PRD said "~5 s"; 5 s buys no extra
   safety and multiplies the pathological stall. Recorded as a deliberate narrowing.)
7. **The state handle is read BEFORE the wait.** `_handle_for` is called at observation
   time exactly as today, so a deferred record carries the handle that was current when the
   frame was *seen*, not one set during the wait. The deferral must not move any other
   field's meaning.
8. **No new record kind, no new field, no schema bump.** A fail-open record is an
   out-of-order pair, which the readers already name. Inventing a `deferral_expired` record
   would be a format change for a case that is already legible.

## 2 · Task order (test-first)

1. **RED, unit** — `tests/test_trace_ordering.py`, exercising `TraceWriter` directly with
   threads and events (deterministic, no sleeps on the assert path):
   - a response whose request is unrecorded does not land; it lands, after the request,
     once the request is recorded (`request seq < response seq`);
   - fail-open: with `request_wait=0.05`, an orphan response lands anyway, out of order;
   - no-wait: a response whose request is already recorded; a server-originated request
     frame (`method` present) travelling s2c; a notification; a truncated frame; a batch
     array; an unparseable frame; a container-valued id;
   - closed-abort: `close()` while a waiter is parked releases it (and the append then
     raises `TraceClosed`, the writer's existing contract);
   - the index is bounded and does not grow with total traffic;
   - the classification-parity test against `belay.index.classify`.
2. **RED, integration** — `tests/fixtures/fast_server.py` (replies immediately, waits on
   nothing) plus a sequenced in-test client; N=20 `tools/call` roundtrips through the real
   `python -m belay.proxy`; assert every correlation is `answered` with
   `request_seq < response_seq`, no `index_gap`, and the `tools/list`
   `annotation_snapshot` present. **Pre-registered measurement, taken before the fix, two
   20-run stresses: 15/20 and 12/20 runs broken, 46 and 60 broken correlation records.**
3. **GREEN** — implement M1–M4 in `src/belay/trace.py`.
4. **Full suite** — `uv run pytest -q -m "not manual"`; watch for tests that record an
   orphan s2c response and now pay the deadline (fix the test, never the default).
5. **M5 docs** — `trace.py`'s ordering docstring; `CLAUDE.md` L3 block; `docs/STATUS.md`;
   `tests/fixtures/docker_roundtrip_trace.py` and `docker_roundtrip_server.py` +
   `docker_roundtrip_client.py` docstrings (re-scoped to the snapshot-before-next-call
   property they still guard); `docs/planning/docker-selfhost/` follow-up line.
6. **PR** → 7 green CI jobs → merge → release.

## 3 · Acceptance criteria

- **AC1** A response is never recorded before its request, for every request/response pair
  the recorder can classify. Deterministic unit test.
- **AC2** The integration guard is 20/20 clean (twice) where it measured 5/20 and 8/20
  clean before.
- **AC3** Fail-open: an orphan response still records, out of order, after the deadline —
  no hang, no fabricated coverage, no new record kind.
- **AC4** `proxy.py`, `index.py`, `annotations.py`, `effect.py` are byte-unchanged, and the
  trace format gains no field (asserted by the existing format tests staying green).
- **AC5** The full suite is green with no new skips and no new named-cause skips.
- **AC6** No published number, verdict axis or coverage line moves.
