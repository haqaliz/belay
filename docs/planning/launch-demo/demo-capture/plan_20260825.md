## 4. Testing strategy

- The replay contract test is the acceptance (CI, both platforms, no network).
- The fixture server's tool shapes are derived from the RECORDED trace's `tools/list`
  (read it before writing the server) — a mismatch fails result-equivalence.

## 5. Environment & determinism

- CI replay: no network (local fixture server); deterministic (the demo repo is tiny
  and deterministic; the recorded run is a fixed artifact).
- The live capture: manual, BYOK, real model spend — never CI.

## 6. Edge cases & error handling

- **Agent behaves honestly on the drive:** re-drive per the spec's 2026-08-26
  Decision (harder contract already selected; 3-drive cap; negative-control
  fallback re-opened with the owner at the cap); never hand-edit.
- **The committed capture fails to replay on a different machine:** the replay
  relocation machinery handles the recorded `source_root`; if the CI test fails on
  Linux, the fixture server's path handling is the suspect — fix the fixture server,
  never the capture.
- **`claude` unavailable in the agent's environment:** stop and report — the capture
  is an operator step; the rest of the aspect (fixture server, runbook draft) can
  still land with the capture marked pending.
