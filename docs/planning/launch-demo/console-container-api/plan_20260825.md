## 2. Implementation phases

### Phase 1: RED — the render-check test fails

- **Goal:** the docker-gated test asserts the container renders a trace; it FAILS
  (the container serves no /api today).
- **Prerequisites:** none.
- **Files to modify:** `tests/test_docker_compose.py` — extend
  `test_the_console_image_builds_and_reports_health_with_the_engine` (or add a sibling
  test, same gate): after the health check, mount a small fixture trace into the
  container at the trace dir (create a 2-turn fixture trace jsonl + a snapshots +
  manifests dir for it — reuse the roundtrip fixtures' output or hand-write a minimal
  one per `TRACE_FORMAT.md`), then `curl /api/traces` (expects the trace listed),
  `curl "/api/trace?path=<trace>"` (expects derived turns JSON), and `/health` still
  reports the engine version.
- **Validation:** the new assertions FAIL against the current image (404s); the rest
  of the module passes as before.
- **Commit message:** `test(compose): RED — the console container renders a trace`

### Phase 2: GREEN — the image runs the real server

- **Goal:** the container serves the real API; the RED test passes.
- **Prerequisites:** Phase 1 RED committed.
- **Files to create/modify:**
  - `console/src/server/index.ts` — add `/health` (200 `{"ok": true, "engine":
    "<version>"}` via the engine wrapper; 503 + honest null when the engine probe
    fails — mirror `server-static.mjs`'s semantics so the healthcheck contract holds).
  - `console/package.json` — add `"build:server": "tsc -p tsconfig.server.json"`
    (or esbuild if tsc's module resolution fights the ESM build — decide by what
    `npm run server` already does; prefer the existing toolchain).
  - `console/tsconfig.server.json` — node-targeted compile of `src/server/` to
    `dist-server/` (plain JS, no bundling needed for the small module graph).
  - `console/Dockerfile` — runtime stage: copy `dist-server/` (built in the build
    stage via `npm run build:server` alongside `npm run build`), `CMD node
    dist-server/run.js`; keep the engine wheel install + non-root user + port; delete
    the `server-static.mjs` usage (the file itself may be removed if nothing else
    references it — grep first).
  - `console/src/server/*.test.ts` — add a `/health` test (ok + engine version,
    honest 503 when the engine probe fails) in the offline suite.
- **Validation:** `npm run test` green (offline); `npm run build && npm run
  build:server` succeed; the docker-gated test passes where docker exists (the CI
  docker job is the real substrate; locally it skips with the named cause);
  `docker compose config -q` valid.
- **Commit message:** `feat(console): the container runs the real server — traces render in compose`

## 4. Testing strategy

- Offline console tests: `/health` semantics (ok + honest 503).
- Docker-gated: render check in `tests/test_docker_compose.py` (CI docker job).
- No network anywhere; deterministic.

## 5. Environment & determinism

- The fixture trace for the render check is small and hand-written (or captured from
  the roundtrip fixtures); deterministic.

## 6. Edge cases & error handling

- **Engine probe fails in-container:** `/health` returns 503 with honest null —
  never a claimed ok (the existing static server's semantics, preserved).
- **Empty trace dir:** `/api/traces` returns `[]` — the console's no-engine/empty
  states (A2-of-L6's tested paths) render honestly.
