## Context (read first)

`run_verify` (`eval/minting_driver/entrypoint.py:995-1063`) is the in-process
`--verify` path. It threads `claim_author` but not `shell_server_command`, while the
printed `verify_command()` (`entrypoint.py:664-700`) emits `--shell-server` for the
shell toolset — so with `--toolset filesystem+shell --verify`, every `run_process`
turn replays against the filesystem server (`Tool run_process not found` → DIVERGED →
abstention: the 2026-08-12 "171 per-turn FAILs are A2 replay artifacts" shape).
`eval/README.md:727-729` claims `--verify` runs "that same command".

Engine seam (verified): `run_batch` accepts `shell_server_command: list[str] | None`
(`src/belay/phase0/runner.py:137-238`) and routes `run_process` turns to it
(`src/belay/verify/turn.py:351-368`). `servers.shell_server_command(root=...)`
(`eval/minting_driver/servers.py:165-171`) returns exactly `["node", <entrypoint>]` —
the argv the printed `--shell-server "node <entrypoint>"` shlex-splits to.
