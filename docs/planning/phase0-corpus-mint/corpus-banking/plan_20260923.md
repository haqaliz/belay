## Phase 2 — MEASURED: run it, after each stage (integrator)

After each stage's verify (aspect `mint-run`), for the captures + ledger that exist:
1. Run the frozen `corpus-run` script; commit the verbatim output
   (`acceptance-cm-run2-corpus-run-stage1.out` / `-stage2.out`), whatever it says.
2. Run the `corpus-score` script; commit verbatim
   (`acceptance-cm-run2-corpus-score-*.out`).
3. Confirm B1–B4 from the ledgers + outputs: every trajectory FAIL banked as
   `trace-<instance>-trajectory` and recomputing MATCH; every per-turn FAIL banked or
   reported `flagged-but-unaddable` WITH its named cause; A3 column filled per
   instance (verdict or named cause); 0 REGRESSION and every SKIP's cause named.
4. `corpus score` reading recorded honestly: `precision`/`recall` `n/a` (cases bank
   `pending`; only the owner labels, S-1) — never fabricated, never a 1.00.
**Commits:** per stage, `test(corpus-banking): <stage> recompute verbatim output — <what it says>`.

## Edge cases

- A stage that banked nothing: B-criteria report zero counts with the denominator
  stated — a recorded result, never a red failure.
- Corpus SKIP causes (`TRAJECTORY_SHELL_BOUNDARY_NOT_SUPPLIED` /
  `TRAJECTORY_FILESYSTEM_BOUNDARY_UNEXPRESSIBLE`, `src/belay/corpus/run.py:524-562`)
  distinguished from banking failures — named, never papered over. The frozen script's
  `--shell-server` placement is exactly what prevents the first.
- Case-id collisions are fail-closed by design (`CaseIdCollisionError`) — reported,
  never re-seeded.
