## 2. Phases (TDD, one commit per phase)

### Phase 1 — RED: the seam contract tests

**Files:** `tests/test_verify_triage.py` only.

Write, in this order (each may be its own test; all must fail against the absent module):

1. `NullTriage.triage(...)` returns `None`; constructing it spawns nothing.
2. Resolution: `triage_from_env()` with `env={}` ⇒ `None`; `env={"BELAY_TRIAGE_AUTHOR":
   "  "}` ⇒ `None`; `env={"BELAY_TRIAGE_AUTHOR": "unbalanced 'quote"}` ⇒ `None`;
   un-lexable never raises.
3. `SubprocessTriage` round-trip: a stub command (`sys.executable -c` echoing
   `{"score": 0.7, "confidence": 0.9}` on stdin) returns that `TriageScore`.
4. Fail-closed parse: non-JSON stdout ⇒ `None`; `{"error": ...}` ⇒ `None`; non-object ⇒
   `None`; missing/wrong-typed `score`/`confidence` ⇒ `None`; out-of-range
   (`score > 1` or `confidence > 1`, or negatives) ⇒ `None`. Never a fabricated score.
5. Timeout: a stub command that sleeps past `timeout=0.1` ⇒ `None`, quickly (never a hang).
6. Exit ≠ 0 ⇒ `None`.
7. Stdout cap: a stub emitting > 1 MiB ⇒ `None` (or truncated-then-fail-closed — assert
   the documented behavior; mirror `author.py:53` `_MAX_OUTPUT`).
8. Whitelist serializer: `build_triage_payload(TriageFeatures(...))` emits exactly the
   whitelisted key set (module-level `WHITELISTED_KEYS` — enumerate it from the PRD's
   whitelist: tool name, per-hint annotation tri-state, annotations-object presence,
   offered toolset, reply size, `hash_raw`/`hash_canonical`, turn index/seq, ordering,
   truncated flag, state-handle status, trace-context ids, protocol version,
   `run_process` command_line). The test asserts `set(payload) == WHITELISTED_KEYS` and
   that no payload value is bytes or a raw trace/state field. The dataclass makes raw
   content structurally unrepresentable — the test pins that.

**Validation:** `uv run pytest tests/test_verify_triage.py` — all RED (module absent).
**Commit:** `test(triage-seam): RED — the triage seam contract tests`

### Phase 2 — GREEN: the seam

**Files:** `src/belay/verify/triage.py`.

Mirror `author.py` exactly:

- `TRIAGE_ENV = "BELAY_TRIAGE_AUTHOR"`; `TRIAGE_TIMEOUT = 60.0`; `_MAX_OUTPUT =
  1024 * 1024`.
- `TriageFeatures` dataclass (whitelisted fields only, see Phase 1.8) with a
  `to_payload()` that serializes `sort_keys=True` and emits exactly the whitelist.
- `TriageScore` dataclass (`score: float`, `confidence: float`) with `_parse_score`
  fail-closed (mirror `_parse_check`, `author.py:122-143`; ranges clamped by rejection).
- `Triage(Protocol)` with `triage(self, features: TriageFeatures) -> Optional[TriageScore]`.
- `NullTriage` — returns `None`, no I/O.
- `SubprocessTriage(command, timeout=TRIAGE_TIMEOUT)` — subprocess.run with
  `input=payload.encode()`, `capture_output=True`, `timeout=`, `check=False`; every
  exception / exit ≠ 0 / timeout ⇒ `None` (abstain — the fail-open contract of the PRD:
  the *caller* decides what None means, this aspect only ever abstains).
- `triage_from_env(env=None)` — mirror `author_from_env` (`author.py:56-74`): unset /
  blank / un-lexable / empty ⇒ `None`; else `SubprocessTriage(command)`.

**Validation:** `uv run pytest tests/test_verify_triage.py` — all GREEN; then the guard:
`uv run pytest tests/test_verify_zero_llm.py tests/test_cli_flag_parity.py` — untouched
and green (no flags added in this aspect).
**Commit:** `feat(triage-seam): the provider-neutral triage seam — SubprocessTriage, NullTriage, whitelisted payload`

## 4. Environment & secrets

- `BELAY_TRIAGE_AUTHOR` — read by `triage_from_env` (this aspect); **no key is read or
  passed by the engine, ever** — that is asserted in the `reference-author` aspect, not
  here.
- No `.env`, no API keys, no network in any test.

## 5. Edge cases & error handling

- Timeout / launch failure / exit ≠ 0 / malformed stdout ⇒ `None` (abstain), never a
  raise, never a fabricated score — the PRD's fail-open contract.
- Un-lexable env value ⇒ `None`, never a crash (mirror `author.py:63-68`).
- Stdout cap enforced before parsing (`author.py:53` pattern).
- Score/confidence range validation: reject out-of-[0,1] at parse, not at use.
