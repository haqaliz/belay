## 2. Phases (TDD, commit per phase)

### Phase 1 — RED: `tests/test_refutation_triage.py`

1. **Identity (the refutation, must never be weakened):** the committed demo capture
   verified through the real CLI with a stub triage author (fixed scores, e.g.
   `sys.executable -c` echoing `{"score": 0.5, "confidence": 0.9}`) vs without triage:
   **verdicts byte-identical on the turns replayed** (the JSON documents' verdict
   sections equal), exit codes agree, and an anti-vacuity spy proves the on-side really
   consulted triage (the author command ran) and the off-side never did. Docstring
   states the rule and that it must never be weakened — same register as
   `test_refutation_no_claim_axis.py:1-38`.
2. **Absent ⇒ no-op:** no flag, no `BELAY_TRIAGE_AUTHOR` ⇒ no subprocess is ever
   spawned and no network is attempted — asserted on the constructed request/env (a spy
   on the resolver / on subprocess spawn; scrubbed by absence, never `""`).
3. **Whitelist (the honest-line pair):** the payload constructed for the stub author
   carries only whitelisted keys and no raw state/trace bytes — asserted on the
   constructed payload at the CLI boundary (the seam-level assertion already exists in
   `test_verify_triage.py`; this pins it at the surface).
