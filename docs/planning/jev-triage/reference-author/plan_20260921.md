## 2. Phases (TDD, commit per phase)

### Phase 1 — RED: `tests/test_reference_triage_author.py`

Stub HTTP server via `http.server` on a localhost port (threaded), or monkeypatched
`urllib.request.urlopen` — deterministic, no external network. Tests:

1. The author reads the whitelisted features from stdin and POSTs them; the request body
   carries **only** whitelisted keys (assert against `triage.WHITELISTED_KEYS`), and the
   request carries the operator's key (`BELAY_JEV_KEY`) in the documented header.
2. Non-whitelisted key in the stdin payload ⇒ fail-closed: exit ≠ 0, `{"error": ...}` on
   stdout, nothing sent.
3. Response `{"score": 0.7, "confidence": 0.9}` ⇒ stdout JSON with those values.
4. Malformed / unexpected response (non-JSON, missing keys, out-of-range) ⇒ exit ≠ 0 +
   `{"error": ...}`.
5. `BELAY_JEV_ENDPOINT` absent ⇒ the documented default endpoint is used (assert on the
   constructed request URL), or fail-closed error if the PRD says no default — the test
   pins whichever the docstring states.
6. `BELAY_JEV_MODEL`: full model id accepted; an alias (e.g. a short name) refused with a
   fail-closed error (mirror `reference_claim_author.py:81`).
7. Provider-neutrality: running the Jev author through the shipped `SubprocessTriage`
   and running a trivial stub command through it behave identically (both round-trip a
   score) — the "laya later is a reference author, never an engine change" pin.
8. The engine never passes a key: assert the constructed child env of
   `SubprocessTriage` contains no `BELAY_JEV_KEY` when the caller env has none — the
   key is the author's own env, by absence never `""` (the honest-line pair).

### Phase 2 — GREEN: `src/belay/verify/reference_triage_author.py`

- Reads stdin JSON, validates keys ⊆ `triage.WHITELISTED_KEYS` (else error exit).
- Reads `BELAY_JEV_KEY` from its own env (absent ⇒ fail-closed error naming the missing
  var, never a guessed key). Full model id required (`BELAY_JEV_MODEL`), aliases refused.
- POSTs with `urllib.request` (stdlib only — the zero-LLM guard walks
  `src/belay/verify/`), timeout bounded (e.g. 10 s, mirror the A3 author's boundedness),
  endpoint from `BELAY_JEV_ENDPOINT` with a documented default.
- Parses the response fail-closed: `{score, confidence}` in [0,1] ⇒ stdout JSON; anything
  else ⇒ exit ≠ 0 + `{"error": ...}`.
- Runs as `python -m belay.verify.reference_triage_author` (a `__main__` guard), matching
  the reference-author precedent's module shape.

## 3. Testing strategy

Unit with stub HTTP; `manual` live test (owner key) is the `refutation` aspect's file —
the live test file is created here but its env-gating follows
`test_reference_claim_author_live.py:118-125` (FAIL-with-instructions when
`BELAY_JEV_KEY` unset).

## 4. Environment & secrets

`BELAY_JEV_KEY`, `BELAY_JEV_ENDPOINT`, `BELAY_JEV_MODEL` — read by the author only. The
engine never reads or forwards any of them (asserted by test 8). The owner's key is for
local manual testing only — never committed, never for users.

## 5. Edge cases

Key absent ⇒ fail-closed, never a guess; non-whitelisted stdin ⇒ error before any
egress; endpoint/model alias ⇒ fail-closed; response malformed/out-of-range ⇒ fail-closed;
timeout bounded.
