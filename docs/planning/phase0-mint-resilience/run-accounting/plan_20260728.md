# Implementation Plan — `run-accounting`

**Unit:** `phase0-mint-resilience` · **Aspect:** `run-accounting` · **Date:** 2026-07-28
**Sources:** `prd.md` must-haves C (10–12) + nice-to-have 27, `run-accounting/spec.md`
**Prerequisite:** `quota-circuit-breaker` — DONE (`RetryingModel` owns `retry_count`;
`checkpoint.py` already carries the entry-schema + history machinery).

---

## The shape of the problem

`batch.py:201` calls `run_session(model_factory(tools), ...)` — the model object is
constructed **inline and never bound**, and `run_session`'s return value is discarded. So
there is nowhere to read accounting from even if the clients recorded it, and they don't:
`local_client.py:125-170` and `anthropic_client.py:147-181` both read only
`.choices`/`.content` and let `response.usage` fall out of scope.

**The fix is one binding and one accumulator**, not a new subsystem.

### Design decisions

**D1 — accounting accumulates on the model object.** `RetryingModel` already sees every
`propose_next` (that is why it owns `retry_count`), so it is the natural place for
`request_count`. Token usage originates in the concrete clients, so they accumulate it and
`RetryingModel` exposes the inner object. No new seam, no new protocol method — `Model` stays
a one-method protocol.

**D2 — bind the model in `batch.py`.** Change `run_session(model_factory(tools), ...)` to
`model = model_factory(tools)` / `run_session(model, ...)`, then read accounting off `model`
after the session. Two lines, and it is the whole reason accounting is reachable.

**D3 — absent is not zero.** A client that cannot report usage yields **absent**, never `0`.
This is the honesty contract in miniature: a measured zero and an unmeasured quantity must
stay distinguishable, exactly as `UNVERIFIED` and `PASS` do.

**D4 — no dollar figures, anywhere.** Under a subscription there is no per-token price, and
inventing one would be fabricated precision. Record **requests + tokens + wall-clock**. If a
metered key is used later, price is applied at *report* time from a stated rate, never baked
into the ledger. A test asserts no currency symbol/field appears.

**D5 — the clock is injected, and it lives in `batch.py`.** `entrypoint.py`'s stated rule is
*"No clock, no randomness"* (`mint-entrypoints/plan_20260723.md:503`); `run-accounting` must
not break it. `run_mint` takes `clock: Callable[[], float] = time.monotonic`.
**`time.monotonic`, not `time.time`** — wall-clock duration must not go negative because NTP
stepped the clock during a 15-minute sympy instance.

## Phase 1 — Usage accumulation in the clients

**Files:** `eval/minting_driver/clients/local_client.py`,
`eval/minting_driver/clients/anthropic_client.py`, `tests/test_minting_driver_clients_mapping.py`

Each client accumulates across its own lifetime (= one instance, since the factory builds one
per instance):
- `request_count: int`
- `usage: Usage | None` — `{input_tokens, output_tokens}`, **`None` until at least one
  response reports it**.

Read duck-typed: OpenAI shape is `response.usage.prompt_tokens` / `.completion_tokens`;
Anthropic is `response.usage.input_tokens` / `.output_tokens`. Use `getattr` throughout — a
fake or a provider that omits usage must yield absent, never raise.

**Tests (RED first):**
1. OpenAI-shaped usage accumulates across two calls (sums, not overwrites).
2. Anthropic-shaped usage accumulates.
3. **A response with no `usage` attribute → `usage is None`**, and `request_count` still
   increments. *The absent-not-zero test.*
4. A response whose `usage` exists but omits one field → the present field is recorded, the
   missing one is absent; no exception.
5. `request_count` counts every `propose_next` that reached the provider.

## Phase 2 — `RetryingModel` surfaces it

**Files:** `eval/minting_driver/resilience.py`, `tests/test_minting_driver_resilience.py`

- `request_count` on the wrapper (counts attempts that reached the inner model).
- Expose the inner object so `batch.py` can read client-level usage without knowing the
  provider.
- **A retried call counts as more than one request** — that is the point; retries cost quota.
  Assert `request_count == 3` for two transients then a success, while the *conversation* sent
  is still identical (already pinned in `quota-circuit-breaker`).

## Phase 3 — `run_mint` records it

**Files:** `eval/minting_driver/batch.py`, `eval/minting_driver/checkpoint.py`,
`tests/test_minting_driver_batch.py`, `tests/test_minting_driver_checkpoint.py`

- `run_mint(..., clock: Callable[[], float] = time.monotonic)`.
- Bind the model (D2). Start the clock before `prepare`, stop it after `bridge_capture` —
  **the instance's whole cost, not just the model's**, because workspace prep and replay
  setup are real wall-clock a stop-loss must account for.
- `Checkpoint.record(..., accounting=...)` storing
  `{wall_clock_seconds, model_requests, retry_count, input_tokens, output_tokens, model, provider}`,
  omitting absent fields rather than nulling them.
- `_validate_entry` must **preserve** `accounting` — it rebuilds entries from a fixed key set
  and will otherwise drop it silently, exactly as it would have dropped `history`.
- **Accounting is recorded on every terminal disposition** — `captured`, `failed`, **and
  `no_observation`**. A quota-stopped instance still consumed requests, and a stop-loss that
  ignores failed attempts under-counts spend.

**Tests (RED first):**
1. Wall-clock recorded from an **injected fake clock**; never real elapsed time.
2. `model_requests` and `retry_count` match what the model saw.
3. Tokens recorded when available; **absent (key omitted) when not**.
4. `model` and `provider` recorded per instance; a batch driven with two different models
   records them distinctly.
5. Accounting is recorded on a `failed` and on a `no_observation` instance too.
6. `accounting` survives save/load round-trip (the `_validate_entry` trap).
7. A legacy entry with no `accounting` still loads.
8. Existing batch/checkpoint tests pass unmodified.

## Phase 4 — Report it

**Files:** `eval/minting_driver/entrypoint.py`, `tests/test_minting_driver_entrypoints.py`,
`eval/README.md`

- `MintReport.render()` gains an accounting block: totals for requests, tokens, wall-clock,
  and **how many instances had usage available vs absent** (the denominator rule — a total
  over partial data must say so).
- **Closes the gap `quota-circuit-breaker` opened** (PRD nice-to-have 27): `render()` today
  summarises only `captured`/`failed`, so after a quota stop it under-reports — the
  `no_observation` instance and the never-driven remainder are in `counts` but not on the
  summary line. Report all four buckets: captured / failed / no_observation / never-driven,
  and say plainly that the batch **stopped early** when it did.

**Tests (RED first):**
1. Totals render with their denominators.
2. Instances with absent usage are counted and stated, not silently excluded.
3. **A quota-stopped batch renders all four buckets and says it stopped early.**
4. **No currency symbol or dollar field appears anywhere** (D4) — asserted so a later change
   cannot quietly add one.
5. `entrypoint.py` still reads no clock (the existing structural rule).

## Edge cases

| Case | Handling |
|---|---|
| Instance fails before any model call | `model_requests: 0`, `usage` absent, wall-clock still recorded — prep time is real. |
| Clock steps backwards | Impossible with `monotonic` (D5). |
| Provider reports usage on some calls only | Sum what exists; the availability count in the report is what makes that legible. |
| A resumed instance overwrites accounting | Prior accounting goes to `history` with the prior disposition — already the established behavior. |
