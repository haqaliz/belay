### Design decisions fixed here (do not re-litigate mid-build)

**D1 — one new status, not two.** `Checkpoint` gains exactly one status:
`"no_observation"`. Both the quota-stopped instance and a transient-exhausted instance
record it. What differs is the *reason* string and whether the batch continues — not the
status. Two statuses would force every consumer to know the difference for no gain.

**D2 — the re-arm is `is_done`, not a flag.** `is_done` returns `True` for `captured` and
`failed`, and **`False` for `no_observation`**. A resume therefore re-drives exactly the
no-observation instances and nothing else, with no new CLI flag and no `--force`-shaped
escape hatch. This is why D1 works: the status *is* the re-arm rule.

**D3 — history is appended, never overwritten.** The entry gains `"history": [...]`. Each
`record` for an instance that already has an entry appends the **previous** `{status,
reason}` before writing the new one. `eval/README.md:303-311` bans `--force` because it
*"lose[s] the record of what already ran"*; this keeps it.

**D4 — a quota error is a control-flow signal, not a failure.** `RetryingModel` raises a
dedicated `QuotaExhausted` on a quota-class error. `run_mint` catches it **before** the bare
`except Exception`, records `no_observation`, and **`break`s** — leaving every later instance
absent from the checkpoint, therefore still eligible.

**D5 — classification is duck-typed and lives in one function.** No SDK import at module
scope: `tests/test_minting_driver_clients_import.py` asserts the driver core imports with
`openai`/`anthropic` absent, and that contract is load-bearing.

## Phase 1 — Error classification

**Goal:** a pure function mapping an exception to `quota` / `transient` / `terminal`.

**Prerequisites:** none.

**Files:**
- CREATE `eval/minting_driver/resilience.py`
- CREATE `tests/test_minting_driver_resilience.py`

**Public surface:**
```python
ErrorKind = Literal["quota", "transient", "terminal"]

QUOTA_RETRY_THRESHOLD_SECONDS = 600.0   # 10 min: above this, no bounded backoff can wait it out

class QuotaExhausted(RuntimeError):
    """A provider quota/period cap. Carries retry_after_seconds when the provider gave one."""
    def __init__(self, message: str, *, retry_after_seconds: float | None = None) -> None: ...

class TransientExhausted(RuntimeError):
    """A transient error that survived every bounded retry attempt."""

def retry_after_seconds(exc: BaseException) -> float | None: ...
def classify_error(exc: BaseException) -> ErrorKind: ...
```

**Classification rules, in order:**
1. `QuotaExhausted` → `"quota"` (idempotent; already classified).
2. Status 429 (via `getattr(exc, "status_code", None)`, falling back to a `429` token in the
   message) **and** a retry hint `> QUOTA_RETRY_THRESHOLD_SECONDS` → `"quota"`.
3. Status 429 **and** a message naming a period cap — `RESOURCE_EXHAUSTED`,
   `GenerateRequestsPerDayPerProjectPerModel`, `quotaId`, `per_day`, `_per_model_per_day` →
   `"quota"`. (Belt and braces: the real errors carry *both* signals, but a provider may give
   only one.)
4. Status 429 otherwise (short or absent hint) → `"transient"`.
5. Status in `{408, 409, 425, 500, 502, 503, 504}`, or the exception is a
   `TimeoutError`/`ConnectionError`/`OSError` → `"transient"`.
6. **Everything else → `"terminal"`.**

`retry_after_seconds` parses, in order: a numeric `retry_after` attribute; a `Retry-After`
response header if reachable by `getattr`; and — because this is the shape the real failures
had — a `'retryDelay': '39043s'` substring in the message. Returns `None` when absent.
**Never raises**: a parse failure yields `None`, because a classifier that throws while
classifying an error would replace a recoverable stop with a crash.

**Tests (RED first):**
1. The **real Stage-3 error string, verbatim** (250/day cap, `RESOURCE_EXHAUSTED`,
   `retryDelay: 39043s`) → `"quota"`. *Use the actual recorded text as a fixture — this is
   the error that cost 56 instances and it is the one case that must never regress.*
2. `retry_after_seconds` on that same string → `39043.0`.
3. A 429 with a 2-second hint → `"transient"`.
4. A 429 with no hint at all → `"transient"`.
5. A 429 with `RESOURCE_EXHAUSTED` but no hint → `"quota"` (rule 3).
6. 500 / 503 / `TimeoutError` / `ConnectionError` → `"transient"`.
7. `ValueError("bad json")` → `"terminal"`.
8. A bare `Exception()` with no attributes → `"terminal"` — **the conservative-default test,
   asserted explicitly** (PRD Gap 2: an unrecognised error must never be optimistically
   `transient`).
9. `retry_after_seconds` on a malformed hint (`'retryDelay': 'banana'`) returns `None` and
   does not raise.
10. `QuotaExhausted` round-trips its `retry_after_seconds`.

**Validation:** `uv run pytest tests/test_minting_driver_resilience.py`
**Commit:** `resilience: classify provider errors as quota / transient / terminal`

## Phase 2 — `RetryingModel` and the sleep seam

**Goal:** a `Model`-shaped wrapper that retries transients with backoff and converts a
quota error into `QuotaExhausted`.

**Prerequisites:** Phase 1.

**Files:** MODIFY `eval/minting_driver/resilience.py`, `tests/test_minting_driver_resilience.py`

**Public surface:**
```python
DEFAULT_MAX_ATTEMPTS = 3
DEFAULT_BASE_DELAY_SECONDS = 1.0

class RetryingModel:
    def __init__(self, inner: Model, *, max_attempts: int = DEFAULT_MAX_ATTEMPTS,
                 base_delay: float = DEFAULT_BASE_DELAY_SECONDS,
                 sleep: Callable[[float], None] = time.sleep) -> None: ...
    @property
    def retry_count(self) -> int: ...
    def propose_next(self, messages: list[Message]) -> ToolCall | Done: ...
```

**Behavior:**
- `quota` → raise `QuotaExhausted(str(exc), retry_after_seconds=...)` **immediately**. No
  retry: the wait is hours (`retryDelay` was 39043s).
- `transient` → sleep `base_delay * 2**(attempt-1)` and retry, up to `max_attempts`. On
  exhaustion raise `TransientExhausted` chained from the last error (`raise … from exc`).
- `terminal` → re-raise the original exception **unchanged**, so `run_mint`'s existing
  containment records the same `str(exc)` it does today.
- `retry_count` accumulates across the instance's whole session (consumed later by
  `run-accounting`).

**Two things this must NOT do:**
- **Never retry a `tools/call`.** Structurally impossible here — the wrapper only wraps
  `Model.propose_next`; the tool call is a different object at `loop.py:117`. Do not move
  this logic into `loop.py` or `session.py`.
- **Never introduce concurrency.** A blocking `sleep` on the single thread is correct;
  `StdioMcp` is not thread-safe (`transport.py:212-213`) and one-call-in-flight is
  R7-by-construction.

**New test scaffolding** (`ScriptedModel` cannot raise a provider error — its only exception
path is `ScriptExhausted`):
```python
class FlakyModel:
    """Raises scripted exceptions on the first N calls, then delegates/returns."""
class RecordingSleep:
    """Callable recording each requested delay; returns immediately. `.delays -> list[float]`"""
```
Put `FlakyModel` in `eval/minting_driver/fakes.py` beside `ScriptedModel` (it is reused by
`subscription-model-client`); keep `RecordingSleep` test-local.

**Tests (RED first):**
1. Transient twice then success → one `ToolCall` returned, inner called 3×,
   `retry_count == 2`.
2. **Delay sequence is exactly `[1.0, 2.0]`** — asserted on `RecordingSleep.delays`, **never
   on elapsed wall time**. No test in this aspect may call real `time.sleep`.
3. Transient on every attempt → `TransientExhausted`, `sleep` called `max_attempts - 1`
   times, and `__cause__` is the last underlying error.
4. Quota on the first call → `QuotaExhausted` immediately, **`sleep` never called**,
   `retry_after_seconds` preserved.
5. Terminal → the original exception propagates **unchanged** (identity assertion, not just
   type).
6. Clean call → inner called once, `sleep` never called, `retry_count == 0`.
7. **A retried `propose_next` sends an identical request.** Wrap a real
   `LocalOpenAICompatModel` backed by `FakeOpenAIClient` scripted to raise a transient once
   then return; assert the two entries in `FakeOpenAIClient.calls` are **equal**. *This pins
   the `_ingest_new_messages` hazard: it mutates `self._seen` and the message list before the
   API call, so a retry is safe only because that mutation strictly precedes the throwing
   call. If someone reorders it, this test is what catches it.*
8. `RetryingModel` satisfies the `Model` protocol (`isinstance`-free structural check,
   matching `tests/test_minting_driver_model.py`'s style).

**Validation:** `uv run pytest tests/test_minting_driver_resilience.py tests/test_minting_driver_clients_mapping.py`
**Commit:** `resilience: bounded retry for transients; quota raises immediately`

## Phase 3 — Checkpoint: `no_observation` + history

**Goal:** the ledger can express "produced no observation", and re-recording preserves the
prior disposition.

**Prerequisites:** none (may run parallel with 1–2; but land **before** Phase 4).

**Files:** MODIFY `eval/minting_driver/checkpoint.py`, `tests/test_minting_driver_checkpoint.py`

**Changes:**
- `_VALID_STATUSES = frozenset({"captured", "failed", "no_observation"})` (`checkpoint.py:41`).
- `record()` (`checkpoint.py:56-80`): before overwriting an existing entry, append that
  entry's `{status, reason}` to the new entry's `history`, carrying forward any existing
  `history`. Entry shape becomes
  `{"status", "reason", "trace_path", "history": [...]}`.
- `is_done()` (`checkpoint.py:82-88`): return `True` only for `captured` / `failed`.
  **`no_observation` is not done** — this *is* the re-arm (D2). Update the docstring: it
  currently says *"any recorded disposition"*, which stops being true.
- `_validate_entry()` (`checkpoint.py:143-170`): preserve `history` (defaulting to `[]`),
  and validate it is a list of objects. It currently **drops unknown keys**, so without this
  the history is silently lost on every load — the exact failure mode D3 exists to prevent.
- Add `history(instance_id)` accessor beside `reason()` / `trace_path()`.

**Fail-closed load and atomic save are unchanged.**

**Tests (RED first):**
1. `record(..., "no_observation")` round-trips through `save`/`load`.
2. **`is_done` is `True` for `captured`, `True` for `failed`, `False` for `no_observation`.*
3. Re-recording an instance appends the prior `{status, reason}` to `history`.
4. **History survives a save/load round-trip** — the `_validate_entry` drop-unknown-keys trap.
5. Two successive re-records produce a **2-entry** history in chronological order.
6. **Backward compatibility:** a ledger written with only `{status, reason, trace_path}`
   (i.e. the real 56-entry Stage-3 file's shape) loads, and its entries get `history == []`.
7. An unknown status still raises a named `ValueError`; a corrupt/non-object entry still
   raises. (Existing tests must pass unmodified.)
8. `record` with an invalid status still raises immediately.

**Validation:** `uv run pytest tests/test_minting_driver_checkpoint.py`
**Commit:** `checkpoint: a no-observation disposition that a resume re-arms`

## Phase 4 — `run_mint`: stop the batch on quota

**Goal:** the headline defect. A quota event costs one instance, not the queue.

**Prerequisites:** Phases 1–3.

**Files:** MODIFY `eval/minting_driver/batch.py`, `tests/test_minting_driver_batch.py`

**Change** — insert **two** handlers ahead of the existing bare `except Exception`
(`batch.py:219-225`), which stays byte-identical:

```python
        except QuotaExhausted as exc:
            # Provider quota/period cap. The wait is HOURS (the observed retryDelay was
            # 39043s), so retrying is useless and CONTINUING is actively harmful: the
            # 2026-07-24 Stage-3 run fed 56 remaining instances into the wall in 3m48s,
            # burning one request each and recording them all `failed` -- which
            # `is_done` then treated as done, permanently. Record THIS instance as having
            # produced no observation and STOP. Every later record stays absent from the
            # checkpoint, therefore still eligible on the next run.
            checkpoint.record(record.instance_id, "no_observation", reason=str(exc))
            checkpoint.save(checkpoint_path)
            break
        except TransientExhausted as exc:
            # Retries were spent and nothing was observed. Re-armable (unlike `failed`),
            # but not a reason to stop the batch.
            checkpoint.record(record.instance_id, "no_observation", reason=str(exc))
            checkpoint.save(checkpoint_path)
            continue
        except Exception as exc:
            ...unchanged...
```

`run_mint`'s signature and return type are unchanged; it still returns the `Checkpoint`.
Update the docstring to describe the stop.

**Tests (RED first):**
1. **HEADLINE — quota stops the batch.** 10 records; the model raises a quota error on
   instance 3. Assert: instances 1–2 `captured`; instance 3 `no_observation`; **instances
   4–10 absent from the checkpoint entirely** (`status(...) is None`), and the workspace

2. **Resume after a quota stop re-drives from instance 3** and does not re-drive 1–2.
3. A `captured` instance is **never** re-driven — assert via a counting `prepare` /

4. Transient-exhausted on instance 3 → `no_observation`, and **instances 4–10 still run**.
5. **Terminal is unchanged:** `failed` recorded, batch continues,

6. **An instance that produced an observation is not re-armable** — a `captured` or `failed`
   instance is skipped on resume. *This is the anti-re-roll contract
   (`mint-execution/spec.md:52`, `:90-92`) in code.*
7. The quota reason recorded contains the provider's retry hint where one was given.
8. **Single-in-flight and sequential ordering survive** — the existing
   `ReentrancyTransport` / sequential tests pass unmodified.

## Edge Cases & Verdict Impact

**Verdict impact: NONE.** No axis changes; no new engine `UNVERIFIED` path is created. These
are *capture* outcomes, and they manifest as an instance **never entering the denominator** —
never as a turn that reads as verified. That distinction is the honesty property here: a
missing instance is visibly missing, whereas a mis-recorded one would silently shrink the
denominator, which is exactly what happened on 2026-07-24.

| Edge case | Handling |
|---|---|
| Quota on the **first** instance | Batch stops immediately; checkpoint has exactly one `no_observation`. Not an error state. |
| Quota during `bridge_capture` (post-session) | Cannot happen — bridging makes no model call. Falls to the bare `except`, recorded `failed`. Correct: an observation *was* produced. |
| Quota inside `discover_tools` | Discovery makes no model call; a failure there is `failed`, unchanged. |
| A provider whose 429 carries **no** hint and no `RESOURCE_EXHAUSTED` | `transient` → retried → `TransientExhausted` → `no_observation`, re-armable. Costs `max_attempts` requests, does **not** burn the queue. Acceptable and documented. |
| Subscription limits with an **unknown** shape | Fall through to `terminal` → `failed`, batch continues. **Conservative in the safe direction** (PRD Gap 2): not re-armable without the migration tool, but never a retry-into-a-wall. |
| `history` growing without bound | Bounded in practice by re-arm count; no cap. If it ever matters, cap at the last 10 — not now. |
| An instance re-armed and then quota-stopped again | `history` gains a second entry; still `no_observation`; still eligible. Converges. |

## Assumptions

1. The Stage-3 error strings are representative of this provider's quota shape. Verified: all
   56 normalize to **one** signature.
2. Subscription-backed quota errors will have a *different* shape, unknown today. Handled by
   the `terminal` fallback; `subscription-model-client` revisits it with real data.
3. `history` is additive metadata no existing consumer reads, so adding it cannot break
   `MintReport` or the re-arm tool. Verified: `entrypoint.py:477-521` counts statuses only.
