## 2. Phases (TDD, commit per phase)

### Phase 1 — RED: `tests/test_verify_triage_ledger.py`
1. **Real-data mechanics:** the demo capture verified with a stub triage author
   (shadow mode, `--json`) → `belay triage-ledger <doc>` renders 0 violations, the
   denominator stated (7 turns, 7 decided, 0 excluded), exit 0. (The fixture shape:
   `tests/test_refutation_triage.py:101-168` — stub author + real CLI.)
2. **Exact output:** a synthetic verify document (hand-written JSON, schema 1) with
   known (score, confidence, status) rows — FAIL/PASS/UNVERIFIED/skipped — pins the
   rendered bins, ECE, and sweep table exactly; `--json` output byte-stable.
3. **Exclusions:** UNVERIFIED turns and `"skipped": true` rows are excluded from the
   calibration column and counted in the report.
4. **100%-UNVERIFIED:** renders the named refusal, NO rates, exit 0 (the
   INSTRUMENT SUSPECT shape).
5. **No triage section:** exit 2, named.
6. **Malformed input:** exit 2 (the `_cmd_phase0_report` load shape).
7. **Determinism:** the same document re-renders byte-identically.
8. **Parity:** the `--json` row widened — guard 2 stays green.
Run `uv run pytest tests/test_verify_triage_ledger.py tests/test_cli_flag_parity.py -q`
— RED. Commit: `git add tests/test_verify_triage_ledger.py && git commit -m
"test(ledger-command): RED — the triage-ledger command contract"`
